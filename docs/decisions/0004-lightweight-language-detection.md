# 0004 · 使用轻量确定性语言检测

- 状态：已接受
- 决定日期：2026-10-20
- 影响范围：HTML 入库、文档与 block 语言字段、sidecar 打包体积

## 背景

原技术选型使用 Lingua 识别文档／block 语言。004 实现用 PyInstaller 打包后，Lingua 的中英文原生模型使 sidecar 从约 33 MB 增至约 331.5 MB。这会显著增加普通 Windows 用户的安装和更新成本，也增加冷启动与分发风险。

首版只支持中文和英文，语言字段只用于展示、筛选与检索提示，不参与正文提取是否成功的判断，因此不需要通用多语言分类模型。

## 候选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 保留 Lingua，只做文档级检测 | 模型识别能力成熟 | 仍有约 290 MB 模型负担，且不能自然表达 block 级 `mixed` | 不采用 |
| 保留 Lingua，逐 block 检测 | 可生成 block 语言 | 体积负担最大；短 block 和代码块信号不稳定 | 不采用 |
| HTML 声明＋文字体系比例 | 确定性、可测试、无额外模型体积，能表达中文、英文、mixed 和 unknown | 不能识别首版范围外语言，阈值需要真实语料校准 | 采用 |

## 决策

采用版本化确定性检测器 `script-ratio-v1`：

- 文档优先使用 `html lang`、`meta[name=language]` 和 `meta[http-equiv=content-language]` 中受支持的 `zh-*`／`en-*`。
- 声明缺失时统计汉字与拉丁字母。有效信号少于 20 个为 `unknown`；两种文字都至少占 20% 为 `mixed`；单一文字达到 80% 时归为该语言；其余为 `unknown`。
- block 先按自身文本判断；信号不足时才回退已知的文档 `zh`／`en`。
- `unknown` 不阻断入库，也不能默认成中文。
- 从后端依赖和打包产物中移除 Lingua。

## 后果

- sidecar 不再携带约 290 MB 的语言模型库，安装体积和冷启动成本显著降低。
- 中文、英文与混排内容都能得到稳定、可解释的语言提示。
- 检测只覆盖中文和英文；日文、韩文或中文中少量英文术语的边界需要真实语料验证。
- 如果 HTML 声明错误，文档语言会跟随错误声明；block 级文本判断仍可提供局部纠正。

## 验证

- 纯函数测试覆盖中文、英文、混排、短文本和纯数字。
- HTML 元数据声明测试覆盖 `content-language`。
- block 测试确认英文 block 不会被文档的 `zh` 声明覆盖。
- 后端完整测试 39 passed；Ruff、Pyright、前端构建和 Rust 检查通过。
- 重建 PyInstaller sidecar 成功，共 725 个文件、40.93 MiB；产物中未发现 Lingua 文件。
- 打包 sidecar 通过本机回环 API 冒烟：健康检查为 `ok`，中文 fixture 为 `zh`／5 blocks，英文 fixture 为 `en`／1 block，退出后端口已释放。
- Tauri release 与 NSIS 构建通过，安装包为 19.81 MiB。

## 已确认规则

- 最低有效文字信号保持 20 个字符。
- `mixed` 的双向最低占比保持 20%。
- 单一语言优势占比保持 80%。
- 文档声明与正文明显冲突时，继续让受支持的可靠声明优先。

## 推翻条件

真实中文、英文和混排语料证明当前阈值经常误判，或后续产品范围加入其他语言时，重新评估轻量检测规则或恢复专用语言识别组件。
