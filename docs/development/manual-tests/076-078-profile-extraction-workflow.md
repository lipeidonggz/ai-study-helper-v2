## 前置条件

- [ ] 已配置 Chat API Key。
- [ ] 当前知识库至少有两篇已完成入库的测试文档。
- [ ] 记录当前 snapshot ID。
- [ ] 使用开发构建启动桌面应用。

## 一、Profile 管理

1. [ ] 打开“Profile 抽取”。
2. [ ] 确认“技术学习与参考”显示为系统只读，且包含四个通道。
3. [ ] 从系统 Profile 克隆一份草稿。
4. [ ] 修改名称、用途、代表性问题、通道条件和补充说明。
5. [ ] 不填写某个通道必填字段并保存草稿，确认草稿可以保存但“保存并校验”指出问题。
6. [ ] 补全后保存并校验，确认通过。
7. [ ] 查看只读编译 Prompt。
8. [ ] 点击“确定使用此 Profile”，确认界面明确提示确定后不可修改。

预期：

- 草稿可重复修改并持久化。
- 确定后 Profile 变为冻结，不能原地编辑。
- selected 指针切换到该 Profile。
- 不触发 Preview 或全库 build。

## 二、试抽取

1. [ ] 再复制或创建一个不同的 Profile，只调整其中一个通道。
2. [ ] 在“预览”中选择 Profile A 和两篇文档。
3. [ ] 点击“估算 token 用量”，确认先显示预计总 token，再显示输入、输出、调用和范围明细。
4. [ ] 关闭“即使配置相同也强制创建新的试抽取记录”，开始试抽取。
4.1 [ ] 勾选“同时执行 LLM 候选审查”，确认成本计划分别显示内容审查、标题区分度审查和
   名称含义审查的新增预计调用；完成后候选列表可筛选“仅有疑点”，候选详情可分别查看
   “只看标题时存在歧义”和“标题与摘要含义不一致”等审查结论。
4.2 [ ] 使用同一 Profile、snapshot 和文档范围重新试抽取，与名称契约升级前的 run 比较：
   不得新增完整句或建议句标题；泛称应使用 evidence 支持的最小锚点；原文同指术语应保留
   为 alias。名称变体去重和候选独立性问题仍单独记录，不用本轮名称契约结果代替。
4.3 [ ] 检查文档级标题消歧：成本计划显示每篇文档的消歧调用和预算；候选详情显示
   provisional/final title、标题类型、缺失锚点、理由及来源 block；若超预算或失败，
   页面明确提示该文档未完成消歧且候选仍可审核。
4.4 [ ] 使用两个语义部分重叠的通道重跑：后通道应收到前面已积累候选；同一对象只增加
   summary variants、alias、source blocks、channel 和理由，不新增重复候选；不同粒度
   对象仍应分别保留。
4.5 [ ] 使用一篇会拆成多个窗口的长文档重跑：同一通道的后续窗口收到此前窗口候选；
   同一对象只增加 summary variants、alias、source blocks 和理由，不新增重复候选。
   不同粒度对象仍应分别保留。
5. [ ] 观察“等待中／抽取中”的动态反馈，再确认状态进入“已完成”。
6. [ ] 查看完成后的 candidate、summary、evidence 正文和 block ID。
6.1 [ ] 隐藏试抽取历史侧栏，确认候选详情区自动扩宽；再显示并按 Profile 名称和状态筛选。
6.2 [ ] 使用候选名称、文档和来源通道筛选，确认左侧候选列表和右侧详情同步更新。
6.3 [ ] 在候选浏览中设置搜索词、来源通道和审查状态，再切到“按原文阅读”，确认
   这些筛选条件继续生效，并同步影响关联候选、覆盖计数和未关联块筛选。
7. [ ] 用相同输入再次启动，确认可显式复用已完成的试抽取记录。
8. [ ] 开启“即使配置相同也强制创建新的试抽取记录”再次执行，确认产生新记录，旧记录保持不变。
8.1 [ ] 构造一个 alias 与同文档另一候选主名称相同的结果，确认出现“别名身份冲突”且
   该 alias 不会被加入质量校验基准。

预期：

- 同一时间只有一个 Preview Run 处于 running。
- 两篇文档分别产生候选，不发生跨文档合并。
- 相同主名称只做文档内精确合并。
- alias-only 候选不会被自动合并。
- 不使用共现自动合成“对象＋机制”候选。
- 预计总 token 等于计划中的输入与输出 token 之和。
- 运行中显示旋转指示、动态进度线和方法说明，不再只显示静态状态词。

## 二之一、英文证据翻译

1. [ ] 在包含英文 evidence 的 completed run 中点击“翻译英文证据”，确认立即显示“翻译中”状态。
2. [ ] 确认首次请求产生中文翻译，原文和 block ID 仍完整保留。
3. [ ] 再次进入包含相同 evidence 的 run 并翻译，确认提示缓存复用且不再产生相同模型调用。
4. [ ] 检查翻译失败时不会覆盖原文，也不会展示缺失块。

## 二之二、按原文顺序检查候选

1. [ ] 在 completed run 中切换到“按原文阅读”，确认默认打开当前候选所在文档。
2. [ ] 核对左侧原文 blocks 与 snapshot 原始顺序一致，右侧候选只引用对应 block。
2.1 [ ] 选择引用多个 block 的候选，确认第一次显示完整卡片，后续只显示“也引用了本段”。
3. [ ] 勾选“只看未关联候选的原文块”，确认未关联提示不写成“漏提”或“失败”。
4. [ ] 切换多篇文档，确认每篇加载自己的完整 blocks 和候选关联。
5. [ ] 给两条不同候选分别选择不同优先级，确认候选之间的临时优先级互不影响。
6. [ ] 从原文行内候选打开详情弹窗；确认详情弹窗与行内候选显示同一优先级，关闭或加入
   质量校验基准后仍停留在原 block 和原文视图。
7. [ ] 在“原文／中文”之间切换，确认英文块按需翻译、中文模式仍可展开查看原文。
8. [ ] 在窄窗口中确认双栏退化为原文在上、候选在下。

## 三、质量校验基准

1. [ ] 选择第一篇文档，填写非 Profile 专属评测说明。
2. [ ] 点击“生成校验项建议”，检查建议项、优先级和 evidence。
3. [ ] 修改或删除建议项，手工添加一个绑定 evidence 的条目。
4. [ ] 从 Profile A 和 Profile B 的候选分别加入至少一个条目。
5. [ ] 确认校验项来源信息可区分 system／preview／manual。
6. [ ] 保存草稿并重新打开。
7. [ ] 冻结质量校验基准，确认之后不能编辑。
8. [ ] 对第二篇文档重复创建并冻结质量校验基准。

## 四、Profile 比较

1. [ ] 在“Profile 比较”中选择两个 completed run。
2. [ ] 选择两篇文档各自对应的冻结质量校验基准。
3. [ ] 创建比较，确认每篇文档独立展示指标，没有综合分。
4. [ ] 对 uncertain 项选择一个 candidate 确认为命中，或确认缺失。
5. [ ] 检查 must 缺失或未决时出现阻断提示。
6. [ ] 为存在 must 阻断的文档填写忽略原因。
7. [ ] 分别设置每篇文档结论和总体结论。
8. [ ] 提交并冻结结论。
9. [ ] 尝试再次修改 conclusion，确认被拒绝。

预期：

- must 缺失和未决 uncertain 均阻断。
- 不同文档允许有不同的用户结论。
- 最终选择只由用户显式提交。
- Comparison 不修改任何 Preview Run 或 Profile。
- comparison hash 和参与比较的 checklist hash 可追溯。

## 失败检查

- [ ] 尝试用不同 snapshot 的 Preview Run 创建比较，确认被拒绝。
- [ ] 尝试修改冻结 Profile，确认被拒绝。
- [ ] 尝试修改冻结质量校验基准，确认被拒绝。
- [ ] 尝试让 Provider 返回非法 source block，确认 run=failed 且没有正式候选。
- [ ] 尝试在未解决 must uncertain／missing 时不填写原因直接结项，确认被拒绝。
