## 控制契约

### 背景与失败场景

- 触发问题：c13-003 要求按一个开放主题取齐相关知识。块级混合检索与 Agentic 改写做了多轮尝试，仍会漏掉 checkpoint 恢复、恢复正确性评估等边界内容。
- 不处理时的用户损失：用户得到一篇看似完整、实际只覆盖常识性隔离手段的回答，并把漏项误认为知识库没有相关内容。
- 现有流程为什么不足：相似度检索只对“与当前查询表述接近的块”负责；它没有一张预先组织好的跨源主题地图，无法告诉 Agent “这个话题还有哪些证据面值得继续检查”。
- 本切片负责什么：建立 LLM Wiki 的最小可信底座，证明一个主题页可以由冻结快照中的 block 编译出来，并且页面的每一段都能回到原文 block。
- 本切片不负责什么：不把它接入主 Agent、不替换 `search_blocks`、不做全库自动概念发现、不做页面向量检索、不做 GraphRAG、不证明 Wiki 已经提升 c13-003 的最终回答。
- 停止或撤掉机制的条件：如果页面段落无法稳定映射到 block，或者编译产物不能相对冻结快照自校验，则停止继续堆叠 Wiki 生成逻辑，先修证据层。

### 用户可观察目标

给定一个冻结 collection snapshot、一个页面主题和一组候选 block，系统生成不可变的 Wiki 页面 artifact。页面中的每个段落都列出至少一个属于该 snapshot 且属于本页候选集合的 `block_id`；任一段落、任一引用不满足约束时，整次编译失败并且不留下“成功”产物。

### 核心不变量

1. Wiki 页面只是索引层；页面段落必须引用当前冻结 snapshot 的 block，原始 block 始终是最终事实源。
2. 页面只能引用调用方为该页提供的候选 block，不能引用其他 snapshot、其他页面候选或模型编造的 ID。
3. 没有段落、空段落或没有来源的段落都使整次编译失败，不能静默删除坏段落后报告成功。
4. 编译 manifest 固定 snapshot、snapshot manifest hash、编译器／提示词／模型版本和每页 artifact hash；读取时重新校验。
5. 编译失败不改变 collection，不发布部分页面，也不把失败包装成空 Wiki。

### 错误代价与非对称门禁

| 错误类型 | 具体例子 | 用户影响 | 处理分类 | 指标与阈值 |
| --- | --- | --- | --- | --- |
| 悬空引用 | 页面引用不属于 snapshot 的 block | 引用链断裂，用户无法核对事实 | 阻断 | 悬空引用数必须为 0 |
| 跨页引用 | 页面引用了本页候选集合外的 block | 页面证据面失控，调试和覆盖统计失真 | 阻断 | 越界引用数必须为 0 |
| 空证据页面 | 模型只写概述、不给 block | Wiki 退化为不可审计摘要 | 阻断 | 空来源段数必须为 0 |
| 产物损坏 | manifest 或页面 JSON 在写入后被修改 | 读取者可能相信错误的页面身份 | 阻断 | hash／identity 校验失败即拒绝读取 |
| 模型内容不完整 | 某页生成失败 | 用户误以为所有页面已编译 | 阻断 | 一次 compile 全有或全无 |

### 明确禁止

- 不得把 Wiki 页面当成 citation 的最终来源；后续 Agent 引用仍必须解析回 block。
- 不得用程序补写页面正文来掩盖模型输出为空或格式错误。
- 不得跳过坏段落、跳过坏页、改用空页面或沿用旧 build 后报告本次成功。
- 不得修改已发布 collection snapshot 目录；Wiki 是独立派生 artifact。
- 不得把 c13-003 的用例词、三个探针或其他案例专属信息写入通用提示词。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| snapshot 不可用 | `wiki_snapshot_unavailable` 与原因 | 原 collection 不变 | 恢复 snapshot 后重试 |
| block 不在 snapshot | `wiki_source_block_missing` 与缺失 ID | 不写新 build | 修正页面候选后重试 |
| 模型输出非法 | `wiki_response_invalid` 与稳定错误码 | 不写新 build | 检查模型输出后重跑 |
| 模型输出越界引用 | `wiki_source_out_of_scope` 与 block ID | 不写新 build | 修正证据包或提示词后重跑 |
| 读取时 artifact 损坏 | `wiki_artifact_invalid` | 原文件留给诊断，不返回页面内容 | 重新编译或恢复 artifact |

## 目标

先验证 LLM Wiki 的证据底座，而不是一次性复刻完整 WeKnora 编译链：

```text
冻结 snapshot
→ 调用方指定页面主题与候选 block
→ LLM 在候选 block 内组织页面段落
→ 每段绑定 source block IDs
→ 程序和 snapshot 双重校验
→ 原子写出不可变 Wiki artifact
```

WeKnora 的七阶段编译只作为后续参考。本切片先为其最关键的三根柱子提供可执行落地：原文 chunk、页面到 chunk 的引用、稳定身份与 manifest。

**范围修正（2026-10-31）：** 本切片没有实现主题发现、身份对齐、跨源页面规划和 Wiki 检索，因此不能作为完整 LLM Wiki 或“主题找全能力”的实现。其有效成果只是后续 Narrative Materialize 阶段的 artifact、段落回源和失败门禁。

## 输入与输出

输入：

- `snapshot_id`：固定 collection snapshot；
- 一个或多个 `WikiPageSpec`：页面标题、别名、覆盖问题、本页候选 block IDs；
- `ChatProvider`：生成页面草稿；
- 编译器、提示词和输出 schema 版本。

输出：

- `WikiCompileResult`：build ID、manifest、页面结果和按页的模型 usage；
- 独立 artifact 目录中的不可变 manifest 与页面 JSON；
- 页面覆盖统计：候选 block 数、被引用 block 数、未被引用 block 数。

首版页面 JSON 结构固定为：

```json
{
  "page_id": "wp_<stable-hash>",
  "title": "页面标题",
  "aliases": [],
  "coverage_questions": [],
  "paragraphs": [
    {
      "text": "由输入证据支持的页面段落",
      "source_block_ids": ["block-id-from-snapshot"]
    }
  ]
}
```

## 不包含

- 全库概念抽取、别名归并和目录规划；
- 自动选择页面候选 block；
- Wiki 页面搜索、页面链接遍历和 Agent 工具；
- 页面增量更新、删除传播和旧 build 清理；
- 模型输出的事实正确性判官；
- c13-003 回答质量提升结论。

## 停止与推翻条件

- 若页面经常无法在候选 block 内生成有信息增量的内容，说明“页面重写”本身没有价值，应改为只做主题路由或多页索引。
- 若真实快照上大量页面出现合法 ID、错误事实，应停止把 Wiki 当知识层，转为路由提示，并引入独立事实判官。
- 若编译成本或失败率随页面数线性失控，应拆分“候选选择”“页面草稿”“提交”为可恢复任务，而不是把整库放在一次调用里。
