# 060 · 语义覆盖与输出结构分离

- 状态：已完成
- 开始日期：2026-10-29
- 关联设计：[06 检索、Agent 与提示词设计](../../design/06-retrieval-pure-agent.md)
- 前置切片：[059 c15 用户监督能力语义校准](./059-c15-supervision-semantics.md)
- 人工验收：沛东确认不使用具体领域概念或表格类别补提示词，改为通用语义覆盖与输出结构两类规则

## 控制契约

### 背景与失败场景

- 触发问题：c15 剩余失败来自答案只写了复合维度的显眼部分，没有覆盖原文中解释方案差异的其他关键要素。
- 不处理时的用户损失：答案表面符合用户要求的结构，但单元格内容不完整，用户需要自行发现遗漏。
- 现有流程为什么不足：现提示词有检索覆盖规则和输出格式建议，但没有把“语义覆盖单位”与“输出结构”分开。
- 本切片负责什么：新增通用 `answer_coverage` 与 `output_structure` 规则，发布 chat-v17。
- 本切片不负责什么：不加入威胁模型、bash、表格对比等具体领域或格式示例，不修改 Judge 或金标准。

### 用户可观察目标

Agent 先识别问题要求的语义方面，再按用户指定结构组织；抽象或复合方面不会只写一个显眼要素。

### 核心不变量

1. 语义覆盖由问题决定，与表格、清单或正文格式无关。
2. 抽象或复合维度有多个关键证据要素时必须完整列出或综合不丢要素。
3. 用户指定结构时，每个命名对象和字段都有对应内容。
4. 细节可以放在主结构之后，不强制塞入同一单元格。
5. 不引入具体领域概念或按题型硬编码。

### 明确禁止

- 不在提示词中加入“威胁模型”“bash”“用户身份”等 c15 特例。
- 不把“对比题”或“表格题”设为唯一触发条件。
- 不因结构要求降低语义覆盖。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| 复合维度只写一部分 | 结构完整但语义不完整 | 答案与证据 | 是 |
| 主表省略、表后补充 | 只要语义覆盖完整即可 | 完整答案 | 是 |
| 证据不足 | 明确缺失项 | 已有证据 | 是 |

### 决策预算

- 预计 B 级决策数量：1。
- 是否存在 C 级决策：否。

## 验收

- chat-v17 包含独立的 `answer_coverage` 与 `output_structure`。
- 提示词不包含 c15 领域特例。
- 定向测试与生产构建通过。
- c15 使用 chat-v17 跑新 N=10。
