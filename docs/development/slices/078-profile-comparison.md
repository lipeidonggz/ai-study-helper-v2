## 控制契约

### 背景与失败场景

- 触发问题：两个 Preview Run 的原始候选差异无法让用户稳定判断 Profile 效果。
- 不处理时的用户损失：用户只能凭整体印象选择，容易偏向候选更多的 Profile。
- 现有流程为什么不足：没有文档级期望清单、must 阻断、多文档独立展示和冻结比较记录。
- 本切片负责什么、不负责什么：负责清单建议／编辑／冻结、双 Profile 比较和比较结论；不负责修改 Preview Run 或 Profile。
- 什么情况下应停止或撤掉本切片引入的机制：如果必须生成综合质量分、必须审核全库候选或无法保持清单独立性，则停止。

### 用户可观察目标

用户可以为每篇文档生成或手工创建 must／should／nice_to_have／noise 清单，从 A/B 候选补充后冻结，运行双 Profile 比较，逐文档查看结果并显式提交最终结论。

### 核心不变量

1. DocumentChecklist 独立于 Profile；Profile 调整不会使清单失效。
2. 清单项必须绑定当前文档版本的真实 source block，冻结后不可原地修改。
3. 正式比较只接受同一 snapshot／文档范围／系统契约／pipeline／模型参数／window policy 的两个 completed run。
4. 比较不生成综合分数，must 缺失或未解决 uncertain 必须阻断提示。
5. 多文档结果独立保存，最终结论必须由用户显式提交，比较完成后不可修改。

### 错误代价与非对称门禁

| 错误类型 | 具体例子 | 用户影响 | 处理分类 | 指标与阈值 |
| --- | --- | --- | --- | --- |
| 错配 snapshot | 两 run 使用不同 snapshot | 差异无法归因 Profile | 阻断 | 100% 拒绝 |
| 自动胜负 | 根据候选数或多数文档选 winner | 误导最终选择 | 阻断 | 0 容忍 |
| must 静默通过 | missing／uncertain 被忽略 | 关键遗漏未暴露 | 阻断 | 100% 提示 |
| 清单绑定 Profile | 修改 Profile 导致清单失效 | 清单被错误污染 | 阻断 | 100% 不复用失效 |
| 相似候选误合并 | evidence 重叠自动算同一项 | 覆盖率虚高 | 阻断 | 只允许 uncertain |

### 明确禁止

- 不生成百分比或综合质量分。
- 不因证据重叠或 alias 自动确认 matched。
- 不修改 candidate、Preview Run 或 Profile。
- 不允许未冻结清单进入正式比较。
- 不允许 concluded comparison 原地改写。

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |

## 目标

建立文档级 Evaluation Checklist、候选匹配、Profile Comparison 和相应前端。

## 输入与输出

- 输入：文档版本、可选评测说明、A/B Preview Run、冻结 Checklist、用户 item decisions 和最终结论。
- 输出：冻结清单、逐文档比较事实、must 阻断提示、可追溯的 Profile Comparison。

## 不包含

- 自动选择 Profile；
- 综合质量分；
- 跨文档加权或多数票；
- 修改 candidate 或执行语义候选归并。

## 协作复盘

- AI 明显加速的环节：质量基准、不可变比较快照、匹配矩阵和界面流程同步实现。
- 负责人失去系统模型的环节：早期“文档清单”没有表达出它是 Profile 比较基准。
- 真正发现问题的控制点：真实界面中的术语、证据查看和比较结论审核。
- 只有仪式感、没有产生判断价值的流程：使用抽象字段名进行验收不能证明用户理解，最终改为业务语言和页面说明。
- 下一次准备调整的一到两项：所有评价产物先明确“它服务于哪个用户决策”，再确定名称和界面。

## 已知风险与后续

- 未验证项：真实文档上的清单质量与 UI 可读性。
- 接受的风险：首版不做语义清单匹配，未匹配项会进入 uncertain。
- 后续待办或 ADR：BL-0018 全局语义候选归并。
