- 人工验收：沛东确认 Agent 应尽可能精确回答；不能精确时，必须让用户发现目标或假设上的偏差并能够纠正

## 控制契约

### 背景与失败场景

- 触发问题：cf-001 原题“各选一篇 OpenAI、Anthropic”可以理解为允许 Agent 自选；改成“刚才那篇”后，只检查是否出现澄清问句又会误杀透明、有用的首轮回答。
- 不处理时的用户损失：过严标准会奖励机械追问，惩罚透明假设和跨文档综合，无法判断用户是否知道 Agent 实际采用了哪些文档。
- 现有流程为什么不足：“澄清动作”是代理指标，不是产品目标本身。
- 本切片负责什么：把 cf-001 收敛为单一“目标范围可见”判据。
- 本切片不负责什么：不修改 Agent Prompt，不要求等待用户回复，不把一边一篇或机构归属准确性作为 gate。
- 停止或撤掉条件：若用户无法从答案中发现实际采用的范围或推断依据，应恢复更严格的目标解析约束。

### 用户可观察目标

用户可以知道 Agent 实际采用了哪些文档、如何理解“刚才那篇”，并能低成本纠正对象或范围；Agent 可以直接回答、透明假设后回答或先澄清。

### 核心不变量

1. cf-001 题面使用“刚才那篇”，会话不提供对应前文。
2. 答案必须让实际采用的文档和推断或澄清依据可见。
3. 为回答宽泛主题，一侧采用多篇相关文档可以接受。
4. 不要求固定措辞、不要求提问，也不要求等待回复。
5. Agent Prompt 保持 `chat-v17`；只替换 case revision。

### 错误代价与非对称门禁

| 错误类型 | 具体例子 | 用户影响 | 处理分类 | 指标与阈值 |
| --- | --- | --- | --- | --- |
| 隐藏自选 | 直接比较，但不说采用了哪些文档或依据 | 用户可能把错误对象当成自己指代的对象 | 阻断 | R1 fail |
| 透明自选后回答 | 列出文档并说明“我按内容归属理解为” | 用户可继续阅读，也可纠正 | 可接受 | R1 pass |
| 先澄清 | 说明回指无法解析并请用户补充 | 用户获得明确下一步 | 可接受 | R1 pass |
| 一侧多篇综合 | 围绕“agent 工程”合并三篇 Anthropic | 可能更完整；只要范围可见 | 可接受 | R1 pass |

### 明确禁止

- 不得把“出现问句”作为唯一通过条件。
- 不得把固定短语当作语义本身。
- 不得因为要求宽泛主题回答完整就阻断一侧多篇综合。
- 不得修改历史 case revision、历史 run 或历史 judgment。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| 直接比较但不披露范围或依据 | R1 fail，指出隐藏目标 | 原答案与 failure reason | 是，可改答后重判 |
| 透明假设后继续比较 | 正常回答与可纠正文档范围 | R1 pass 与完整答案 | 不需要恢复 |
| Judge 输出非法 | 当前样本 pending | invocation 与错误码 | 是，有限重试后仍需重判 |

## 目标

让 cf-001 测量回答是否透明、可恢复，而不是测量是否说了某句澄清话或是否严格一边一篇。

## 输入与输出

- 输入：无前文的“刚才那篇 OpenAI 的、那篇 Anthropic 的”问题。
- 输出：澄清回答，或披露实际文档和推断依据后的回答。

## 不包含

- 不改善 Agent 自行生成透明披露的稳定性。
- 不修改 Judge prompt，只修改 cf-001 criterion。
- 不重新运行 Agent；对冻结答案重判以控制变量。

## 协作复盘

- AI 明显加速的环节：从冻结答案和 Judge reason 中区分目标披露、措辞形式和比较范围。
- 负责人失去系统模型的环节：早期把“澄清动作”误当成产品目标本身。
- 真正发现问题的控制点：负责人指出真实目的是精确回答，或让不精确可见、可纠正。
- 只有仪式感、没有产生判断价值的流程：只检查是否出现澄清句。
- 下一次准备调整的一到两项：让判据围绕用户能否恢复，而不是围绕模型是否遵循某个话术。

## 已知风险与后续

- 未验证项：纯澄清候选清单中的机构归属准确性不进入 cf-001 gate，见 `BL-0014`。
- 接受的风险：透明假设后的回答可能基于错误对象，但用户能看到实际采用文档并纠正。
- 后续待办：如需验证来源归属，用 collection 元数据或独立 checker，不继续堆叠本用例措辞。

## 停止与推翻条件

- 若用户仍无法从答案中发现实际文档范围，恢复更严格的目标解析要求。
- 若产品主要面向精确指代场景，可另建“精确两边一篇”用例，而不是把该要求塞回 cf-001。
