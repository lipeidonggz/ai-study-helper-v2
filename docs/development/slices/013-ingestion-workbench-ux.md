## 控制契约

### 用户可观察目标

1. 顶部品牌区明显变矮，打开应用后无需滚动即可看到主要工作内容。
2. 有任务运行时，任务队列和选中任务详情无需越过新建表单才能看到。
3. 用户可以看清单个任务当前正在处理哪个来源、已经运行多久，以及真实的排队位置。
4. 暂停、恢复和取消可以直接在队列任务上完成，不需要先选中再向下寻找按钮。

### 核心不变量

1. 新建批次表单始终可用，不因已有 queued／running 任务消失或被禁用。
2. 队列显示顺序与后端串行调度顺序一致。
3. 同一任务在队列行和详情区显示相同状态，partial 不显示为完整成功。
4. 操作按钮只出现在该状态允许的动作上。

### 明确禁止

- 不通过隐藏快捷键暴露产品能力。
- 不把多个互斥操作伪装成同一状态按钮。
- 不压缩到影响正文可读性或触控区域。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| 队列读取失败 | 明确错误，不伪装成空队列 | 已有页面数据与后端任务 | 是 |
| 任务操作失败 | 对应任务附近显示原因 | 后端原状态 | 是 |
| 时长字段缺失 | 显示运行中但不虚构用时 | 任务记录 | 是 |

### 人工检查点

- 编码前确认双栏布局、队列行直接操作和顶部压缩范围。
- 第一阶段完成后先检查顶部与 1920 宽窗口。
- 第二阶段检查运行中＋排队中＋中断任务混合队列。

### 决策预算

- 预计 B 级决策：3 项。
- C 级决策：无。

## 目标

减少无效滚动和状态判断成本，让“新建任务”和“观察当前任务”可以同时完成。

## 输入与输出

输入：

- `/api/tasks/active` 返回的非终态任务；
- 当前选中任务和来源列表；
- 当前任务起止时间。

输出：

- 紧凑顶部；
- 新建批次／任务监控双栏；
- 带真实排队位置和直接操作的队列；
- 当前来源、阶段和已用时间。

## 不包含

- 拖拽文件；
- 文件总大小；
- 历史记录筛选和分页；
- 失败来源一键重试；
- 来源标签增强；
- 多应用实例锁。

## 验收条件

- [x] 1920 宽窗口中，顶部品牌区高度明显缩减。
- [x] 运行中任务时，队列位于首屏可见区域。
- [x] 桌面端为新建批次与任务监控双栏，窄窗口自动变单列。
- [x] 任务行直接提供该状态允许的暂停、恢复和取消操作。
- [x] 排队任务显示真实的“排队第 N 位”。
- [x] 运行中的选中任务显示当前来源名和已用时间。
- [x] 已有任务运行时不阻止创建下一批次。
- [x] 真实界面人工验收通过。

## 协作复盘

- AI 快速完成布局重构和状态/时长派生，但“用户能看到多少”仍需通过真实窗口尺寸检查。
- 人指出顶部占用过大和隐藏刷新能力，把优化目标从“功能可用”提升为“正常路径可发现”。
- 双栏与队列行直接操作减少了滚动和定位成本；已用时间避免长 S5 被误判为卡死。
