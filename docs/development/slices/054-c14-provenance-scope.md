## 控制契约

### 背景与失败场景

- 触发问题：c14 fresh N=10 为 0/10，10 个 attempt 全部因 R3 失败；R1 为 2 pass、8 fail，R2 为 8 pass、2 fail。
- 不处理时的用户损失：来源归属正确的答案会因为未额外展开“代码执行风险＋提示注入”而被判整题失败，c14 无法反映其主要考点。
- 现有流程为什么不足：R3 检验的是另一个问题“外部资源有哪些风险”，超出“这句话是原文还是模型补充”的题目目标。
- 本切片负责什么：删除 R3，发布新 c14 revision，同步 active suites，并用旧 run 冻结重判。
- 本切片不负责什么：不修改 c14 题面、R1、R2、X1、Agent 提示词、检索工具或 Judge v3。
- 停止或推翻条件：若删除 R3 后 R1/R2 仍暴露判据含义冲突，应另立切片，不在本切片继续扩展语义。

### 用户可观察目标

c14 答案只需完成来源分层和原文归类即可通过，不再被要求附带“外部资源的两类风险”这一额外知识。

### 核心不变量

1. R1 必须区分“不是原句”与“完全没有语义依据”。
2. R2 必须指出 MCP servers 与第三方插件、网页搜索工具同属不可控外部内容。
3. X1 继续禁止把 MCP 升级为最大、最主要或唯一攻击面。
4. 旧 case revision 与旧 judgment 保留，不覆盖历史。
5. 重判只使用原 run 的 10 个答案，不重跑 Agent。

### 错误代价与非对称门禁

| 错误类型 | 具体例子 | 用户影响 | 处理分类 | 指标与阈值 |
| --- | --- | --- | --- | --- |
| 来源归属遗漏 | 答案只说“模型补充”，不说明 MCP 的外部内容归类有原文依据 | 用户无法区分原句与语义依据 | 阻断 | R1 或 R2 fail |
| 来源过度升级 | 把 MCP 说成最大、唯一或最主要攻击面 | 错误放大文章立场 | 阻断 | X1 violated |
| 额外知识未展开 | 未提代码执行风险和提示注入 | 本题无需回答 | 可容忍 | 不再作为 criterion |

### 明确禁止

- 不得在删除 R3 的同时修改 R1、R2 或 X1。
- 不得重跑 Agent 后把生成变化混入本次判据校准。
- 不得覆盖或删除旧 c14 revision、旧 judgment。

## 协作复盘

- AI 明显加速的环节：从 10/10 R3 同因失败中区分题目范围与工具使用问题。
- 负责人失去系统模型的环节：未出现。
- 真正发现问题的控制点：R3 原文成立，但不属于本题目标。
- 只有仪式感、没有产生判断价值的流程：无。
- 下一次准备调整的一到两项：先冻结重判，再决定是否处理 R1 表达稳定性。

## 已知风险与后续

- 未验证项：没有重跑 Agent，因此本结果只证明旧 10 个答案在新判据下达到 K=9。
- 接受的风险：c14 不再验证外部资源两类风险，可另立用例。
- Judge 版本影响：旧 v2 对 R1 为 2 pass、8 fail；新 v3 对同一批答案的 R1 为 10 pass。该变化来自 v3 reason-first 合同，不能全部归因给 R3 删除。
- 后续待办或 ADR：观察 v3 对“非原句但语义有依据”的判定是否稳定，并避免把 c14 的 9/10 解释为 Agent 行为发生变化。

## 停止与推翻条件

- 若 R1/R2 在删除 R3 后仍无法区分真实语义，停止本切片并另做语义校准。
- 若工具补读行为成为主要用户问题，另立 Agent 工具使用切片。
