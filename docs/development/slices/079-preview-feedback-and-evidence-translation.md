## 控制契约

### 背景与失败场景

- 触发问题：试抽取成本只显示零散输入 token；运行中状态不够醒目；英文 evidence
  阅读成本高且重复翻译会重复消耗 token。
- 不处理时的用户损失：用户难以判断试抽取规模，等待时误以为界面卡住，或在阅读英文
  证据时依赖外部翻译工具。
- 本切片负责：总量优先的成本计划、queued／running 动效、英文原文中文翻译及
  跨 run 缓存。
- 本切片不负责：修改原文、把翻译写入 candidate、改变 Profile 比较语义或生成 Wiki 页面。

### 用户可观察目标

用户可以一眼看到预计总 token，运行中能明显区分等待与抽取状态，并可显式翻译当前结果中
的英文证据；重复请求相同 evidence 时显示缓存复用。

### 核心不变量

1. 成本计划先展示预计总 token，再展示输入、输出和调用明细。
2. 运行状态变化不改变 Preview Run 的后端状态机。
3. 翻译只新增辅助文本，不覆盖 evidence 原文或 block ID。
4. 翻译缓存按 Prompt 版本、模型 ID 和原文 hash 隔离，文本或模型变化不得复用旧结果。
5. 翻译失败不得把缺失项伪装成成功，也不得写入不完整的部分缓存。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| Chat API Key 缺失 | 明确提示先配置 Key | 原候选和已有缓存 | 配置后重试 |
| 翻译返回缺失或多余 block | 翻译失败，不展示伪造结果 | 原候选和旧缓存 | 是 |
| 请求 block 不属于当前 run | 明确拒绝 | 当前 run | 选择合法 evidence 后重试 |
| Provider 临时失败 | Provider 错误 | 已成功缓存的其他翻译 | 是 |

### 明确禁止

- 不用翻译结果替换原文 evidence。
- 不把中文翻译作为 candidate alias、匹配证据或比较依据。
- 不跨模型或跨 Prompt 版本复用翻译缓存。
- 不在保存、查询或开始试抽取时隐式调用翻译。

## 目标

降低试抽取前的成本理解门槛、运行中的状态识别成本和英文证据的阅读成本，同时避免重复翻译费用。

## 输入与输出

- 输入：Preview plan；completed run 文档范围内的原文 block IDs。
- 输出：总量优先的 token 计划；实时运行反馈；按 block 返回的中文翻译和缓存复用状态。

## 证据包

### 自动化证据

- 命令：Profile 目标 pytest、Ruff、前端类型检查、注释检查和生产构建。
- 覆盖不变量：1、3、4、5。
- 结果：目标测试、静态检查和构建通过。

### 运行证据

- 用户操作序列：估算 token → 开始试抽取 → 观察动态状态 → 翻译英文证据 → 再次进入含相同
  evidence 的 run 并确认缓存复用。
- 实际结果：用户已检查成本摘要、运行反馈、翻译缓存和原文／中文切换。

## 已知风险与后续

- 未验证项：真实桌面中的动效观感、英文检测启发式和真实成本的估算偏差。
- 接受的风险：首版只对明显英文证据显示批量翻译入口。
- 后续待办或 ADR：若真实成本偏差持续较大，再引入 Provider 侧历史均值或独立预算策略。

## 停止与推翻条件

- 翻译结果被用于事实判断或身份合并；
- 缓存无法证明原文、模型或 Prompt 版本边界；
- 动态状态会误导用户认为任务已运行但后端实际未进入 queued／running。
