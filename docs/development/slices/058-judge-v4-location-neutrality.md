- 人工验收：沛东确认“不判内容位置”应作为 Judge 通用规则，而不是重复写入单条 criterion

## 控制契约

### 背景与失败场景

- 触发问题：Judge v3 在 c15 R4 中把表后补充的隔离开销与用户依赖判为缺失，理由是它们不在主表“代价”列。
- 不处理时的用户损失：语义完整的答案会因为展示位置被判失败，评测结果依赖排版。
- 现有流程为什么不足：v3 只要求 criterion 是唯一标准，没有明确禁止判官自行增加表格位置条件。
- 本切片负责什么：新增 Judge v4，明确除 criterion 要求位置外，答案任意位置的语义等价内容都计入。
- 本切片不负责什么：不修改 criterion、Agent prompt 或 v3 历史规则。

### 用户可观察目标

同一 criterion 下，信息位于主表、补充表、正文、脚注或相邻段落时，判官按语义而非位置判定。

### 核心不变量

1. v2、v3 prompt 与 hash 保持不变。
2. v4 继承 v3 的 reason-first 和理由/verdict 一致性要求。
3. v4 只新增位置无关规则。
4. 所有 active LLM criteria 迁移到 v4，checker 不变。
5. c15 R2/R3/R4 不因本切片改语义。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| criterion 明确要求指定位置 | 按明确要求判定 | v4 规则与 criterion | 是 |
| 信息位于表后补充 | 计入语义覆盖 | 完整答案 | 是 |
| v3 历史重放 | 继续使用 v3 hash | v3 prompt 原文 | 是 |
