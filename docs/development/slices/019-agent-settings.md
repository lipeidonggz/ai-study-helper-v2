## 控制契约

### 用户可观察目标

1. 用户可以在同一设置页保存、测试和删除独立的 embedding Key 与对话 Key。
2. 用户可以调整下一次问答使用的 Top-K、最大输出 token、上下文预算、请求累计预算和最大工具调用数。
3. 页面明确区分用户可调参数和系统管理参数，并提供默认值与取值范围。

### 核心不变量

1. API Key 仍只进入 Windows Credential Manager，不进入 SQLite、日志或响应。
2. 设置变更只影响之后创建的 Agent 请求，不改变进行中的请求。
3. `top_k` 默认 5、范围 3–10；`max_output_tokens` 默认 8192、范围 2048–384000。
4. 查询模式、候选深度和 RRF 常数仍由系统管理；上下文预算、请求累计预算和工具调用上限可由用户调整。
5. 非法数值在 API 边界被拒绝，不保存部分设置。
6. 前端所有本地 API 请求都有分类超时；超时退出忙碌状态并显示可操作错误。
7. 每个可调数值字段始终显示允许范围；越界或跨字段冲突在输入时立即提示，并阻止保存。

### 明确禁止

- 不把参数暴露给 Agent；
- 不因为修改查询参数重建 collection；
- 不把 Key 显示在回填输入框；
- 不在本切片实现聊天页面或 SSE。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| Key 测试失败 | 明确错误信息 | 已保存的 Key 与旧测试状态 | 是 |
| 数值超出范围 | 字段级错误 | 原设置 | 是 |
| 设置读取失败 | 设置页错误状态 | 原本地配置 | 是 |
| 设置写入失败 | 保存失败，不伪装成功 | 原设置 | 是 |

## 目标

形成面向普通用户的统一模型与 Agent 运行设置入口，并为下一片流式问答提供稳定配置边界。

## 输入与输出

输入：

- 两类 API Key；
- Top-K、最大输出 token、上下文预算、请求累计预算和最大工具调用数。

输出：

- 可持久化、可重新加载的设置；
- 每次 Agent 请求固定的运行配置；
- 当前设置和系统管理参数的可读状态。

## 不包含

- 流式问答页面和 SSE；
- trace viewer；
- 候选深度、RRF 常数和查询模式的用户配置；
- 多知识库或模型供应商切换。

## 关键转折与根因

- 2026-10-22 人工保存运行参数时页面显示 `TypeError: Failed to fetch`。根因是运行参数接口使用 `PUT`，但后端 CORS 只允许 `GET`／`POST`；浏览器预检失败，请求没有到达保存处理逻辑。现已允许 `PUT`，并增加浏览器预检回归测试。
