## 控制契约

### 背景与失败场景

- 触发问题：评测样本详情把 `answer` 放入 `<pre>`，Markdown 表格、标题和段落显示为等宽纯文本，长表格阅读困难。
- 不处理时的用户损失：人工复核需要同时看懂判定理由和答案结构，纯文本会显著增加阅读成本。
- 现有流程为什么不足：产品问答页已有安全 Markdown 渲染器，但评测详情复制了另一条纯文本显示路径。
- 本切片负责什么：让样本详情答案正文复用 `renderChatMarkdown` 和 `chat-answer-text` 样式。
- 本切片不负责什么：不改变答案内容、引用数据、判定结果、弹窗结构或运行轨迹。
- 停止或推翻条件：若复用渲染器导致评测答案中的来源占位符行为不可接受，应提取独立只读 Markdown 组件，而不是回退到 `<pre>`。

### 用户可观察目标

样本详情中的 Markdown 标题、列表、段落、代码和表格按产品问答正文的排版显示，长答案保留折叠与内部滚动。

### 核心不变量

1. 答案仍使用产品销售问答的安全 Markdown 渲染器。
2. 原始 answer 字符串不被修改。
3. 无答案时显示明确空状态。
4. 弹窗、判定和轨迹结构不变。

### 明确禁止

- 不启用原始 HTML。
- 不把评测答案写回或重新生成。
- 不修改判定与引用数据。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| answer 为空 | “无答案” | attempt 原状态 | 是 |
| Markdown 含表格 | 按表格渲染并允许内部滚动 | 原始 answer | 是 |
| 渲染器拒绝 HTML | 原始 HTML 不执行 | 安全文本 | 是 |
