## 控制契约

### 用户可观察目标

1. 用户可以在独立“问答”导航中提交问题，并看到按安全 Markdown 格式逐步出现的答案正文。
2. 等待期间在固定状态区显示用户可读的当前动作，例如“正在查看文档结构”“正在检索相关段落”“正在组织回答”，并实时显示输入、输出 token。
3. 用户可以看到答案引用的文档来源，并在运行中主动停止回答。
4. 连接中断、取消、预算终止和模型失败都不会被显示成完整成功。

### 核心不变量

1. 每次运行固定请求开始时的 collection 快照、运行参数和 trace ID；运行中修改设置不影响该次问答。
2. `answer_delta` 只在模型进入 `Finish[...]` 最终答案后发送；Thought、Action 和 Observation 不进入用户正文。固定状态区只展示受控的工具／阶段标签。
3. SSE 事件带稳定的 `schema_version`、`trace_id`、单调 `sequence`；断线续传不得重复渲染正文。
4. 流式中的 token 数量必须标记为估算；模型调用结束后用供应商 usage 替换，输入与输出分别累计并保留数据来源。每次运行只有一个终态：完整成功、部分成功、失败或已取消。
5. 答案按 GitHub Flavored Markdown 渲染，但禁用原始 HTML；引用来源通过结构化元数据展示，不把文档 HTML 注入页面。

### 明确禁止

- 不向普通用户展示 Thought、原始提示词或完整工具 JSON；
- 不因 SSE 断线自动重新提交问题或开启第二次运行；
- 不把前端收到部分文本等同于回答完整；
- 不在本切片实现跨请求多轮会话、trace viewer 或持久化会话列表；
- 不把模型或工具失败静默降级成空答案。
- 不允许模型答案中的原始 HTML、脚本或危险链接进入 DOM。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| 缺少对话 Key、无活动快照 | 提交前明确阻断和修复入口 | 原设置与原快照 | 是 |
| SSE 首次连接失败 | “连接中断，尚未开始回答” | 不创建第二次运行 | 是，可重试同问题 |
| 回答中断线 | 已接收正文标记“连接中断”，不标完整 | run ID、最后一个事件序号 | 有事件缓冲区时可续传，否则需重新提问 |
| 用户主动取消 | 已生成内容标记“已停止”，终态为 `canceled` | 已接收正文与取消原因 | 是，可重新提问 |
| 模型或工具终态失败 | 明确错误及错误码；保留已有正文并标“不完整” | 失败事件与已有文本 | 是 |
| 预算终止 | 部分回答加确定性预算警告 | limitations、触发参数和终态 | 是，可调整设置后重试 |

### 人工检查点

- 编码前确认流式范围、续传、取消、来源展示与切片边界；
- 后端事件流完成后，先用确定性 fake provider 检查事件顺序和正文提取；
- 前端首条主路径完成后，确认真实窗口能逐步显示正文；
- 最后人工验证取消、断线／重连和错误终态。

## 目标

把现有一次性 Agent API 升级为可观察、可中断、可恢复的流式问答垂直路径，并提供面向普通用户的问答工作台。

## 输入与输出

输入：

- 用户问题；
- 请求开始时固定的运行设置与 collection 快照；
- DeepSeek 流式模型输出与检索工具事件。

输出：

- REST 启动端点与 SSE 事件流；
- 结构化终态、预算限制和来源元数据；
- 前端问答工作台、过程状态、流式正文和停止入口。

## 不包含

- 多轮会话记忆与会话历史列表；
- trace 持久化、trace viewer 和诊断包；
- 评测台；
- 富文本／Markdown 白名单渲染；
- 修改 Agent 提示词语义。

## 验收条件

- [ ] 用户提交问题后先看到固定状态区的当前动作和输入／输出 token，再看到正文逐步出现。
- [ ] 答案中的标题、列表、粗体、代码和表格按安全 Markdown 渲染，原始 HTML 不生效。
- [ ] 最终回答、部分回答、失败和取消四种终态在界面和 API 中明确区分。
- [ ] Thought、Action、Observation 和工具原始 payload 不进入用户正文。
- [ ] SSE 事件序号单调，按最后序号重连不会重复追加正文。
- [ ] 用户取消后不再启动新的模型或工具调用，并保留已生成内容。
- [ ] 来源按钮或引用区能解析查询运行实际返回的块并显示标题／来源。
- [ ] 从来源卡片打开文档后，页面自动滚动到对应 block 并持续突出显示。
- [ ] 缺少 Key、快照不可用、断线、模型失败和预算终止均有明确反馈。
- [ ] 完整质量门、真实 DeepSeek 流式回归和人工窗口验收通过。

- 当前桌面应用提供独立“问答”导航和固定问答布局。

### 失败探针

- 慢模型的流式读取可被取消信号立即打断，终态为 `canceled` 且无后续模型／工具调用。

- 来源解析按全局唯一的 `block_id` 去重并精确匹配；当前快照漂移时前端禁止打开旧来源文档。

## 关键转折与根因

- 真实窗口首次验收时，正文引用全部显示“来源未匹配”。已确认根因是工具返回的 `block_id` 本身已经包含稳定文档身份，而后端来源键又额外拼接了一次 `doc_id`，形成双前缀。规范来源键已改为 `block_id`，设计文档和提示词同步澄清；当前没有持久化旧会话，因此不增加旧格式兼容。
- 修正来源键后仍有引用未匹配。真实 `block_id` 可包含多个 `#` 分段，前端首个解析正则错误地在第二个 `#` 处截断了键。解析已改为按引用分隔符拆分并保留完整键值；实时探针确认模型引用与工具来源逐项相等。
- 真实窗口感觉答案瞬时出现，但后端时间戳证明模型和 Runtime 都在持续分块。根因是浏览器一次读取可能包含多个 SSE 事件，Vue 在同一个 JavaScript 任务中把它们合并为一次绘制。前端已增加按动画帧消费的事件队列，保持事件顺序并让正文按可见节奏出现。

## 协作复盘

- AI 明显加速的环节：DeepSeek 流式适配、Runtime 事件、SSE 管理、前端主路径和确定性失败测试可以在同一垂直切片中快速串通。
- 负责人失去系统模型的环节：AI 首次把“后端分块”当成“界面一定在逐字渲染”，没有同时验证浏览器绘制节奏；引用键也曾因双前缀和多 `#` 分段连续出错。
- 真正发现问题的控制点：真实桌面运行、真实 DeepSeek 时间戳探针和负责人对产品语义、Markdown、引用定位的逐项检查。
- 只有仪式感、没有产生判断价值的流程：R1 过于基础，没有形成新的行为判断。
- 下一次准备调整的一到两项：反向解释优先问失败／状态边界，不问肉眼可确认的问题；声称“流式完成”前必须同时验证协议分块和界面实际绘制。
