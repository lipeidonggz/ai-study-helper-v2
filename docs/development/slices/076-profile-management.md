## 控制契约

### 背景与失败场景

- 触发问题：现有系统没有可持久化的 Profile，也没有用户自定义抽取策略和 selected Profile。
- 不处理时的用户损失：用户无法表达不同领域或用途的抽取意图，无法为后续 Preview 和构建确定输入。
- 现有流程为什么不足：11 号实现把抽取规则、候选和 Wiki build 固化在旧模型里，不能由用户安全调整。
- 本切片负责什么、不负责什么：负责 Profile 草稿、通道配置、确定性 Prompt 编译、冻结和 selected；不执行预览、全库 build、页面或检索。
- 什么情况下应停止或撤掉本切片引入的机制：如果无法保证冻结后不可变、selected 原子切换，或必须开放任意 Prompt 才能表达策略，则停止并回到设计。

### 用户可观察目标

用户可以查看只读的“技术学习与参考”Profile，创建空白或克隆草稿，编辑结构化抽取通道和高级设置，保存后重新打开，校验通过后确定使用；确定后该 Profile 不可修改，调整会创建新的 Profile。

### 核心不变量

1. draft 可以反复保存和修改；frozen Profile 不可原地修改。
2. “确定使用此 Profile”必须在单一事务中完成校验、必要时冻结和 selected 指针切换。
3. 系统 Profile 固定包含四个只读 discovery channel，用户只能克隆后调整。
4. Profile 的 channel 配置、系统契约、compiler 版本和 profile hash 足以确定性生成只读编译 Prompt。
5. 本切片不导入 `app.wiki` 业务模型；只有用户主动点击 AI 建议按钮时才调用聊天模型，
   且不得自动触发 Preview Run 或全库 build。

### 错误代价与非对称门禁

| 错误类型 | 具体例子 | 用户影响 | 处理分类 | 指标与阈值 |
| --- | --- | --- | --- | --- |
| 冻结后被修改 | API 更新 frozen Profile | 历史结果不可解释 | 阻断 | 集成测试 100% 拒绝 |
| selected 非原子切换 | 校验失败仍替换旧指针 | 用户当前选择被破坏 | 阻断 | 失败后旧 selected 不变，100% |
| 不完整 Profile 被 selected | 0 个通道或空名称 | 后续无法执行 | 阻断 | 冻结／select 校验 100% |
| draft 保存失败 | 用户暂时缺少某些字段 | 用户无法分步编辑 | 可容忍但不得发生 | draft 可分步保存 |
| 系统模板被修改 | 用户调整预置四通道 | 基线漂移 | 阻断 | 系统 Profile 只读 |

### 明确禁止

- 不提供任意 system prompt 编辑。
- 不把 channel 名称或说明编译成 candidate label。
- 不在保存 draft、确定 Profile 或更新 selected 时调用抽取模型。
- 不静默修正用户通道配置或自动删除冲突字段。
- 不覆盖旧 Profile；调整 frozen Profile 必须创建新 `profile_id`。
- 不依赖 `app.wiki` 业务模型或 `wiki_*` 表。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| draft 协议字段非法 | 明确字段错误 | 旧 draft 内容 | 是 |
| draft 不完整 | 可保存，显示未完成项 | 最新 draft | 是 |
| 存在语义冲突 | `conflicted` 和冲突字段 | draft 与冲突审计 | 修改后可恢复 |
| selected 切换事务失败 | 可操作错误 | 原 selected 不变 | 是 |
| 系统 Profile seed 冲突 | 启动或迁移错误 | 原数据库 | 修复代码或迁移后重试 |

## 目标

建立 Profile 数据模型、迁移、确定性编译器、服务层和受保护 API，并提供对应前端页面。

## 输入与输出

- 输入：Profile 名称、说明、领域上下文、用途、代表性问题、1–8 个抽取通道、全局排除项、粒度、补充说明。
- 输出：可变 draft、不可变 frozen Profile、只读编译 Prompt 和知识库 selected 指针。

## 不包含

- Preview Run、候选抽取、遗漏补抽、清单、比较；
- 全库 build、canonical topic、页面、链接、索引和问答；
- 旧 Wiki 数据迁移。

## 协作复盘

- AI 明显加速的环节：Profile 数据模型、确定性校验、编辑界面和自动化测试同步落地。
- 负责人失去系统模型的环节：早期“预览”“文档清单”等命名不够贴近用户任务，需要多轮界面反馈才收敛。
- 真正发现问题的控制点：真实界面操作和用户对术语、弹窗与操作优先级的连续反馈。
- 只有仪式感、没有产生判断价值的流程：逐切片单独人工复审被批次验收替代，减少重复检查。
- 下一次准备调整的一到两项：先冻结用户术语表，再进入界面实现；关键流程尽早提供真实截图验收。
