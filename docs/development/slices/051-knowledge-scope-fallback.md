## 控制契约

### 背景与失败场景

- 触发问题：c12 要求解释 gVisor 是什么，但文档只给出名称、产品角色和可靠性评价。10/10 答案都停留在“文档中的 gVisor”并明确表示文档没有给出技术定义，导致 R1 全部失败。
- 不处理时的用户损失：用户直接询问概念或机制时，Agent 因过度保守而不提供模型已具备的常识性解释，问题没有被完整回答。
- 现有流程为什么不足：提示词只说明模型补充不能冒充原文，没有说明“通用背景知识可以补充，文档事实不能补”的判断边界。
- 本切片负责什么：在 Agent 系统提示词中加入通用知识与文档事实的分界，升级 prompt bundle，并对 c12 做新数据验证。
- 本切片不负责什么：不写任何具体用例答案，不修改检索工具、Harness、判官或 citation annotation。
- 停止或推翻条件：如果模型借“通用知识”编造文档立场、精确数据或覆盖结论，应回退并收紧该规则。

### 用户可观察目标

当问题同时需要通用解释和文档事实时，Agent 明确区分两部分：通用解释可补充且不会冒充原文，文档事实仍必须由本次工具证据支持。

### 核心不变量

1. 文档事实、原文观点、精确数据、作者立场、出处和覆盖情况仍必须有 block 支持。
2. 通用背景缺失时允许使用模型知识，但必须说明不是原文表述。
3. 文档本身是否说了某事、原文数据和覆盖结论不能用模型知识补齐。
4. 提示词不得包含 gVisor、MCP 等具体用例答案。

### 明确禁止

- 不得用模型知识冒充原文、block 证据或作者立场。
- 不得因为模型“知道”某内容而断言文档提到过。
- 不得为通过 c12 把 gVisor 定义直接写进系统提示词。
- 不得修改其他协议、工具或判定项来迎合单个用例。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| 文档缺少通用背景 | 通用解释和“不是原文”的提示 | 通用说明与文档事实分离 | 是 |
| 文档事实缺失 | 明确说明证据不足 | 不补造文档结论 | 是 |
| 模型编造定义 | 评测失败或人工识别 | 答案与 trace | 是 |

- AI 明显加速的环节：将用户提出的通用边界转写成不含答案泄漏的提示词，并完成单例修复与两个回归。
- 负责人失去系统模型的环节：未出现；负责人纠正了“术语/技术”过窄条件，改为按缺失信息性质判断。
- 真正发现问题的控制点：c12 从全失败变为全通过，同时 c10、c11 保持全通过。
- 只有仪式感、没有产生判断价值的流程：无。

## 已知风险与后续

- 接受的风险：模型可能把不确定的通用知识说得过细；提示词已要求限定表述和区分来源。
- 后续：观察包含模型知识补充的回答在 citation support 中是否出现更多 unknown；该项目前是软质量属性。
