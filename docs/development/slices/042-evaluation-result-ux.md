## 控制契约

### 用户可观察目标

评测历史可以手动刷新；一个执行批次先按 case 分组，再展开该 case 的各个样本；判定结果页通过 case 选择、状态筛选和判定矩阵快速定位异常样本，矩阵是唯一判定工作区；单个样本的判定、轨迹和人工操作统一在“判定／运行轨迹”双页签详情中完成，并分别保留滚动位置。

### 核心不变量

1. Case 的 N/K 门禁结论、样本 pass／fail／pending 分布和 evaluation revision 完整性必须分开显示。
2. 执行批次必须以 case 为第一层、attempt 为第二层；问题摘要和样本序号可稳定定位。
3. 判定总览中的单元格只能打开对应样本详情，不修改判定事实；详情以“判定／运行轨迹”两个页签呈现，切换时不卸载内容且各自保留滚动位置。
4. 历史刷新只重新读取服务端事实，不改变 run、case、判定或人工复核结果。
5. 前端展示变化不得改变后端 N/K、pending、红线或基线资格规则。

### 明确禁止

- 不把带 pending 样本的 K 门禁通过显示成无条件的普通绿色通过。
- 不用前端推测补齐缺失的 case、attempt 或 judgment。
- 不在刷新时重置用户当前的用例集筛选、选中的 run 或详情页签。
- 不把评测 revision 的“完整”与 case 的“通过”混为同一状态。
- 不在本切片修改后端聚合、判官、评测执行或基线规则。
- 不保留“按样本／按判定项”重复视图，也不恢复依赖旧样本列表的“上一个异常／下一个异常”。

### 失败语义

| 场景 | 用户看到什么 | 系统保留什么 | 是否可恢复 |
| --- | --- | --- | --- |
| 历史刷新失败 | 明确错误提示和上次成功刷新时间 | 当前 run 列表与选中状态 | 是 |
| 当前选中 run 已不存在 | 提示并选择最新可用 run；没有 run 时显示空状态 | 用例集筛选条件 | 是 |
| Case 没有 attempt | 该 case 下显示“无执行样本” | Case 汇总信息 | 是 |
| 判定项或样本缺失 | 使用缺失占位，不伪造 pass | 已有判定事实 | 是 |
| 刷新期间重复点击 | 按钮禁用 | 当前视图 | 是 |

### 人工检查点

- 编码前需要确认的契约或风险：刷新保持当前筛选与选中项；判定矩阵作为总览而不取代详情。
- 实现中途需要查看的可运行路径：历史刷新 → 选择 run → 展开 case → 查看样本 → 判定总览 → 点击矩阵单元格。
- 完成后需要人工执行的操作：用 c5-001 的 9 pass／1 pending 现场检查层级、颜色和异常定位。

### 决策预算

- 预计 B 级决策数量：3。
- 是否存在 C 级决策：否。
- 超过预算时的拆分方式：历史刷新、执行批次层级、判定导航分别拆成独立切片。

## 目标

1. 在最近执行批次标题增加手动刷新和最近成功刷新时间。
2. 将执行批次 attempt 列表改为 case → sample 两级折叠列表。
3. 判定结果使用唯一的总览矩阵，并提供 case 选择、状态筛选、文本搜索和矩阵定位。
4. 判定矩阵覆盖 R、X 和通用跨项检查；单元格打开聚焦详情；完整判定、运行轨迹、criterion 人工改判和引用支持复核都在同一个样本详情内完成。
5. 删除旧的“按样本／按判定项”视图及其“上一个异常／下一个异常”导航。

## 输入与输出

- 输入：现有 run、attempt、case revision、evaluation revision、judgment、check 和 result matrix API 数据。
- 输出：无新后端数据；仅调整前端查询触发、分组、筛选、导航和展示。

## 不包含

- 后端聚合口径调整。
- N/K、pending、引用复核和基线资格规则修改。
- 自动轮询历史 run。
- 批量人工改判。
