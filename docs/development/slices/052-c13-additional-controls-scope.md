## 控制契约

### 背景与失败场景

- 触发问题：c13 题面明确要求列举“除了沙箱／虚拟机／出口控制”之外的手段，旧 R1 却把出口代理与检查列为五类必选之一；同时要求挂载模式、宿主机钥匙串和按会话缩权 token 等具体参数，导致语义正确的答案被误杀。
- 不处理时的用户损失：题面与判据互相冲突，Agent 无法同时满足；正确答案可能因为少写一个实现参数而失败，评测失去可信度。
- 现有流程为什么不足：旧 R1 没有区分“手段类别”和“实现子参数”，也没有限制模型层概率性防护与硬隔离的边界。
- 本切片负责什么：修正题面和 R1，保留 X2 边界，并对已有 c13 run 的同一批答案重新判定。
- 本切片不负责什么：不修改 Agent、Harness、检索、citation annotation 或其他用例；不重跑 c13 Agent。
- 停止或推翻条件：如果四类核心手段仍不能代表题面，应重新定义 c13，而不是继续增加子参数。

### 用户可观察目标

c13 的题面、四类必答手段和边界互不冲突；答案可以用语义等价表述或代表性例子说明每类作用，而不会因缺少所有实现子参数被误判。

### 核心不变量

1. 沙箱、VM、出口控制不能替代四类必要手段。
2. 文件系统边界、凭证隔离、工具权限最小化、工具／外部内容检查四类缺一不可。
3. 不强制列举全部挂载模式或逐字写出按会话缩权 token。
4. 模型层概率性防护不能冒充硬隔离。
5. 重判使用原 run 的 10 个答案，不重跑 Agent。

### 明确禁止

- 不得把出口控制继续列入“除了出口控制”后的必答项。
- 不得用模型层系统提示、分类器或探针替代四类硬控制。
- 不得因为答案多写其他合理控制而扣分。
- 不得删除或覆盖旧 c13 revision 与旧 judgment。
