## 1 分类原则

本文采用两层结构：

1. **第一层：关系观察轴。** 由设计者维护，用于规定从什么角度观察对象之间的关系、审查跨领域覆盖范围和发现分类缺口。
2. **第二层：二级关系标签。** 是某个观察轴下可用于检索的语义标签。主 Agent 根据完整用户问题选择轴和标签，并用带求值作用域的表达式组合它们，再检索对应关系命题和原文证据。

第二层关系必须满足：

- 能够用一个稳定的语义定义说明；
- 能够在至少三个差异明显的领域中找到实例；
- 用户可能把它作为一个独立检索角度；
- 与相邻关系有明确、可解释的排除边界；
- 可以被原文证据直接支持，不依赖模型补写。

分类不要求每一条原文关系只能参与一个现实情境，也不要求一条关系实例在同一轴内只能获得一个标签。同一关系实例可以在多个轴上得到标签，也可以在同一轴内得到多个二级标签；每个额外标签都必须有独立原文依据和可区分的检索价值，完整语义由自然语言命题和原文证据承担。

主 Agent 的接口保持简单：

> 完整用户问题 + 冻结关系轴与二级标签目录 → 带 `AND`／`OR` 和求值作用域的表达式树。

不增加“关联关系组”“逆关系表”或固定查询映射。找全类问题默认可以在同一轴的备选标签之间使用 `OR`；只有用户明确要求同时具备多个语义时才使用 `AND`，并声明在关系实例、block 还是文档范围内求交。若同一问题在不同运行中无法稳定表达，先调整标签定义、边界或表达式语义，再判断是否需要合并或删除标签。

### 1.1 分面分类语义

当前分类采用分面结构，而不是父子本体树：

1. 一级是彼此独立的观察轴，用来规定从什么角度观察对象之间的关系。不同一级之间不要求存在继承、优先级或固定映射；知识库根据自身关注范围选择启用哪些轴。
2. 二级是某个观察轴下赋予关系实例的语义标签。同轴标签允许重叠，不要求任意两个标签互斥；所有标签的并集必须覆盖该轴声明适用范围内的全部适用关系实例。
3. “覆盖”的适用范围是该轴中由原文明确表达、且属于当前知识库范围的关系实例，不是所有可能的世界关系。轴不适用、原文未表达或知识库明确排除的内容不进入该轴适用范围。
4. 关系实例身份与分面标签分开。一条对象关系可以在多个轴上有标签，也可以在同一轴内有多个二级标签。例如“只有经过批准才能访问外部网络”可以同时具有条件依赖、规范许可和权责控制等不同轴上的标签；同一轴内也允许并存多个有独立证据的标签。
5. 主 Agent 输出带求值作用域的布尔表达式树。`OR` 表示任一备选标签满足即可，`AND` 表示同一关系实例、block 或文档范围内必须同时满足；不能只返回一个不带作用域的标签列表。

如果两种语义差异对应不同观察轴，应拆成不同轴，而不应制造轴之间的父子关系。如果同轴标签无法形成覆盖，或大量标签完全重合而没有独立检索价值，应先收窄轴的适用范围、合并冗余标签或重新定义，不能用优先规则长期掩盖分类结构问题。

当前 12 个一级仍是历史候选，不是已经冻结的轴目录。F05“分类与结构”、F10“来源与证据”和 F12“主体与资源”等是否属于单一观察轴仍需按 15.1 重新审计；在完成审计前，不能宣称现有 38 个具体关系已经构成当前二级标签目录。

## 3 F01 因果与作用

### 3.1 家族定义

一个对象、事件、状态或机制，对另一对象的发生、可能性、程度或持续状态产生明确作用。

本家族不负责表达以下内容：

- 某行动是否被明确允许或禁止，属于“允许与禁止”；
- 某行动是否以另一条件为前置、某对象是否必须借助另一条件才能成立，或目标只能在什么边界内成立，属于“条件与控制”；
- 某行为服务的预期目标，属于“目的与用途”；
- 没有作用来源的单纯状态变化，属于“状态与过程”。

### 3.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 导致 | 前者实际造成或引发后者的发生、结果或状态 | 原文明确表达前者实际造成、引发或产生后者，不能只靠常识推断因果关系 | 仅相关、共同出现或可能产生影响不算；条件前置归“条件控制”；预期目的归“目的与用途” | 法律：关键证人失联导致庭审延期。<br>临床医学：长期高血糖导致血管损伤。<br>历史：粮食歉收导致粮价上涨。 |
| 使能 | 前者使后者成为可能或变得可行，但不保证后者实际发生 | 原文明确表达某能力、行动或状态因前者而成为可能、可行或可执行 | 它可以是“可能性”的充分或贡献条件，但不是目标实际发生的充分条件；实际发生并被造成时优先归“导致” | 法律：生效判决使权利人能够申请强制执行。<br>临床医学：及时开放气道使患者能够接受机械通气。<br>历史：铁路建设使军队能够快速跨区域调动。 |
| 阻止 | 前者阻止、阻断或使后者无法发生 | 原文明确表达前者阻断后者的发生、进入、流动或继续 | 只表达规范许可或范围边界时归“允许与禁止”或“条件控制”；单纯失败结果而没有阻断来源时不算 | 法律：财产保全冻结账户，阻止被执行人转移资金。<br>临床医学：抗凝治疗阻止血栓继续扩大。<br>历史：防线阻止敌军进入城市。 |
| 增强 | 前者提高后者的程度、概率、强度、范围或有效性 | 原文明确表达作用方向为提高，并说明被提高的对象或属性 | 没有作用来源的单纯数量变化归“状态与过程”；方向不明的一般“影响”不抽 | 法律：更严格的监管提高了违法行为被发现的概率。<br>临床医学：运动训练提高心肺耐力。<br>历史：铁路扩张提高了物资运输效率。 |
| 减弱 | 前者降低后者的程度、概率、强度、范围或有效性 | 原文明确表达作用方向为降低，并说明被降低的对象或属性 | 没有作用来源的单纯数量变化归“状态与过程”；方向不明的一般“影响”不抽 | 法律：和解协议降低了诉讼成本。<br>临床医学：降压药降低脑卒中风险。<br>历史：防疫措施降低了疫情传播速度。 |
| 维持 | 一个主体、机制或条件持续作用于对象或状态，使其在观察区间内保持既定状态、持续存在或持续可用 | 原文明确存在持续作用主体，并表达该主体使目标保持、持续或避免退出既定状态 | 纯静态状态描述不算；保存与恢复归“状态与过程”；表达必要条件或边界限制的“条件控制”不能改写为“维持” | 法律：持续的权限复核使账户权限保持在授权范围内。<br>临床医学：胰岛素维持血糖稳定。<br>历史：常备驻军维持边境秩序。 |

### 3.3 家族级补充规则

1. “触发”暂不作为独立关系，归入“导致”，并在命题中保留“紧接着、随后、达到阈值时”等时间语义。
2. “影响”暂不作为独立关系。必须根据原文明确表达的方向和结果落到“导致、使能、阻止、增强、减弱”。

### 3.4 主 Agent 选择方式

主 Agent 只读取第二层具体关系及其定义，不读取“因果与作用”这一设计侧家族。

- “冷却系统如何维持温度？”选择“维持”；
- “哪些措施降低了停机风险？”选择“减弱”；
- “出口控制为什么能阻止数据外流？”选择“阻止”；
- “检查点让 Agent 能做什么？”选择“使能”；
- “温度为什么能保持稳定？”可以同时选择“维持”和“条件控制”，因为问题没有明确区分主动机制与必要条件。

这不引入额外关系结构，只是允许主 Agent 对确实跨关系的问题返回多个具体关系。

## 4 跨领域示例与验证策略

关系定义使用三个与当前主知识库差异明显的领域进行设计和人工打磨：

| 领域 | 主要检验的语义 |
| --- | --- |
| 法律 | 规范、义务、许可、禁止、例外、生效时间和程序前置 |
| 临床医学 | 因果、风险、预防、必要条件、程度变化和持续状态 |
| 历史 | 事件顺序、原因、目的、替代、来源和证据表述 |

每个具体关系至少各写一个法律、临床医学和历史例子。这些例子用于人工审核定义是否跨领域成立，不必全部写入抽取提示词，避免模型只学会照搬例子。

当前 Agent／AI 技术语料作为主应用验证集：

- 不参与关系和排除边界的设计调参；
- 等关系目录冻结后，再检查每个原文关系能否稳定映射到一个或多个具体关系；
- Agent 语料已经参与过早期设计讨论，因此不是严格独立的留出集；
- 后续仍需增加一个完全未参与设计的领域作为真正的泛化留出测试。

Agent 技术语料验证重点记录三类失败：

1. 原文存在明确关系，但无法归入任何具体关系；
2. 一个关系实例同时强烈匹配多个具体关系，且定义无法消歧；
3. 只有补写原文没有表达的信息，才能归入某个关系。

只有同一失败在多个独立样本中重复出现时，才修订关系目录；不能针对单个 Agent 样本反复增加模式或堆积提示词例外。

## 5 F02 条件与控制

### 5.1 家族定义

一个行动、状态、对象或结果要成立、执行、运行、继续、可见、访问或被接受，需要另一条件、必要支撑或范围边界得到满足。本家族回答的核心问题是：目标要成立或继续，需要满足什么。

本家族统一使用一个查询入口“条件控制”。文档不把条件控制继续拆成相互独立的子类型，也不要求抽取模型判断一个实例属于哪一类。前置步骤、持续支撑和范围限制只是帮助识别关系的说明，具体语义由 `proposition` 和原文证据保留。

### 5.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 条件控制 | 原文明确表达，某个对象、行动、状态或结果只有在某个前置条件、必要支撑或范围边界成立时，才能发生、继续、可见、访问或被接受 | 原文明确表达前置、必要支撑或范围边界对目标成立条件的限制；“必须、需要、只有、仅限、最多、不得超出、依赖、支撑”等表达都可作为证据 | 普通条件从句、共同出现、技术能力、单纯许可或实际阻断不自动归入；检查、验证、监控、防护、降低风险和一般建议不能单独反推出条件控制 | 法律：申请执行前，必须提交生效法律文书。<br>临床医学：脑组织存活依赖持续供氧。<br>历史：条约把海军吨位限制在约定上限。 |

### 5.3 识别说明，不划分子类型

条件控制可以由不同措辞表达，但所有实例只使用同一个关系模式：

| 原文表达示例 | 规范语义 |
| --- | --- |
| 执行 A 之前必须完成 B。 | 未完成 B 时，A 不能执行。 |
| A 缺少 B 就无法运行或继续。 | B 是 A 成立或继续的必要支撑。 |
| A 只能访问 B 范围，或最多执行 N 次。 | 超出该范围或上限时，相应访问或执行不能继续。 |
| 任务包含最大迭代次数等停止条件。 | 当前迭代次数达到上限时，任务不能继续下一轮。 |

上表不是子类型定义。模型不需要输出“前置要求、依赖或范围边界”这样的标签，也不应在多个标签之间做互斥选择。一个实例可能同时具有多种解释，例如“执行前最多检查三轮”同时包含前置动作、次数上限和停止条件。统一判断它是否表达条件控制即可。

### 5.4 普通条件、时间和例外的处理

普通条件、时间范围和例外仍由自然语言命题及原文证据完整保存，但不单独升级为关系模式。

例如：

> 当负载超过阈值且管理员尚未确认时，熔断器阻止请求进入下游系统；维护模式除外。

这里抽出的主关系是“阻止”。条件和例外交给命题保留：

> 当负载超过阈值、管理员尚未确认且不处于维护模式时，熔断器阻止请求进入下游系统。

用户询问“熔断器在什么情况下阻止请求”时，主 Agent 选择“阻止”，检索精确命题和原文证据后即可回答。这不要求主 Agent 再选择一个“条件关系”或“例外关系”。

需要区分两类情况：

- 条件只是限定另一关系的成立范围时，保留在命题中；
- 条件本身决定目标能否成立、继续、访问或被接受时，抽出“条件控制”。

两个事件之间本身的先后、并发或持续时间关系，归入 F06“时间与顺序”。时间作为某一关系的成立范围时，仍保留在该关系的命题中。

### 5.5 必要条件和充分条件的位置

“条件控制”采用必要条件式定义：

> 目标成立或获准，意味着相应条件或边界已经满足。

必要条件不在查询层继续拆成“前置要求、依赖、边界”三个入口。充分条件也不新增为独立关系，因为它必须说明充分保证的结果：打开可能性归“使能”，建立许可归“允许”，建立权力或资格归“授权”，造成实际排除归“阻止”，形成实际结果归“导致”。

### 5.6 主 Agent 选择方式

- “申请需要准备什么？”选择“条件控制”；
- “没有电源系统还能运行吗？”选择“条件控制”；
- “X 的前置条件是什么？”选择“条件控制”；
- “X 离不开哪些条件？”选择“条件控制”；
- “访问范围或数量上限是什么？”选择“条件控制”；
- “X 为什么能持续运行？”可以同时选择“条件控制”和“维持”，具体取决于问题关注必要条件还是主动持续作用。

## 6 F03 允许与禁止

### 6.1 家族定义

一个规则、主体或机制直接确认某项行动、访问或状态可以实施，或明确确认其不得实施。本家族只处理明确的规范极性：允许是正极性，禁止是完整负极性。

需要满足什么条件、存在哪些必要依赖、允许范围缩小到什么子集，归 F02“条件控制”。技术能力、实际阻断或空间边界也不由本家族承担。

### 6.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 允许 | 规则、主体或机制确认某项行动可以实施 | 原文明确表达许可、准许、获准或可以实施某项行动 | 技术能力上的可行归“使能”；授予权力或代表资格归 F12“授权”；限制适用条件或范围归“条件控制”；没有禁止但没有明确许可时不能补写 | 法律：法院准许当事人查阅本案案卷。<br>临床医学：主治医生允许患者进行轻度活动。<br>历史：地方当局允许商队通行。 |
| 禁止 | 规则、主体或机制确认某项行动不得实施 | 原文明确表达不得、不允许、严禁或禁止实施某项行动 | 实际被阻断归“阻止”；前置条件或范围限制归“条件控制”；风险提示不等于禁止 | 法律：法律禁止在庭审过程中录音录像。<br>临床医学：服用该药期间禁止饮酒。<br>历史：停战协定禁止双方在缓冲区内调动部队。 |

### 6.3 家族级补充规则

1. “控制”不设为独立关系，因为它既可能表达条件限制，也可能表达许可、禁止或实际阻断；应根据原文明确表达落到“条件控制、允许、禁止或阻止”。
2. “授权”暂不在本家族展开。它在语义上把权力、资格或代表权交给主体，进入 F12 再审核，不能与一般行动许可合并。
3. 本表的三领域例子用于验证单一关系。真实原文可以同时支持多个关系，例如“经法院许可，当事人可以查阅案卷”可以同时产生“条件控制”和“允许”，不能用它单独检验“允许”。
4. “分离”不留在本家族。它描述两个对象、状态或信息域之间的边界和不流通关系，转入 F07“空间、边界与连通”。
5. “保护”不设为独立关系。原文明确表达降低风险、危害或暴露时归“减弱”；明确阻断具体行动或流动时归“阻止”；缩小适用、可见或可访问范围时归“条件控制”；建立不可见域时归“分离”。如果只表达设计目的而没有实际作用，则归“目的与用途”。

### 6.4 主 Agent 选择方式

- “哪些行为被允许？”选择“允许”；
- “哪些事情不能做？”选择“禁止”；
- “访问范围受到什么限制？”选择“条件控制”；
- “哪些措施能够保护隐私？”根据证据中的具体机制选择“减弱、阻止、条件控制或分离”，不选择“保护”。

## 7 F04 状态与过程

### 7.1 家族定义

一个对象、状态或过程被创建、改变、保存、恢复、重置、移除或终止；本家族关注生命周期和状态本身如何变化，不以追溯作用来源为中心。

本家族与相邻家族的边界如下：

- 明确强调某来源造成某种结果时，归 F01“因果与作用”；只表达目标自身从旧状态转为新状态时，归本家族。
- 某过程或对象只在特定条件或边界内成立，但并未改变生命周期状态时，归 F02“条件控制”。
- 某对象是否先于另一对象、持续多久或何时发生，归 F06“时间与顺序”；本家族只表达状态或过程发生了何种生命周期变化。

### 7.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 创建 | 某对象、状态、记录或结果从不存在变为存在 | 原文明确表达建立、生成、创建、形成或产生了一个此前不存在的新对象或新状态 | 仅表达可能产生某结果时归“使能”；只表达作用来源造成既有对象变化时归 F01“导致”；没有明确形成新对象时不能补写 | 法律：法院新设了环境资源审判庭。<br>临床医学：骨髓生成新的血细胞。<br>历史：朝廷建立了常平仓。 |

| 终止 | 正在进行的过程、活动或运行实例停止，并不再继续 | 原文明确表达过程、活动或运行实例结束、停止、终止或不再继续 | 暂时暂停且保留继续可能时不能自动归为终止；进程或对象被删除归“移除”；过程按计划正常完成时是否另设“完成”关系待覆盖检查 | 法律：法院裁定终止本次执行程序。<br>临床医学：医生终止了对患者的持续镇静。<br>历史：停战协定终止了持续多年的边境战争。 |

### 7.3 家族级补充规则

1. “转换”不单设独立关系，统一归入“改变”。具体从什么形式转到什么形式由自然语言命题保留，避免“改变”和“转换”形成两个高度重合的检索入口。
2. “创建”和“终止”保留为生命周期边界关系。缺少这两个入口时，“如何创建”“如何停止”只能退化为宽泛的动作检索。
3. “持久保存”强调跨阶段可读取，“维持”强调持续作用使对象保持当前状态；“恢复”强调回到先前状态或重新继续，“重置”强调回到初始、默认或空状态。
4. 本表例子同样只用于验证一个主关系。真实原文可以同时表达多个关系，例如“系统删除临时文件前，将检查点归档保存”可以同时涉及“移除”和“持久保存”。

### 7.4 主 Agent 选择方式

- “X 是如何创建或生成的？”选择“创建”；
- “什么操作会改变 X？”或“X 如何转换成 Y？”选择“改变”；
- “X 如何跨会话保存？”或“X 被记录在哪里？”选择“持久保存”；
- “中断后如何继续？”或“如何回到之前的状态？”选择“恢复”；
- “如何把 X 恢复到初始状态？”选择“重置”；
- “如何删除、撤销或废除 X？”选择“移除”；
- “如何停止 X？”或“X 在什么情况下结束？”选择“终止”。

## 8 F05 分类与结构

### 8.1 家族定义

一个对象被归入某个类别，或一个整体被表达为由若干部分、成员或子项构成。本家族关注概念之间的类别层级和结构组成，不关注对象在空间中的位置、内容如何流动或对象之间是否存在作用。

本家族与相邻家族的边界如下：

- 对象位于容器、区域或空间内部时，归 F07“空间、边界与连通”；不能仅因为原文使用“包含”就归本家族。
- 一段文本、上下文或集合在内容上涉及若干主题，但没有明确表达它们构成一个整体或类别时，不形成本家族关系。
- 某对象影响另一对象时归 F01“因果与作用”，即使两者在原文中被并列提及也不等于结构关系。

### 8.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 组成 | 一个整体、结构或明确集合由若干部分、成员或子项构成 | 原文明确表达整体与组成部分、结构与其构件，或明确集合与成员之间的构成关系；具体方向由自然语言命题保留 | 一般内容包含、主题并列或共同出现不算；空间容器所装对象归 F07“空间、边界与连通”；类别与实例或子类的层级归“分类” | 法律：该案合议庭由三名审判员组成。<br>临床医学：心脏由四个腔室组成。<br>历史：古代驿站系统由驿马、驿舍和驿吏组成。 |
| 分类 | 一个对象、实例、类型或实践被归入某个类别，或一个类别被明确划分为若干子类 | 原文明确表达“属于、是一种、归入、划分为”等类别归属或类型划分关系；具体方向由自然语言命题保留 | 整体与构件之间的组成关系归“组成”；仅主题相似、共同出现或功能相近不算；临时评价不是分类 | 法律：法律分为实体法和程序法。<br>临床医学：高血压属于慢性疾病。<br>历史：科举属于选官制度。 |

### 8.3 家族级补充规则

1. “包含”不设为独立关系。它的日常语义同时覆盖结构组成、内容涉及和空间容纳，作为检索入口歧义过大。只有明确形成整体与部分或集合与成员关系时使用“组成”；明确形成类别归属时使用“分类”。
2. “分类”同时覆盖类型归属和类型划分。原文中的方向由自然语言命题保留，不额外设计上下位角色或逆关系。
3. 列表、枚举和多项并列不自动形成“组成”。只有原文明确把它们视为一个整体、结构或集合时，才形成组成关系。
4. 本表例子只用于验证一个主关系。真实原文可以同时表达多个关系，例如“合议庭由法官和人民陪审员组成”可以同时支持“组成”，如果后文说明二者属于不同人员类别，还可以支持“分类”。

### 8.4 主 Agent 选择方式

- “X 由哪些部分组成？”、“X 包括哪些构成要素？”或“某个整体中有哪些成员？”选择“组成”；
- “X 是什么类型？”、“X 属于哪一类？”或“某个类别可以分成哪些子类？”选择“分类”；
- 用户只问“X 包含什么”时，需要结合完整问题判断是在问结构组成、类别范围、内容涉及还是空间容纳，不能仅凭“包含”选择本家族。

## 9 F06 时间与顺序

### 9.1 家族定义

两个事件或状态之间存在明确的先后、并发、持续或周期性关系。本家族只把能够形成稳定检索入口的时间结构作为关系；具体日期、普通时间范围、期限条件和“某事发生时的背景状态”仍由自然语言命题和原文证据承担。

本家族与相邻家族的边界如下：

- 某主体持续作用于对象并使其保持状态时，归 F01“维持”；只说明某状态或过程持续了多久时，归本家族的“持续”。
- 某行动以时间条件为前置时，归 F02“条件控制”，具体时间条件保留在命题中。
- 某过程开始、结束或中断的生命周期变化归 F04“状态与过程”；F06 只表达事件之间的相对时间结构，不重复表达生命周期变化本身。

### 9.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 先于 | 一个事件或状态在时间上早于另一个事件或状态；具体方向由自然语言命题保留 | 原文明确表达“先、后、之前、之后、早于、晚于”等相对先后关系 | 仅表达因果作用时归 F01“因果与作用”；两个事件同时发生归“同时”；普通日期和期限条件不单独抽为先于 | 法律：法院先立案，后开庭审理。<br>临床医学：患者先出现发热，随后出现皮疹。<br>历史：条约签署先于双方撤军。 |
| 同时 | 两个事件、过程或状态在同一时间点、同一时期或重叠区间内发生或存在 | 原文明确表达“同时、同期、与此同时、期间一直”等并发或时间区间重叠关系 | 先后发生归“先于”；只因发生在同一天但没有原文明确建立并发关系时不自动补写 | 法律：财产保全申请与诉讼请求变更在同一日提交。<br>临床医学：患者同时出现发热和呼吸困难。<br>历史：春耕与水利修缮在同一时期进行。 |
| 持续 | 一个事件、过程或状态跨越一段时间并保持存在或继续进行 | 原文明确表达持续了若干时间、贯穿某区间，或从某时延续到某时 | 主动维持某状态归 F01“维持”；有规律地重复发生归“周期性”；单纯记录一个时间点不算持续 | 法律：诉讼中止状态持续了六个月。<br>临床医学：患者发热持续三天。<br>历史：围城持续了八个月。 |
| 周期性 | 一个事件、行动或状态按明确的时间间隔重复发生或定期出现 | 原文明确表达每隔、每日、每周、每年、每次一轮等有规律的重复方式 | 无规律的多次发生不自动归为周期性；只规定允许频率上限归 F02“条件控制”；只持续一段时间但只发生一次归“持续” | 法律：行政机关每季度公布一次执法统计。<br>临床医学：患者每日测量两次血糖。<br>历史：官府每年征收一次田赋。 |

### 9.3 家族级补充规则

1. 普通日期、月份、年份、时点和“在……期间”等时间范围只有在构成明显的时间关系入口时才抽取；否则保留在所属事件、状态或规范关系的命题中。
2. “先于”不设置“后于”逆关系，也不设置额外角色。原文方向由自然语言命题保留。
3. “持续”只表达时间跨度，不表达谁主动使状态保持；“周期性”只表达有规律的重复，不表达频率是否受到规范限制。
4. 本表例子只用于验证一个主关系。真实原文可以同时表达多个关系，例如“系统每隔十分钟保存一次状态，并持续运行两小时”可以同时支持“周期性”和“持续”。

### 9.4 主 Agent 选择方式

- “哪个先发生？”、“X 发生在 Y 之前还是之后？”选择“先于”；
- “哪些事情同时发生？”、“X 和 Y 是否同期？”选择“同时”；
- “X 持续了多久？”或“X 贯穿哪个时间段？”选择“持续”；
- “X 多久发生一次？”或“X 是否定期重复？”选择“周期性”；
- 用户只问某个事件发生在哪一天或哪个时点时，不强制选择本家族关系，优先依据相关概念、事件和原文证据检索。

## 10 F07 空间、边界与连通

### 10.1 家族定义

对象、区域、系统或信息域之间存在明确的空间位置、连通或隔离关系。本家族处理物理空间以及与其结构同构的逻辑空间，例如独立工作区、隔离环境和不可互访的网络域；它不处理规范上的允许或禁止，也不把实际访问能力设成独立的第二层关系。

本家族与相邻家族的边界如下：

- 一个对象作为整体的组成部分时归 F05“组成”；只表达对象位于容器、区域或场所内部时归本家族的“位于”。
- 规则、主体或机制确认某行动可以实施时归 F03“允许”；某机制使主体能够通过路径完成访问时归 F01“使能”；只有路径、通道或接口本身存在时归本家族的“连通”。
- 某个具体行动或流动被实际阻断时归 F01“阻止”；原文建立两个区域之间不可共享、不可流通或不可见的边界时归本家族的“分离”。同一原文可以同时表达二者。

### 10.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 位于 | 一个对象、场所或过程处于某个空间区域、容器或位置之中 | 原文明确表达在、位于、存放于、处于某区域等空间位置关系 | 对象作为整体构件归“组成”；只在原文中共同出现但没有位置表达不算；规范权限不等于位置 | 法律：该案证物存放在第三审判庭的证物柜中。<br>临床医学：肿瘤位于患者左肺上叶。<br>历史：都城位于两条河流的交汇处。 |
| 连通 | 两个空间、对象或系统之间存在可通行、可传输或可交互的路径、通道或接口 | 原文明确表达由某通道、链接、接口或网络将两个区域或对象连接起来 | 仅表示空间相邻但没有通行路径不算；某机制使主体能够通过路径访问时另归 F01“使能”；规范许可归 F03“允许” | 法律：法院两座办公楼通过地下连廊连通。<br>临床医学：该分流通道连通动脉与静脉。<br>历史：大运河连通了南方产粮区与北方政治中心。 |
| 分离 | 两个对象、区域、状态或信息域之间存在原文明确的边界，并在某个维度上不共享、不可流通、不可见或不能相互进入 | 原文明确表达分隔、隔离、独立域、不可互访或边界隔离等关系 | 只限制某行动的权限、可见或可访问范围归 F02“条件控制”；实际阻断某一次具体行动或流动归 F01“阻止”；结构整体与部分归“组成” | 法律：法庭将证人与其他证人安排在独立等候室，彼此不能接触。<br>临床医学：隔离病房将传染病患者与其他患者分开，双方不共享空气循环。<br>历史：边墙把农耕区与游牧区分隔开。 |

### 10.3 家族级补充规则

1. “边界”不设为独立关系。边界本身通过其实际作用落到“分离”或“连通”；其名称和控制作用由自然语言命题保留。
2. “相邻”不设为独立关系。只有相邻进一步形成通道或隔离结构时，才抽为对应关系。
3. “连通”表达路径、通道或接口本身存在，不保证任何主体实际能够通过。实际访问能力由“连通”与 F01“使能”等关系共同表达；规范许可仍归 F03。
4. 沙箱、隔离病房、独立工作区等边界的主关系是“分离”。如果该边界之外还明确存在一条受控通道，则隔离本身抽为“分离”，通道本身可另抽为“连通”；只有原文还说明某机制使主体能够通过时，才再抽“使能”。
5. 本表例子只用于验证一个主关系。真实原文可以同时表达多个关系，例如“沙箱与主机隔离，但授权进程可通过单向接口提交结果”可以同时涉及“分离”“连通”“使能”和“允许”。

### 10.4 主 Agent 选择方式

- “X 在哪里？”或“某个区域中包含什么位置对象？”选择“位于”；
- “X 和 Y 之间有什么通道或接口？”或“哪些区域彼此连接？”选择“连通”；
- “X 和 Y 如何隔离？”、“哪些域彼此不可见？”或“控制边界划分了什么？”选择“分离”；
- “X 通过什么路径或接口到达 Y？”选择“连通”；如果原文另有机制使主体能够完成访问，再同时选择 F01“使能”；
- 用户问“是否允许进入或访问”时选择 F03“允许”；用户问“是什么阻断访问”时选择 F01“阻止”；用户问“边界如何隔离”时选择“分离”。

## 11 F08 目的与用途

### 11.1 家族定义

一个对象、机制、行动、规则或设计服务于明确的目标、功能或应用场景。本家族关注“为了什么”或“用来做什么”，不关注该目标是否已经实际实现。

本家族与相邻家族的边界如下：

- 原文只说明某项行动实际造成了某种结果时，归 F01“因果与作用”；明确表达设计目的、预期目标或用途时才归本家族。
- 某项条件让某个行动成为可能时，归 F01“使能”；某项机制被用来完成该行动时归本家族的“用于”。
- 某项规范确认某行动可以实施时归 F03“允许”；规范是否许可某个具体用途本身不改变“用于”所表达的预期用途。

### 11.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 用于 | 一个对象、机制、行动或设计被用来实现某目标、承担某功能或服务某场景 | 原文明确表达用于、用来、目的是、为了、服务于或承担某项功能 | 实际造成的效果归 F01“因果与作用”；仅表达实现方式归 F01“使能”或其他关系；仅相关或共同出现不算 | 法律：电子签章的设计目的是确认文书来源。<br>临床医学：抗生素用于治疗细菌感染。<br>历史：驿站用于传递公文。 |

### 11.3 家族级补充规则

1. 首版不把“目的”和“用途”拆成两个具体关系。二者都建立对象、机制或行动与预期目标／功能之间的联系；当前没有足够稳定的证据表明拆分后能形成不同且不重叠的检索入口。若后续跨领域语料反复出现稳定的“设计者意图”和“使用者实际用途”区别，再重新审核是否拆分。
2. “用于”表达预期目标或实际承担的用途，不证明该目标已经实现。例如“该机制用于防止数据泄露”即使后来发生泄露，仍表达“用于”；如果原文另说明实际发生了阻止或泄露，再按 F01 抽取对应实际作用。
3. “功能是”“作用是”“设计目的是”“用来”“服务于”等表达，只要形成对象或行动与目标／功能之间的关系，都归入“用于”，不另设“功能”关系。
4. 单纯表达“通过某种方法完成某事”属于方法或使能关系，不自动归为“用于”；只有原文把该方法作为实现目标的用途或功能时才抽取。
5. 本表例子只用于验证一个主关系。真实原文可以同时表达多个关系，例如“检查点用于恢复任务，并在任务失败后实际恢复了执行状态”可以同时支持“用于”和“恢复”。

### 11.4 主 Agent 选择方式

- “X 是用来做什么的？”、“X 的功能是什么？”或“X 服务于什么场景？”选择“用于”；
- “为什么设计 X？”或“X 的目的是什么？”选择“用于”；
- “X 实际造成了什么结果？”或“X 是否真的解决了问题？”选择 F01 中相应的因果关系，不单独选择“用于”；
- “X 通过什么方式实现 Y？”优先选择使能或方法相关关系；只有问题关注用途或功能时才选择“用于”。

## 12 F09 比较与替代

### 12.1 家族定义

两个或多个对象、方法、状态或方案被原文明确比较，或一个对象、方法、角色能够取代另一个。本家族关注相对关系和替代关系，不关注单独对象的程度变化、类别归属或实际因果效果。

本家族与相邻家族的边界如下：

- 某个作用来源实际提高或降低了目标属性时，归 F01“增强”或“减弱”；只有存在明确比较对象和比较结果时才归本家族的“比较”。
- 某对象属于某个类别时归 F05“分类”；“等同于”或“不同于”构成明确比较时归“比较”。
- 某对象被用于承担某个目标或功能时归 F08“用于”；一个对象能够取代另一个承担其角色时归本家族的“替代”。

### 12.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 比较 | 两个或多个对象、方法、状态或方案之间被原文明确建立相似、差异、优劣、大小、取舍或其他相对关系 | 原文明确表达相比、较、优于、劣于、不同于、等同于、更高等比较关系，并存在可识别的比较对象 | 没有比较对象的单独程度变化归 F01“增强”或“减弱”；只表达类别归属归“分类”；只表达替代而不比较属性时归“替代” | 法律：简易程序比普通程序的审理周期更短。<br>临床医学：药物 A 的降压效果优于药物 B。<br>历史：铁路运输比马车运输成本更低。 |
| 替代 | 一个对象、方法、角色或方案能够取代另一个承担相同或相近的作用，或已经实际取代另一个 | 原文明确表达替代、取代、替换、作为替代方案或使用另一对象代替某对象 | 仅比较优劣但未表达可取代或已经取代不算；单纯删除旧对象归 F04“移除”；实际替换还表达旧对象消失时可同时抽取“移除” | 法律：电子送达可以替代纸质送达。<br>临床医学：仿制药可以替代原研药。<br>历史：铁路逐渐替代了长途马车运输。 |

### 12.3 家族级补充规则

1. “比较”同时承载相似、不同、优于、劣于、更高、更低和取舍等结果，不拆成“相似”“不同”“优于”“劣于”等多个具体关系。具体方向、比较维度和结论由自然语言命题保留。
2. “比较”要求原文存在明确比较对象。单独说“性能提高了”不形成比较关系；如果是某来源作用于对象造成的提高，归 F01“增强”。
3. “替代”要求表达可替代性或实际替代。仅仅说两个方案有差异，不代表一个能替代另一个。
4. 同一原文可以同时支持多个关系。例如“方案 B 成本更低，并可替代方案 A”可以同时支持“比较”和“替代”。

### 12.4 主 Agent 选择方式

- “X 和 Y 有什么区别？”、“哪个更好？”、“两种方案如何取舍？”或“X 与 Y 是否相同？”选择“比较”；
- “有什么可以替代 X？”、“Y 能否取代 X？”或“X 的替代方案是什么？”选择“替代”；
- “使用 Y 代替 X 后效果更好”同时表达替代和比较时，可以同时选择两个关系；
- 用户问“某个来源是否让 X 更强或更弱”时，优先选择 F01“增强”或“减弱”，除非原文还明确以另一个对象为比较基准。

## 13 F10 来源与证据

### 13.1 家族定义

信息、主张、作品、记录或数据具有可识别的来源；某个判断、结论、行动或决定以另一信息、证据、规范或权威内容为依据。本家族关注内容从哪里来以及为什么能够被采信或据以行动，不关注物理因果来源，也不关注一般使用关系。

本家族与相邻家族的边界如下：

- 事件或结果由另一对象实际造成时归 F01“因果与作用”；本家族的“来源”只处理信息、内容、作品、记录和数据的出处或归属。
- 某行动以另一条件作为必须满足的前置时归 F02“条件控制”；某结论或决定以证据、规范或权威内容作为理由时归本家族的“依据”。
- 某对象被用来完成某功能时归 F08“用于”；该对象被明确用作证明、判断或决定的依据时归本家族的“依据”。

### 13.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 来源 | 信息、主张、作品、记录、数据或材料来自某个人、文件、机构、事件或存储出处 | 原文明确表达来自、出自、发布于、制定于、引用于、归属于某来源或由某主体提供 | 物理因果来源归 F01“因果与作用”；某内容被用来支持判断时另归“依据”；只有主题相关但没有出处表达不算 | 法律：该指导案例由最高人民法院发布。<br>临床医学：该临床指南由中华医学会制定。<br>历史：该史料出自清代地方志。 |
| 依据 | 某判断、结论、行动、决定或规则以另一信息、证据、规范或权威内容作为理由、证明或成立基础 | 原文明确表达依据、根据、基于、据以、支持、证明或用作判断基础 | 必要条件或前置条件归 F02“条件控制”；一般使用目的归 F08“用于”；实际因果作用归 F01“因果与作用”；只有来源关系但没有被用作依据时归“来源” | 法律：法院依据现场勘验笔录认定损害事实。<br>临床医学：诊断依据患者的病理检查结果。<br>历史：该结论依据出土竹简的纪年记录。 |

### 13.3 家族级补充规则

1. “来源”和“依据”不合并。来源回答“它从哪里来、由谁提供”；依据回答“为什么相信它、为什么据此作出判断或行动”。同一内容可以既有来源又被用作依据。
2. “引用、支持、证明、确认、据以”等表达不拆分独立关系。引用的主要语义通常是来源；被用作判断基础时归“依据”，证据强度、肯定程度和限制由自然语言命题保留。
3. 来源身份不等同于内容可信。原文只说明出自某主体时抽“来源”；只有明确表达该主体或内容被信任、被质疑或具有权威效力时，才抽取相应的信任或评价关系。
4. 仅主题相关、表达相同观点或共同出现，不构成来源或依据关系。
5. 本表例子只用于验证一个主关系。真实原文可以同时表达多个关系，例如“判决依据最高人民法院发布的指导案例”可以同时支持“依据”和“来源”。

### 13.4 主 Agent 选择方式

- “这条信息来自哪里？”、“谁提出的？”或“该文件由谁发布？”选择“来源”；
- “有什么证据？”、“凭什么得出结论？”、“这个判断依据什么？”或“哪些材料支持该主张？”选择“依据”；
- 用户问“为什么会发生”时选择 F01“因果与作用”，不选择“来源”或“依据”；
- 用户问“为什么可以使用某种材料”时，需要区分规范前置、一般用途和证据依据，再分别选择 F02、F08 或“依据”。

## 14 F11 表征与映射

### 14.1 家族定义

符号、术语、文字、图示或编码表达某种含义，或两个表示体系中的元素之间存在明确对应关系。本家族关注“用什么表示什么”以及“什么对应什么”，不关注经验证据、类别归属或一般相似比较。

本家族与相邻家族的边界如下：

- 症状、数据或线索表明某个事实时通常属于经验指示或证据支持，归 F10“依据”；约定符号、术语、图示或编码表达含义时才归“表示”。
- 一个对象属于某个类别，或一个示例属于某个概念时归 F05“分类”，不归“对应”。
- 两个对象仅被比较异同或优劣时归 F09“比较”；只有两个表示体系或编码体系中的元素存在结构化映射时，才归“对应”。

### 14.2 具体关系

| 具体关系 | 定义 | 原文判定依据 | 排除边界 | 三领域例子 |
| --- | --- | --- | --- | --- |
| 表示 | 一个术语、符号、文字、图示、声音或编码形式表达、指称或标识某个含义、对象或状态 | 原文明确表达“表示、代表、指称、名为、标记为”等符号与含义之间的表达关系 | 经验症状或线索支持判断归 F10“依据”；对象属于类别归“分类”；没有明确含义关系只算共同出现不算 | 法律：“甲方”表示合同的一方当事人。<br>临床医学：心电图中的 P 波表示心房除极。<br>历史：古代地图上的朱线表示驿道。 |
| 对应 | 两个表示、编码、字段、坐标或分类体系中的元素之间存在明确的结构化对应、转换或索引关系 | 原文明确表达对应、映射到、编码为、可与另一系统中的某元素相互转换或索引 | 一般异同比较归 F09“比较”；类别归属或示例关系归“分类”；只有相似而没有结构化对应不算 | 法律：该实施细则第三条对应上位法第十二条。<br>临床医学：ICD-10 编码 I10 对应原发性高血压。<br>历史：康熙二十年对应公历 1681 年。 |

### 14.3 家族级补充规则

1. “指称、命名、标记、编码”等表达不单独拆分关系。一个术语、符号或编码表达含义时归“表示”；两个体系中的元素存在结构化对应时归“对应”。
2. “表示”要求存在约定或明确的符号—含义关系。医学症状提示疾病、数据支持结论等经验指示归 F10“依据”，不能因为日常语言说“表明”就归入本家族。
3. “对应”要求存在可说明的一对一、一对多、多对一或转换关系。单纯说两个对象相似、相等或不同，归 F09“比较”。
4. 映射本身不等于实际执行转换。原文只说明两个表示体系如何对应时抽“对应”；另外说明某机制实际把 A 转换成 B 时，再按 F04“改变”抽取转换过程。
5. 本表例子只用于验证一个主关系。真实原文可以同时表达多个关系，例如“编码 I10 映射到‘原发性高血压’这一名称”可以同时支持“对应”和“表示”。

### 14.4 主 Agent 选择方式

- “X 这个符号、术语或编码是什么意思？”、“X 表示什么？”或“这个图示代表什么？”选择“表示”；
- “X 对应哪个编码、字段或名称？”、“两个系统之间如何映射？”或“A 在另一体系中对应什么？”选择“对应”；
- 用户问两个概念是否相同、相似或哪个更好时选择 F09“比较”；
- 用户问某症状、证据或数据为什么支持某个结论时选择 F10“依据”。

## 15 F12 主体与资源

### 15.1 家族定义

一个行为主体获得或拥有某种权能、资源或职责，或者资源、任务和职责在主体之间被分配、使用、消耗或转交。本家族关注主体—权责—资源的归属与流转，不处理一般目的、空间位置或规范上的行动许可。

本家族与相邻家族的边界如下：

- 规则或主体只确认某行动可以实施时归 F03“允许”；把特定权力、资格或代表权授予主体时归本家族的“授权”。
- 对象只位于某处时归 F07“位于”；主体当前拥有、持有或控制资源、凭证、信息、权利、资格或权限时归本家族的“拥有”。
- 某对象服务某个目标时归 F08“用于”；某主体或过程实际占用、使用或耗尽资源时归本家族的“消耗”。
- 授权、资源分配和委托是对权力、资源或任务的配置动作；拥有和负责是配置后可能形成但不由前三种动作自动推出的当前状态。

### 15.3 家族级补充规则

1. “授权”和“允许”不合并。允许确认某项行动可以实施；授权额外赋予主体某种权力、资格、身份或代表权。一个授权行为可能同时允许接受者实施相关行动，但只有原文明确表达行动许可时才另外抽取“允许”。
2. “拥有”和“位于”不合并。拥有、持有或控制强调主体对资产的当前归属或支配状态，位于某处只表达空间位置。
3. “授权”是授予权力、资格或代表权的动作，“拥有”是主体当前具有相关资产、权利或资格的状态。授权、资源分配或委托都不自动推出拥有，只有原文明确表达当前持有状态时才抽取“拥有”。
4. “资源分配”只处理资源、配额、权益或机会的分配；具体任务或决策交给另一执行者归“委托”。如“分配案件”实际是在安排具体任务的执行者，应归“委托”；如“分配预算”才是“资源分配”。
5. 授予读取权限、操作资格或代表权归“授权”，不能因为原文使用“分配权限”就机械归入“资源分配”；判断依据是接收方获得了能力或资格，还是获得了有限资源份额。
6. “消耗”处理主体或过程对资源的实际占用、使用或耗尽；资源服务于什么目标由 F08“用于”表达。
7. “委托”处理任务或执行职责的转交，“负责”处理持续承担责任的状态。接受委托不自动意味着承担最终责任，责任仍可由委托人承担，必须依据原文判断。
8. 本表例子只用于验证一个主关系。真实原文可以同时表达多个关系，例如“医院授权专科医生负责会诊，并为其分配独立会诊额度”可以同时支持“授权”“负责”和“资源分配”。

### 15.4 主 Agent 选择方式

- “谁被授予了什么权力或资格？”选择“授权”；
- “谁拥有、持有或控制 X？”选择“拥有”；
- “资源、配额或权益如何分配？”选择“资源分配”；
- “什么过程消耗或占用了哪些资源？”选择“消耗”；
- “任务或决策被交给了谁？”选择“委托”；
- “谁负责某任务或领域？”选择“负责”；
- 用户只问“是否允许做 X”时选择 F03“允许”；用户问“被授予什么资格或代表权”时才选择“授权”。
- 原文使用“分配案件”等表达时，如果实际是安排具体任务由谁执行，应选择“委托”；只有分配有限资源或份额时才选择“资源分配”。

## 17 当前 AI Agent 语料人肉走查

### 17.1 走查样本与方法

首个样本为 Anthropic 的《How we contain Claude across products》：

- 文档标识：`doc_fd4dec9976e041308e2b39ed797c75d1`
- 快照：`s51_7f7e71a6b581c451`
- 原文块：`b00001` 至 `b00026`，共 26 块

选择该文是因为它在同一篇中覆盖条件控制、允许与禁止、因果作用、分类组成、空间隔离、目的用途、比较、来源证据和主体资源，能够同时检验多个关系家族。

走查采用“整篇通读、按连续块组判断、证据回到原文块”的方式：

1. 先通读完整章节，避免孤立块切断论证上下文；
2. 对每一条候选关系定位当前块内的最小原文片段；
3. 相邻块只用于理解语义，不把后文事实借给前文形成证据；
4. 如果一个宏观命题需要多个独立块补写才能成立，记为证据碎片化，不直接视为单块已经明确表达的关系；
5. 同一具体关系可以在多个原文块中出现，形成多条关系实例或多块证据，不因此增加关系类型。

### 17.2 覆盖结果

按调整后的 38 个具体关系重新归纳，现有关系仍能够覆盖该文的主要功能语义。代表性结果如下：

- `分类／组成`覆盖风险类别、防御对象、VM 构件、文件挂载模式和运行环境表格；
- `允许／禁止／条件控制`覆盖逐轮批准、工作区读写边界、网络默认禁止、文件挂载和代理策略；
- `导致／使能／阻止／增强／减弱`覆盖安全措施、攻击成功率、隔离副作用、事故链、自建组件故障和部署取舍；
- `条件控制`覆盖用户确认前置、管理员能力、用户监督能力、工具运行条件和防御多层协同；
- `位于／连通／分离`覆盖本地与服务端运行位置、代码执行环境、宿主与客户机、租户之间和上下文可见性；
- `先于／持续／周期性`覆盖信任确认与配置执行顺序、跨会话保留和每次启动重新加载；
- `比较／替代`覆盖本地与远程工具、Claude Code 与 Cowork 架构、事后日志与实时监控、分层防御与替代关系；
- `来源／依据`覆盖文章署名、攻击指令到达渠道、项目配置来源和日志不能作为事后异常依据；
- `授权／拥有／消耗／委托／负责`覆盖按会话缩小范围的令牌、凭证控制、管理员决策转交和工具能力授予。

走查没有发现必须通过“跨块关系”才能表达的核心命题。多个块共同支撑同一宏观结论的情况，按多证据关系处理，不改变具体关系目录。

### 17.3 候选缺口

#### 17.3.1 信任

`trusted／untrusted／trust boundary／trust escalation` 在 `b00010`、`b00019` 和 `b00021` 中反复出现。它们至少表达三类现有关系不能单独覆盖的语义：

- 来源、内容、执行者或环境当前被视为可信或不可信；
- 安装时建立的信任可能因远程对象后续改变行为而失效；
- 多 Agent 系统可能因为来源身份而赋予更高信任，形成信任升级风险。

现有关系边界如下：

- `来源`只说明内容从哪里来；
- `依据`说明判断或审核以什么材料为基础；
- `允许`说明某项行动是否获得许可；
- `信任`才直接表达“是否接受该来源、内容或执行者”。

当前暂不新增，先记为强候选。最终是否加入，以真实抽取回放和下列查询探针能否稳定映射为准：

1. `哪些外部资源应该被视为不可信？`
2. `为什么安装时可信的远程工具后来可能不可信？`
3. `信任边界建立前哪些内容不能执行？`

F10 的补充规则目前写有“明确表达被信任、被质疑时，才抽取相应的信任或评价关系”，但 F10 尚无对应具体关系。若最终决定不新增“信任”，必须同步修正该悬空引用。

#### 17.3.2 失败

组件失败或防御漏过在 `b00007`、`b00016`、`b00023` 和 `b00025` 中反复出现：

- 自建代理在事故中失效；
- 久经考验的标准原语可靠，而自建组件失败；
- 概率性模型防御漏过异常，由确定性边界接手；
- 分类器放过一部分冒进行为。

当前可以暂用 `改变`表达对象进入故障状态，并把“失败、漏过、未被阻止”保留在命题中，但 `改变`不能直接形成“哪个组件失败”“什么防御漏了什么”这类查询入口。该关系暂不新增，等待真实抽取回放确认是否反复只能勉强映射到 `改变`。

### 17.4 暂不新增的关系

- `输入／输出／传输`：`feed/load/pass/upload`等流转语义先由自然语言命题承载，并结合`来源／允许／连通／阻止`检索；不由“输入与来源互为逆关系”直接新增第二层关系。
- `观察／审计／检查／扫描`：优先分别落到`减弱／使能／先于／依据`。例如隔离降低可见性归`减弱`，OTLP 导出使日志可取归`使能`，进入上下文前检查归`先于`，日志不能提供事后信号归否定形式的`依据`。
- `具有属性／具备能力`：属性或能力描述暂由概念义项、原文证据和其他功能关系承载，不为一般属性判断新增关系。

### 17.5 下一步验证

先验证当前 38 个具体关系，用固定快照、固定模型和固定提示词对 D04 做一次真实抽取回放。重点验证：

1. `feed content into the agent's context from sources you don't control`能否正常形成`来源`关系；
2. trust 相关句子是否被错误归入`允许`或整条漏抽；
3. failure 相关句子是否只能勉强归入`改变`；
4. 审计、检查和扫描是否被合理拆为`减弱／使能／先于／依据`；
5. 安全控制中的`允许／授权／条件控制／阻止／分离`是否有稳定且可解释的边界。

真实抽取结果用于决定是否新增“信任”和“失败”；在得到该证据前，不继续扩展或细分当前 38 个具体关系。

## 18 关系模式使用方法：实验结论

- 状态：以下为 2026-11-16 调整前的 40 关系历史实验证据；当前 38 关系候选的组织方式仍待验证。
- 证据来源：[D04 直接关系实验](experiments/2026-11-13-stage51-direct-relations.md#极简提示词在-b00021-上验证分离)
- 当前日期：2026-11-15

### 18.1 已观察事实

在固定的目标正例块上，只输入一个关系模式的极简提示词已经表现出显著优于原两阶段候选加
结构化抽取的目标召回和稳定性，而且不只存在于一个关系上：

- `constrain`：在 `b00021` 上，原两阶段流程对子 Agent 目标的命中为 0/10，对凭证目标的
  命中为 2/10；极简提示词对两个目标均为 10/10。`b00019` 的两个明确目标也均为 10/10。
- `separate`：完整 40 模式流程没有为显式的
  `sub-agents can isolate untrusted content` 发布 `separate` 关系；极简提示词下该关系达到
  10/10，同一块中的凭证边界也达到 10/10，且每轮返回的句子集合完全一致。

同一凭证句既能表达宿主凭据与 VM 之间的边界，也能表达会话令牌的权限范围缩小，说明一条原文
可以同时支持多个具体关系。关系抽取不能再按“为整句选择一个主要关系”的方式设计。

### 18.2 已确认与待验证的边界

已经确认：

1. 单关系输入时，极简的证据句判断在目标证据召回和稳定性上优于两阶段候选加结构化抽取；
2. 该优势至少在 `constrain` 和 `separate` 上复现；
3. 同一原文可以支持多个关系，不能采用单选主关系的方式。

仍需验证的是 40 个关系如何组织，主要包括：

1. **关系竞争假设**：同时暴露 40 个相近关系，会使模型在边界、阻止、约束、分离等模式之间
   摇摆，降低召回和稳定性；
2. **协议负担假设**：候选、命题、参与者和多字段结构校验使模型先完成复杂输出，再间接完成
   关系语义判断，增加漏抽和格式偏差。

### 18.3 对后续方法的约束

当前采用以下方向组织实验，但暂不改写最终架构：

1. 关系判断按多标签处理，不要求每条原文只有一个主要关系；
2. 将“原文是否表达某关系”的语义检测与“概念义项、参与者、命题和原文跨度”的结构化抽取
   分成两个独立阶段，只对检测命中的证据执行第二阶段；
3. 单模式独立判定暂作为召回基线；任何把多个模式合批的优化都必须用同一固定样本证明不会
   降低召回和稳定性；
4. D04 的 16 个金标准块已全部获得直接关系命中，但当前 block 级 precision 未通过；下一步
   必须增加显式负例和近邻负例，不能继续只以提高命中数为目标。

### 18.4 全 D04 检验后的适用边界

[全 D04 单关系极简覆盖回放](experiments/2026-11-13-stage51-direct-relations.md#全-d04-单关系极简覆盖回放)
对 26 个 block 分别运行 `constrain` 和 `separate`：16 个金标准块全部获得直接关系命中，但
`constrain` 在 26/26 个 block 上返回证据，`separate` 在 24/26 个 block 上返回证据。

因此，单关系极简提示词已经解决的是“在可能相关的原文块中找到目标关系表达”，尚未解决“该关系
表达是否属于用户所问的 Agent 控制边界”。它不能直接作为 c13-003 的 block 级关系过滤器：

- `constrain` 会把分类、普通语法限定、文档范围和订阅频率都识别为约束；
- `separate` 会把文档主题范围和非本文讨论内容也识别为信息域边界；
- 16/16 金标准覆盖是在检测器几乎不拒绝任何 block 的情况下取得的，不能单独证明检索通过。

当前的准确表述是：**单关系极简提示词在正例识别和目标证据召回上优于原两阶段流程，但作为通用
block 关系过滤器仍存在严重的 precision 不足。**

## 19 条件控制候选的路由验证

### 19.1 实验设置

2026-11-16 使用调整后的 38 个具体关系做一次临时路由验证：

- 模型：`deepseek-flash`；
- `temperature=0`，thinking disabled；
- 用户问题：`AI Agent中有哪些隔离与控制边界`；
- 主 Agent 获得完整二级关系名称清单，不获得关系定义、正例或反例；
- 模型按 must／should／possible 三级排序，连续运行 10 次。

调整前的 40 关系对照中，`约束`为 10/10 被选中，`要求`和`依赖`均为 0/10。调整后：

| --- | ---: | ---: | --- |
| 分离 | 10/10 | 1.00 | must 10/10 |
| 阻止 | 10/10 | 2.00 | must 10/10 |
| 允许 | 10/10 | 3.00 | must 10/10 |

`条件控制`被选中时的理由是“边界在何种条件下生效”“边界在特定条件下生效的访问控制逻辑”“边界控制通常依赖条件判断来生效”等。

### 19.2 当前结论与边界

本轮说明合并后的名称没有丢失条件类入口：在没有关系定义辅助的情况下，`条件控制`仍被 10/10 选择，并多数进入 must。它同时覆盖原问题会路由到`约束`的语义，而不再依赖主 Agent 看到独立的`要求`或`依赖`标签。

该结果只验证查询层路由。它不能证明条件控制关系卡在原文块上的召回和 precision，也不能替代 D04、D14 金标准回放。当前 F02、F03 仍保持“待验证”状态。下面的“原要求、依赖、约束”只是旧三关系方案的回归分组，不是新关系的子类型；下一步应使用统一关系卡分别验证：

1. 原`要求`证据能否由`条件控制`召回；
2. 原`依赖`证据能否由`条件控制`召回；
3. 原`约束`证据能否保持既有召回；
4. 检查、验证、防护和一般建议等负例是否会因合并而增加误报。

### 19.3 D04 条件控制首轮回放中的人工边界确认

2026-11-16 使用整篇 D04、统一“条件控制”关系卡和 26 个 block 做了一次真实回放。模型返回
19 个命中 block、27 条候选，并对未命中 block 返回了 5 条最接近候选。本轮只验证协议和边界，
不作为稳定性结论。

人工审查确认 `b00025` 不是条件控制：原文说明自动审批模式只是沙箱内部的一层纵深防御，
不能替代沙箱。它表达的是组成、角色和非替代关系；“不能替代”不蕴含“某项行动或状态只有在另一
条件成立时才能发生”，因此不能因为 `not a substitute` 带有否定或限制意味就归入条件控制。

该结论强化了当前定义的操作边界：判断条件控制时，必须能指出一个目标及其成立或继续所依赖的
必要支撑或范围边界，不能从防御层次、职责、组成或替代关系反推必要条件。完整运行产物见
`backend/.runtime/condition_control_d04_v7_20261116/result.json`。
