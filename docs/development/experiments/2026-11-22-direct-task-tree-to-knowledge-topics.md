## 1. 问题

两阶段路径先从任务树生成 KnowledgeNeed，再从知识需求生成知识主题。该路径能显式表达任务覆盖和生成责任，但可能把人类可以直接完成的一次判断拆成两次模型调用。

本实验验证另一条路径：

```text
完整根任务树
  → 一次调用直接生成知识主题森林
  → 独立检查结构、任务引用和未解决任务
```

知识需求不再作为输出对象或阶段间通信数据。任务只用于判断知识覆盖。

## 4. 主题产出

### 4.1 第 1 轮

根主题为“Agent 决策控制循环架构模式”，下含四个子主题：

- Agent 决策控制循环状态与转移模型；
- Agent 控制循环运行约束与状态所有权；
- Agent 控制循环场景走查与验证；
- Agent 控制循环实现契约与接口映射。

其中四个子主题各自同时支持根任务和一个对应子任务，形成稳定的共享知识节点。

### 4.2 第 2 轮

同样生成一个“Agent 决策控制循环架构”根主题和四个子主题，顶层结构类似，但方面更少：状态转移模型和实现接口分别只有两个方面。知识范围没有明显复制任务动作，但内容明显比第 1 轮薄。

### 4.3 第 3 轮

没有生成独立根主题，而是直接生成四个并列主题：

- Agent 决策控制循环的状态-转移模型；
- Agent 执行治理与运行时约束；
- Agent 执行场景类别与验证判据；
- Agent 控制循环实现接口契约。

状态模型、约束和接口主题边界清楚，场景验证主题还合并了正常与异常走查两个子任务。

## 5. 初步结论

1. **直连路径具备可行性。** 三轮均生成名词性知识主题，没有直接把任务动作复制成主题；6 个任务也都在结构上获得了主题支持。
2. **知识需求不是完成这次生成的必要外部中间件。** 模型能够在一次调用内完成任务需求判断和知识组织。
3. **共享知识可以自然形成。** 每轮都有 4 个多任务主题，说明不先输出 KnowledgeNeed 也能表达一个主题服务多个任务。
4. **直连路径成本显著下降。** 当前样本上，输入、输出和耗时都约为两阶段路径的 60%。
5. **输出形态仍不稳定。** 第 1、2 轮形成两级主题树，第 3 轮形成平铺森林；方面数在 11 至 20 之间波动。
6. **模型自报任务覆盖不可信。** 第 3 轮把根任务列入多个主题的 `source_task_keys`，但四个主题都没有清楚承载“控制循环整体架构模式与设计维度”这一知识范围。结构校验仍会显示 6/6 任务已支持。

## 6. 风险与下一步

当前结果只能说明“任务树直接生成主题”值得继续，不足以直接替换两阶段设计。

下一步应固定同一任务树和主题候选，增加独立任务覆盖审查：审查器只读取完整任务树和主题森林，逐项判断任务所需的领域知识是否真实覆盖、主题是否只是任务动作的换名，以及多个主题共同支持一个任务时是否存在不可见缺口。

如果独立审查能识别第 3 轮这类根任务覆盖缺口，并证明直连输出在多次运行中仍可修复，再考虑把正式设计从两阶段生成改为单次主题生成加独立覆盖审查。
