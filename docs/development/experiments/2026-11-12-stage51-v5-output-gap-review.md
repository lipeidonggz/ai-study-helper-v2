## 逐项证据

### O1 · 关键综合入口被错误拒绝或长期悬置

最新地图缺少以下三个关键入口：

| 候选词面 | 原文块 | 最新判断 | 模型理由 |
| --- | --- | --- | --- |
| `environment layer` | `b00006` | 术语为噪声，义项不确定 | “句子片段或临时描述短语” |
| `model layer` | `b00004`、`b00005`、`b00023` | 三处均为术语不确定 | “可能为稳定领域短语，但上下文不足” |
| `egress` | `b00002`、`b00004`、`b00011`、`b00015`、`b00023` | 一处噪声、四处不确定 | 多处认为可能为安全术语，但没有一处确认 |

这不是候选扫描漏词：上述词面均真实存在于候选组。`b00006` 是全文概述段，原文直接写明
“Focusing on the environment layer, we describe three isolation patterns……”；`b00004` 明确
以环境层和模型层并列描述防御；`b00023` 又把“先在环境层设计遏制，再在模型层引导行为”总结为
首要原则。模型仍在这些充分上下文中拒绝了核心短语，属于术语资格判断错误。

最新地图中有 5 个原文块没有进入任何概念义项支持集合：

- `b00006`：环境层、三类隔离模式，属于正文核心概述；
- `b00009`：经验用户监督、多智能体系统，属于监督能力边界；
- `b00020`：工具调用经过代理检查返回值，属于代理边界；
- `b00024`：作者和致谢名单，不属于知识正文；
- `b00026`：订阅推广文案，不属于知识正文。

因此至少 `b00006` 和 `b00009` 是知识内容覆盖缺口。`b00020` 中的 `proxy` 和检查机制已在其他块
形成概念，但本块没有成为支持证据，是否构成缺口需结合 O6 讨论。

#### O1 当前根因分析

已观测事实：

1. 当前系统提示词要求 `accepted` 只表示完整词面是“稳定、可复用的检索锚点”，并要求多词候选
   只有“固定名称、标识符或有术语意义的固定名词短语”才能接受；逐字可组合的普通描述判为
   `noise`。同时，`uncertain` 可用于“词面形态可能成为稳定锚点，但当前上下文不足以决定术语
   资格”，而 `mention_only` 只允许稳定名称或专名，见
   [`induction.py`](../../../backend/app/dual_entry_index/induction.py:48)。
2. `environment layer` 被归入“句子片段或临时描述短语”；`model layer` 在三个块中都被认为
   “可能稳定，但上下文不足”；`egress` 在一次运行中被归为普通名词，在其余四处被认为可能是
   安全术语但未获确认。
3. `b00006` 的 37 个候选里，模型只接受了 `Claude`、`claude.ai`、`Claude Code` 三个专名；
   `environment`、`layer`、`isolation`、`patterns` 等正文概念词全部被判为普通名词性噪声。
   `b00023` 的 177 个候选中同样没有接受任何术语，环境层、模型层、`containment`、`isolation`
   和 `egress` 都在噪声或不确定状态。
4. 相同提示词和输入的另一份地图中，`model layer` 至少有一个块被接受，`egress` 至少有三个块
   被接受；本次运行则全部未获接受。这说明判断边界并不稳定，模型在不同运行中对同类名词短语
   给出了不同置信水平。
5. 结构上相近的其他短语又可以被接受，例如 `permission prompts`、`workspace folder`、
   `network access`、`hard limit` 和 `attack surface`。因此模型不是单纯拒绝所有“修饰词＋名词”
   或多名词短语，而是在按自身对“是否像已有固定术语”的先验判断逐项浮动。

根因假设：

1. **提示词把“组合式技术名词”当成普通描述的概率过高。** 当前规则主要告诉模型什么样不是术语，
   对“原文把它作为分类、边界或组织原则使用”的多词名词短语缺少可执行的接受条件。因此
   `environment layer` 和 `model layer` 被按字面组合解释成普通描述，而不是文章中的稳定分类。
2. **术语资格与义项可解析性仍然耦合。** 系统提示词虽然声明两者分开，但 `uncertain` 规则仍以
   “上下文不足以决定术语资格”为条件，`mention_only` 又被限制在专名。结果是 `egress` 这类没有
   形式定义、但作为安全机制稳定出现的技术名词只能反复进入 `uncertain`，无法保留为仅提及入口。
3. **没有跨块提升机制。** 每个原文块独立决定是否接受术语，`model layer` 在 3 个块、
   `egress` 在 5 个块中反复出现，但没有一个块确认后，它们不会因为跨块重复和角色一致性得到
   第二次判断机会。
4. **紧凑输出可能强化保守偏置。** 噪声可以按理由合并且一次携带多个局部序号，接受项则需要
   填写义项、标签和摘要字段。提示词又连续强调“不要因为常见或看起来重要而接受”，可能使模型
   对处于边界的名词短语优先选择更省输出且更保守的 `noise` 或 `uncertain`。这一点是协议层面的
   待验证假设，现有产物不能单独证明。

可以确定的结论是：O1 的主要原因不在候选发现，也不在模型缺少领域知识本身，而在当前“什么
才算稳定术语”的语义契约过于依赖模型对固定术语的先验，并把“当前原文有没有解释清楚含义”
混入了术语资格。具体修复方式仍需在人工确认根因后决定。

### O2 · 相同契约下术语结果漂移

两次运行使用完全相同的快照、候选、模型和提示词版本，但结果差异很大：

| 指标 | 第一次 `km51_930...` | 第二次 `km51_b90a...` |
| --- | ---: | ---: |
| 术语 | 242 | 193 |
| 概念义项 | 163 | 107 |
| 仅第一次出现的术语 | 78 | - |
| 仅第二次出现的术语 | - | 29 |
| 两次交集 | 164 | 164 |
| Jaccard 相似度 | 0.605 | 0.605 |

第一次出现而第二次缺失的词面包括 `model layer`、`egress`、`persistent memory`、`trust boundary`、
`model training`、`devcontainer` 等；第二次新增的词面有一部分是 `perspective`、`posture`、
`probes`、`process`、`desktop`、`local` 等泛词。这说明当前不是简单地“第二次更严格”，而是
接受边界在不同语义类别之间移动。

同一词面在单个块内的状态也不稳定。例如 `human-in-the-loop` 仍因其他块被接受而存在，但
`b00012` 在第二次运行被判为术语不确定。当前产物只能证明“至少一处接受”，不能证明该术语在
各块的角色判断稳定。

### O3 · 术语层混入页尾人名和局部泛词

193 个术语中有 87 个没有义项关联。按设计，仅提及术语合法，因此“无关联”本身不是错误；但本
次分布暴露了两个需要讨论的问题：

1. 87 个无关联术语中有 53 个只来自 `b00024` 作者与致谢名单，占全部术语的 27.5%。既接受完整
   姓名，也接受姓氏或名字片段，例如 `Abel Ribbink`、`Ribbink`、`Jake Eaton`、`Eaton`。
2. 其他无关联术语仍包含 `Files API using`、`Remote`、`Sealed`、`local`、`servers`、
   `perspective` 等片段或泛词。另有 `process`、`security`、`response`、`probes` 等泛词获得了
   概念义项。

最新地图中也存在大量部分词面与完整短语同时成为术语的现象，例如：

- `Claude Code` 与 `Code`；
- `Claude Cowork` 与 `Cowork`；
- `Claude Desktop` 与 `Desktop`；
- `Remote MCP servers` 与 `Remote`；
- `Sealed VM` 与 `Sealed`。

并非所有部分词面都应删除；例如独立出现的 `MCP`、`Claude` 可能确实是有效入口。问题在于当前
判断没有稳定区分“原文独立使用的稳定锚点”和“只是从更长固定名称中切出的组成部分”。

### O4 · 术语与概念边界碎片化

最新结果的 107 条术语—概念义项关联全部是一对一：每个义项只有一个术语，没有形成任何
“一义多词”；只有 `code` 形成一个词面两个义项。没有任何明示同指候选。这不直接证明设计错误，
但说明“术语和概念义项是多对多关系”的收益在当前产物中完全没有体现。

具体碎片化例子：

- `remote` 和 `remote mcp servers` 分别形成两个义项，但摘要逐字相同；
- `classifiers` 和 `probes` 分别形成两个义项，但摘要都只是“用于约束或塑造模型行为的机制之一”；
- `code` 的其中一个义项被写成 Claude Code 产品，而 `Claude Code` 本身已有产品义项；
- `model` 被写成“模型层”，但真正的候选 `model layer` 又全部未通过术语判断；
- `agent`／`agents`、`allowlist`／`allowlists`、`defense`／`defenses`、`MCP`／`MCPs` 等词形均
  分别保留。

这些例子兼有术语边界错误和概念归并缺口。需要分别决定：哪些应在术语资格阶段排除，哪些应在
同一原文块的明确指代阶段处理，哪些应允许查询时提出同义假设。

### O5 · 部分摘要不能稳定区分概念

最新摘要没有超过 180 字的问题，长度本身可控；不足在语义边界：

- `Claude Cowork` 的摘要同时写了产品定义、密封虚拟机、六种隔离机制、启动开销和挂载工作区，
  更像一段局部答案，而不是用于识别概念的摘要。
- `Claude` 的摘要列出产品家族及文件访问、代码执行和安全隔离，混入多个相邻概念。
- `isolation` 的摘要只描述 Cowork 虚拟机中的隔离机制，无法代表全文中的一般隔离语义。
- `classifiers` 与 `probes` 的摘要完全相同，另一个判断者无法仅凭摘要判断二者区别。
- `remote` 与 `remote mcp servers` 的摘要完全相同，但词面粒度明显不同。

这会同时影响后续概念归并和功能关系抽取：摘要若不能回答“这个概念是什么、与相邻概念如何区分”，
模型只能继续依赖原文块或自身先验。

### O6 · 关键概念的证据覆盖偏窄

107 个概念义项中：

- 90 个只有 1 个支持块；
- 8 个有 2 个支持块；
- 5 个有 3 个支持块；
- 2 个有 4 个支持块；
- 2 个有 5 个支持块。

术语支持与义项支持按设计本来就可以不同，但当前差距很大：

| 术语 | 术语支持块 | 义项支持块 |
| --- | ---: | ---: |
| `Claude Code` | 8 | 3 |
| `Claude Cowork` | 6 | 2 |
| `code` | 3 | 1 |

原因通常是其他块被判为仅提及或不确定。它们能证明该词面出现，却不能成为概念证据，也不能
成为功能关系锚点。后续 5.2 抽取“谁在什么地方约束了什么”时，可能因此丢失关键上下文。

### O7 · 单篇成本仍然很高

最新单篇运行的处理量：

- 26 个原文块产生 2,958 个候选组，其中 2,699 个交给模型判断；
- 术语判断阶段单独使用 71 次成功请求和 175,012 输入 token；
- 全部阶段共 103 次成功请求、113 次实际尝试；
- 输入 218,814 token、输出 28,786 token，墙钟 38.96 秒；
- 模型判断候选组到已确定义项候选组的比例约为 19.4∶1。

如果仅按相似文档粗略线性外推，1,000 篇文档约为 2.19 亿输入 token 和 10.8 小时。这不是容量
结论，只说明当前结果密度很低，后续扩大验证前必须讨论成本结构。现阶段不应先通过放宽或收紧
固定候选数量来调质量。

### O8 · 失败原因不可诊断

最新运行有 10 次失败尝试和 9 次重试，但产物只保留总数。现有诊断不能回答：

- 是 JSON 格式错误、局部编号遗漏、未知对象引用还是输出截断；
- 是否集中在某个原文块或某类候选；
- 重试后结果是否与首次结果发生语义变化；
- 供应商超时、网络错误与模型协议错误各占多少。

这不直接改变地图内容，但限制了稳定性根因判断，也会影响后续成本优化。

## 对先前根因假设的修正

此前曾提出“连续内容词只保留完整最长片段，导致 `environment layer` 等中间短语无法成为候选”。
最新扫描证明该判断至少不适用于本用例：`environment layer`、`model layer` 和 `egress` 都是
独立候选，失败发生在模型术语资格判断，而不是候选发现。

中间短语问题仍可能存在，例如 `b00006` 有长片段
`describe three isolation patterns`，也有 `isolation` 和 `patterns`，但没有独立的
`isolation patterns`。因此它仍值得后续讨论，但不能作为本次三个关键入口缺失的主要解释。

## 建议讨论顺序

1. O1：术语资格如何判断完整综合短语，并避免被“普通名词／句子片段”规则误杀；
2. O2：同一契约下如何获得稳定语义，而不是继续堆叠一次提示词；
3. O3：正文、作者名单和推广页脚是否应在候选扫描前按块角色区分；
4. O4：部分词面、单复数和明确同指分别由哪一层处理；
5. O5：概念摘要应表达什么、排除什么；
6. O6：术语支持与概念支持的差异是否应保留，如何避免丢失证据方面；
7. O7：在不使用固定数量调质量的前提下降低请求数和 token；
8. O8：补充哪些失败诊断，才能支持稳定性和成本根因分析。
