# 5.1 概念索引紧凑协议性能实验

- 日期：2026-11-12
- 切片：090
- 目标：验证 5.1 概念义项归纳在保持候选覆盖、身份校验和证据回源的前提下，能否降低模型输出、重复调用和端到端耗时。
- 输入：`How we contain Claude across products`
- 文档标识：`doc_fd4dec9976e041308e2b39ed797c75d1`
- 快照：`s_6b787258ba7d700c`
- 模型：`deepseek-flash`
- 配置：并发 8，单次输入上限 100,000 字符，输出上限 8,000 token，最多重试 2 次，单次候选局部序号上限保持 48。

## 变更

本次只优化 5.1 独立编译链，不改变候选扫描范围、48 条单批上限或原文证据规则：

1. 模型输出改用紧凑 JSON；噪声按原因分组。
2. 模型只引用请求内局部整数序号，完整候选身份由宿主映射。
3. 移除模型请求和响应协议中的缩进。
4. 同指核对前使用显式同指标记或成对括号做确定性预筛。
5. 归并结果直接携带最终摘要，不再逐临时分组额外刷新摘要。
6. 同一归并轮内，独立词面分量并发；归并轮之间串行。
7. 诊断记录阶段墙钟、成功请求、实际尝试、失败、重试以及缓存命中／未命中 token。

运行期间另补了两项协议防护：已有义项标识必须属于当前候选词面；模型重试后仍漏局部序号时，二分失败批次继续覆盖全部候选，并保留失败响应 token。

## 结论

- 性能目标成立：端到端约快 5.3 倍，输出 token 降低约四分之三。
- 当前瓶颈仍是术语与义项判断，占总墙钟约 80.1%、总输入 token 约 77.8%、总输出 token 约 92.2%。
- 23 次失败尝试全部通过结构重试收敛；其中术语判断 20 次、同指 3 次。后续若要继续降本，应优先分析术语批次的漏项和请求形状，而不是调整候选、义项或证据数量上限。
- 速度与成本结论只对本次固定文档、固定快照、固定模型和 8 并发配置成立，不能直接外推到 15 篇或 1,000 篇。
- 质量等价尚未成立。优化版保留了更多术语，但概念义项、关联和已确定义项出现明显减少，且明示同指从 3 条变为 0 条。旧产物还生成于更严格的同指门禁之前，因此只能做运行特征对照，不能把差异全部归因于本次 7 项优化。下一步应先人工抽查“仅提及”数量激增和同指归零，再决定是否继续调提示词或协议。
- 高精度词法过滤带来约 10% 的请求下降和 13%～15% 的 token 下降，但小批固定样本仍不足以证明跨文档稳定性；需要至少在未参与规则调整的中文、英文、混合语言和技术标识符文档上回放。
