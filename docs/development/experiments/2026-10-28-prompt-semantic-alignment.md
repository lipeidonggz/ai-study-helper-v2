# 2026-10-28 提示词语义对齐：来源元门禁迭代记录

- 状态：实验归档；不构成 043 或产品目标合理性结论
- 模型：DeepSeek Flash，`temperature=0`，thinking disabled
- 固定目标：在预先冻结的 span 金标准上达到每项 N=10、K=9
- 正式产物：本轮 043 将按新方法重做，产品实现不沿用本次中间改动

## 目的

本轮实验只研究一个问题：固定任务、类别、输入和验收目标后，怎样通过可观测的模型判定依据定位提示词语义偏差，并逐步让分类结果达到稳定标准。

本实验不讨论来源元门禁是否值得保留，也不讨论分类目标是否正确。这些属于目标定义层，不属于提示词执行对齐层。

## 固定实验现场

| 项目 | 配置 |
| --- | --- |
| 输入 | question、冻结 answer、结构过滤后的 spans |
| 输出 | 每个 span 的 `source_meta`、`category`、`reason` |
| 重复次数 | 每个答案 10 次 |
| 稳定目标 | 对冻结金标准至少 9/10 正确 |
| 回放要求 | 与产品提示词组装、结果解析和一次重试语义一致 |

## 关键迭代

### 1. 只有分类结果，无法解释偏差

早期提示词只返回 `source_meta` 和固定 reason 枚举。实验能看到“哪一条错了”，但不能判断模型把输入理解成了什么，调优只能依赖结果猜测。

### 2. 加入 reason，暴露概念混淆

候选提示词要求同时返回：

```json
{
  "span_id": "span_0001",
  "source_meta": true,
  "category": "answer_provenance",
  "reason": "以“文档称”说明该判断的来源与可信度。"
}
```

模型给出的典型 reason 暴露了两类偏差：

- 把“文档称某事实”理解成“回答依据和可信度”；
- 把对来源内容的多步综合理解成“answer 整体的组织方式”。

这两条 reason 把问题从“约束不够强”定位为“类别命题对象与模型学习到的含义不一致”。

### 3. 定向修复不等于全量通过

根据 reason 调整 `answer_provenance` 的主语和命题对象后，三个定向误判曾达到 10/10。但全量回归立即显示错误转移：

- c6 的 K=9 从 285/301 降至 270/301；
- 18-case 的 K=9 降至 478/528；
- 长答案出现协议错误。

因此，定向样本通过不能作为提示词收敛依据。

### 4. 产品等价回放

进一步检查发现，实验回放与产品语义有两个差异：

- 模型在 `source_meta=false` 时经常省略空 `category`，实验解析器起初把它当协议错误；
- 实验脚本起初没有模拟产品的一次重试。

修正回放语义后，候选结果变为：

| 数据集 | 调用数 | 最终协议错误 | 10/10 一致 | K=9 稳定 |
| --- | ---: | ---: | ---: | ---: |
| c6 | 100 | 0 | 293/301 | 295/301 |
| 18-case | 180 | 0 | 519/528 | 524/528 |

该结果只说明该候选在固定目标下基本接近稳定要求，不等同于产品验收。已知反例和剩余波动仍需按 043 的正式流程重新验证。

## 方法结论

1. 调优前冻结目标、类别、金标准、输出协议和 N/K。
2. 让模型输出简短且结构化的判定依据，而不是不可验证的隐藏思维链。
3. 按 reason 聚类模型的理解偏差，不从单个错误直接猜原因。
4. 每轮只验证一个主要语义假设，并保留版本差异。
5. 定向探针通过后必须跑全量回归；定向修复不能抵消回归退化。
6. 回放必须与产品解析、重试和提示词组装语义一致。
7. 稳定性只描述重复一致性；正确性始终由冻结金标准决定。
