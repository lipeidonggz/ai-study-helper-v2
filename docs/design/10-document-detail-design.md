# 10 · 文档详情页设计

- 日期：2026-10-21
- 状态：已审核 · 首版实现基线
- 关联：[01 产品需求](01-product-requirements.md)、[07 HTML 入库与 collection](07-html-ingestion-design.md)

## 1. 目标

详情页回答四个问题：

1. 这篇文档是什么、来自哪里？
2. 当前知识库实际使用的是哪个版本？
3. 用户可以检索到哪些章节和正文？
4. 这个版本由哪次入库产生，技术上是否完整？

详情页首先是阅读页，不是数据库调试页。普通用户默认只看到标题、来源、正文和状态；内部 ID、hash 和索引参数放到“技术信息”次级页签。

## 2. 数据事实源

| 区域 | 唯一事实源 | 不允许使用 |
| --- | --- | --- |
| 当前正文、章节、block | 当前 active snapshot 中该文档的 `document.json` artifact | 文档登记库中的最新版本、job workspace 中未发布内容 |
| 版本时间线 | `documents`／`document_versions` | 从正文 hash 临时猜测版本 |
| 相关操作 | 持久化入库任务表 | 当前页面内存中的任务状态 |
| 快照身份 | `ActiveCollectionPointer` 与 manifest | “最新目录”或文件修改时间 |

回滚后，详情页必须显示回滚后快照中的活动版本，不能继续显示回滚前的正文。

## 3. 信息架构

```text
知识库文章清单
    └─ 点击文章
        └─ 文档详情
            ├─ 内容
            ├─ 版本与记录
            └─ 技术信息
```

详情页属于“知识库”工作区，不新增顶层导航。URL 使用 `#knowledge/{doc_id}`，支持刷新、后退和直接定位。

## 4. 页面结构

### 4.1 顶部摘要

- 标题；
- 来源显示名；
- 语言；
- 当前活动版本；
- 当前可检索状态；
- 章节数、block 数和发布时间；
- 返回知识库；
- 复制来源地址或本地路径。

### 4.2 内容页签

桌面端为左侧章节树、右侧正文的双栏阅读布局。章节树点击后滚动到对应章节；窄窗口改为单列。正文必须来自 active snapshot，不能在前端重新拼接或修正。

### 4.3 版本与记录页签

- 按版本倒序显示历史版本；
- 明确标记当前活动版本；
- 显示每个版本的创建时间与 extractor 版本；
- 显示与该文档来源或 job 相关的最近入库任务。

历史版本只用于追溯，不能在“内容”页签中与当前版本混排。

### 4.4 技术信息页签

- `doc_id`；
- 来源 URI、内容 hash；
- snapshot ID；
- extractor、section builder、chunker 版本；
- embedding model 与维度；
- extraction hash。

技术字段默认不占首屏。

## 5. API 边界

```text
GET /api/collections/current/documents/{doc_id}
```

响应同时包含：

- active snapshot 中的正文与章节；
- 全部已登记版本及 active 标记；
- 相关入库任务；
- 技术版本信息。

文档不在 active snapshot 时返回 `collection_document_not_found`，不能回退到登记库中查找旧版本并伪装成当前文档。

## 6. 首版不包含

- 删除单篇文档；
- 编辑标题、别名或合并来源；
- 切换、恢复单个历史版本；
- 在详情页直接修改知识库；
- 打开外部浏览器或操作系统文件管理器。
