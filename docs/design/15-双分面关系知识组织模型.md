## 1 文档目的

本文提出“双分面关系知识组织模型”：以“知识对象—关系”为事实层，同时从知识对象域和关系语义
两个方向组织知识，并用两者共同限定找全类问题的检索范围。

模型包含两组相互正交的分类轴。知识对象域轴必然领域相关，并按知识组织目的把知识对象及其证据
划入领域，回答“在哪里找”；关系分面轴从多个相对领域无关的观察视角对知识对象之间的关系进行分类，回答
“找什么关系”。原文中的自然语言命题和证据继续回答“具体关系是什么”，不要求把完整语义压缩为
固定三元组或严格本体。

在这套组织方式下，找全问题不再依赖单一主题或一段相似文本，而被转化为一个可检查的范围问题：
确定资料范围和知识对象域范围，识别查询锚点，通过带求值作用域的布尔表达式选择关系观察轴及二级
关系标签，再验证所选范围内关系实例是否完整召回、原始证据是否充分。知识对象域负责缩小候选知识
对象和原文块的范围，关系分面负责给出横切于知识对象域的关系枚举维度。

本文既描述最终候选模型，也明确当前阶段的验证边界。当前阶段只验证关系分面能否为 AI Agent 全域
中的找全问题提供稳定范围；知识对象域分类、组织树和域筛选暂不进入实现与验收。具体关系观察轴目录、
关系实例存储和检索接口仍在后续讨论中。

## 2 背景

此前的知识组织主要依赖概念、主题和分组：

- 概念或术语入口用于回答“某个对象是什么、在哪里出现”；
- 主题和分组入口用于把同一文档内或跨文档的相关内容组织到一起；
- 功能关系入口用于回答对象之间通过什么方式相互关联。

实践表明，仅依赖概念或主题入口难以稳定覆盖横切多个主题的问题。问题真正要求的往往不是某个主题，
而是满足某类关系模式的所有对象关系。例如“隔离”关心的不是包含“隔离”字样的主题，而是系统中
哪些对象之间被建立边界、哪些流动被排除。

因此，关系不只是用于解释概念或主题的附加信息，而应成为知识组织和检索的一等入口。一个关系实例
至少要保留：

- 参与关系的对象或概念义项；
- 原文表达的关系命题；
- 支持该关系的原文证据；
- 在相关观察轴下得到的关系分类。

功能关系只承担检索边的职责，不要求把完整语义压缩成严格三元组。条件、否定、模态、程度、时间、
例外和评价等由自然语言命题及原文证据保留。

### 2.1 与主题、社区式检索的边界

这一判断也解释了主题索引、LLM Wiki 和 GraphRAG 等组织方式为何不能直接提供关系找全保障。
GraphRAG 会抽取实体和关系，但其全局检索主要通过社区及其摘要进行聚合。社区可以视为从图连接
紧密度中产生的知识对象域候选，却没有把关系整理为面向查询分解和覆盖检查的显式分类目录。社区报告
又是有损摘要，因此跨社区的关系细节、条件、例外和局部证据可能在聚合中丢失。GraphRAG 仍可能
通过局部检索或其他路径找到部分跨社区细节，但它无法据此保证某个关系视角下的证据已经找全。

LLM Wiki 或仅依赖主题、分组和文本相似度的组织方式缺少独立的关系实例与关系分类，限制更明显。
它们可能召回包含相关内容的页面或块，却无法说明应当从哪些关系类别逐一枚举，也无法判断某个
关系维度是否仍有缺失。

因此，两者的共同问题不是绝对不能生成相关答案，而是缺少关系视角下的覆盖契约：

- community 和主题入口主要回答“知识属于哪一片区域”；
- 关系分类回答“在这一区域中应当枚举哪些关系”；
- 只有区域导航而没有显式关系分类时，系统不能证明关系找全问题的覆盖完整性。

双分面模型保留知识对象域轴以缩小候选区域，同时把关系实例和关系分面作为独立的一等组织对象，使系统
能够把找全问题转化为可执行、可检查的关系枚举与证据覆盖问题。

## 3 已有探索及其问题

前期曾尝试先定义 12 个一级家族，再为每个家族定义二级具体关系，并将“要求／依赖／约束”合并为
“条件控制”。这些工作证明了关系入口对找全问题有价值，同时也暴露了两个结构问题：

1. 一级“家族”之间的语义地位不清楚。部分一级看起来是观察角度，部分更像相关关系的主题集合；
2. 同一一级下的二级关系是否必须互斥、是否覆盖完整，没有形成可验证的统一约束。

后续讨论形成的更明确判断是：知识库最终由关系分面和知识对象域分类两组正交体系组织。关系分面的一级
定义关系观察轴，二级是该轴下可用于检索的关系语义标签。原来的 12 个一级因此不能直接视为已经成立；它们
只是候选，需要先判断每个候选是在划分关系语义，还是在划分知识对象所属知识域，再按相应规则重新审计。

关系目录不能直接根据某个具体金标准反推。金标准可以在关系视角冻结后验证找全效果，但不能成为
设计观察轴和二级关系标签的来源，否则会把单个问题或单一领域的答案方面误当成通用分类结构。

## 4 核心模型

最终候选模型以“知识对象—关系”为事实层，并增加两组对象不同、用途不同的分类轴：

```text
事实层
  知识对象
    实体
    事件、动作或状态
    概念或命题
    已实体化的关系
  关系实例
  自然语言命题
  原文证据

分类层
  知识对象域轴
    把知识对象和证据划入按知识组织目的定义的知识域

  关系分面
    按相对稳定的观察轴划分知识对象之间的关系语义
```

知识对象域轴与关系分面正交。知识域回答“在哪里找”，关系分面回答“找什么关系”，自然语言命题和原文
证据回答“具体关系是什么”。本阶段只实现并验证后者，前者保留为后续组织能力。

### 4.1 对象关系

关系是知识对象之间的关系。知识对象不限于普通实体，还包括事件、动作、状态、概念、命题以及已经
实体化的关系实例。关系实例描述这些知识对象之间由原文明确表达的作用、条件、许可、结构、位置、
时间、来源或其他联系。

因此，条件关系可以把一个目标动作或状态作为端点。例如“只有经过人工批准，Agent 才能访问外部
网络”可以先形成目标情形 `R1：Agent 访问外部网络`，再形成条件关系 `R2：R1 以人工批准为
必要条件`。这里的目标端点是关系对象 `R1`，不是普通实体。

第一阶段以二元关系作为检索边即可。原文中存在更复杂结构时，完整语义由自然语言命题和证据承担，
不要求把所有关系强制改写为固定的三元或多元模板。

### 4.2 关系观察轴：一级

关系分面的一级定义“从什么角度观察对象关系”。关系观察轴回答一个稳定的问题框架，例如：

- 一个知识对象为什么、以何种方式影响另一个知识对象；
- 一个目标要成立需要满足什么必要条件；
- 一个行动被允许还是禁止；
- 知识对象之间是什么结构或类别关系；
- 信息来自哪里、又被用作什么依据。

不同关系观察轴之间没有必然的继承、优先级或固定映射关系。一个知识库可以只启用与其目标相关的轴，
不要求所有知识库都实现同一套完整本体。与知识对象域轴不同，关系观察轴应尽量使用领域无关的
语义定义。

### 4.3 关系分面标签：二级

二级是某个观察轴下赋予关系实例的语义标签。一个可用的轴必须同时满足：

1. 该轴有明确、单一的观察角度；
2. 在该轴明确声明的适用范围内，所有二级标签的并集能够覆盖全部适用关系实例；
3. 每个标签能够由原文证据直接判断，不依赖大量领域常识补写；
4. 同一关系实例可以在同一轴内获得多个二级标签，但每个额外标签都必须有独立原文依据和可区分的检索价值；
5. 完全重合且不能形成独立检索入口的标签应合并；对应不同观察角度的语义应拆成不同轴。

这里的“覆盖”不是指覆盖世界上所有可能的关系，而是覆盖该知识库声明关注、并由原文明确表达的
该轴关系实例。轴不适用或原文没有表达的内容不进入该轴适用范围。二级标签不要求互斥；允许重叠
可以保留同一关系实例在不同语义方向上的检索入口，但不能仅靠增加标签掩饰定义不清。

如果两个标签实际上对应不同观察角度，应拆成不同轴，而不是强行放在同一轴下。如果某个轴无法形成
稳定覆盖，应优先收窄该轴的范围、合并冗余标签或重新定义，而不是持续添加优先规则和个案例外。

### 4.4 关系实例与分面标签

关系实例的身份与关系分面标签必须分开：

```text
关系实例
  参与角色
    知识对象值
  自然语言命题
  原文证据
  分面标签集合

分面标签
  关系观察轴
  轴内二级关系标签集合
```

同一条关系实例可以同时具有多个观察轴上的分类。例如：

> 只有经过人工批准，Agent 才能访问外部网络。

它可以同时得到：

```text
必要条件轴：条件控制
规范许可轴：允许
```

这不是重复抽取两条关系，而是同一条关系在两个关系观察轴上的不同分类。同一关系实例在单个轴内
也可以拥有多个二级标签；这些标签附着在同一个关系实例和同一份原文证据上，不复制事实。

### 4.5 知识对象域轴

知识对象域轴必然领域相关，并按知识组织目的把知识对象及承载其知识的证据划入知识域。它先缩小
候选知识对象范围，再由关系分面在这些候选知识对象所参与的关系中筛选具体关系。知识对象域轴
不存在领域无关的通用划分；例如面向 AI Agent 开发人员的知识库，可以先按生命周期划分：

```text
AI Agent
  概念理解
  设计与开发
    主循环
    记忆管理
    工具调用
    ……
  发布
  运维
    安全
    可观察性
    故障恢复
    ……
```

组织树的一个节点可以在本层选择不同的主导切分视角，分别生成下级知识域。例如根节点使用生命周期
视角，而“设计与开发”节点使用组成视角。知识对象域分类可以来自人工目录、文档与章节结构、
知识对象之间的关系或社区聚类候选；GraphRAG 的 community 可视为基于关系紧密度生成知识对象域
候选的一种实现方式，但 community 本身不等于已经按知识组织目的确定的知识对象域。

知识域节点与被归入该域的知识对象也不是同一层概念。例如“记忆管理”不是某个具体实体，而是一个
能力、职能或主题域；归入该域的知识对象可以包括记忆存储实体、记忆写入动作、检索过程、保留策略
以及这些对象之间的关系。知识域节点首先承担分类标签作用；当“记忆管理”本身作为原文对象参与
关系时，可以再把它实体化为一个概念或能力对象，但它不会因此变成普通实体。

知识对象域允许跨域关联。一个关系实例可以同时关联“AI Agent/构建/记忆管理”和
“AI Agent/安全/权限控制”等域，以便从任一相关域检索到同一原始证据。

### 4.6 当前阶段的范围约束

当前阶段要验证的问题是：关系观察轴和轴内二级关系标签，能否为基于关系分类的找全问题提供可靠范围。
因此暂不实现知识对象域分类、组织树和知识对象域筛选。

当前实验将整个知识库固定视为一个完整的 AI Agent 域：

- 不把“概念理解、设计与开发、发布、运维”等知识对象域分类作为数据字段；
- 不根据用户问题选择知识对象域子树；
- 不要求知识对象或关系实例携带知识域标签；
- 所有关系筛选都在当前知识库的 AI Agent 全域中进行。

这意味着当前阶段的找全验收只检验关系分面的分类、抽取和证据覆盖。知识对象域轴能否进一步缩小范围、
解决同一关系类别下的歧义，属于下一阶段问题，不能成为本阶段实现或通过条件。

## 5 概念对象

本阶段不直接确定数据库表，但需要先稳定以下概念边界。

### 5.1 关系观察轴定义

一个关系观察轴至少应说明：

- 轴标识和名称；
- 该轴回答的核心问题；
- 该轴适用的关系实例范围；
- 不适用于该轴的情况；
- 轴内二级关系标签集合，以及这些标签如何以并集覆盖适用范围；
- 同轴多标签、独立检索价值和标签边界规则。

### 5.2 轴内关系类别

一个二级关系标签至少应说明：

- 稳定、领域无关的语义定义；
- 原文中的判定依据；
- 与同轴其他标签的语义边界和允许重叠的条件；
- 它对轴覆盖的贡献，以及是否存在独立检索价值；
- 设计目标为覆盖多个差异明显领域的实例；当前阶段先以 AI Agent 域内的差异实例进行验证，
  跨领域泛化留作后续验收；
- 用户可能如何使用该标签发起检索。

### 5.3 关系实例

一个关系实例至少应能追溯到原文中的一个明确表达，并保留参与角色、参与角色上的知识对象值、关系
命题和证据位置。关系实例是否合并、如何消歧以及同一关系在不同块中的重复处理，属于后续数据模型
和增量编译问题。

## 6 检索模型

### 6.1 最终候选模型的查询计划

最终候选模型中的查询由资料范围、知识对象域范围、查询锚点和关系分面共同确定：

```text
查询
  资料范围
    当前知识库或快照
    可选：指定文档或来源

  知识对象域范围
    按知识组织目的选择的组织路径或子树

  查询锚点
    被知识对象域范围约束的目标知识对象或参与角色

  关系分面表达式
    AND(
      OR(A.A1, A.A2),
      B.B1
    )
  求值作用域：关系实例 / block / 文档
```

资料范围是硬边界：不在该范围内的证据不得因为语义相关而进入结果。知识对象域范围是语义范围，通常
约束查询锚点，而不是要求关系两端都属于同一域。例如查询“AI Agent 构建中的隔离”时，Agent 是
目标锚点，环境或宿主可以位于 AI Agent 域外；只要关系表达的是目标锚点受到的隔离，仍应命中。

关系分面使用表达式树组合多个关系观察轴及其二级标签。`OR` 表示任一子表达式满足即可；`AND` 表示
在同一个求值作用域内必须同时满足所有子树。默认的“找全”候选召回可以在同一轴的备选标签之间使用
`OR`，用户明确要求同时具备多个语义时才使用 `AND`。每个 `AND` 都必须声明它是在关系实例、block
还是文档范围内求交。最终返回的是经过资料范围、知识对象域范围、锚点和关系分面表达式共同约束的
关系实例及原始证据。

### 6.2 当前阶段的查询计划

当前阶段固定整个 AI Agent 域，不执行知识对象域分类、查询锚点分解或域范围筛选，因此实际查询计划
只包含资料范围和关系分面：

1. 将资料范围固定为当前活动知识库快照，整个知识库视为 AI Agent 全域；
2. 选择一个或多个关系观察轴，为每个轴选择二级关系标签，并用 `AND`／`OR` 组成表达式；
3. 按声明的关系实例、block 或文档作用域计算表达式，合并、去重并返回原始证据。

当前阶段的查询计划可以表示为：

```text
查询
  资料范围：当前活动知识库快照
  知识对象域：AI Agent 全域（固定，不参与筛选）
  关系分面表达式
    AND(
      OR(A.A1, A.A2),
      B.B1
    )
  求值作用域：关系实例 / block / 文档
```

同一关系实例命中多个表达式分支时，只应返回一份关系及证据，同时保留其多个分面标签。表达式命中
不等同于证据覆盖完成；还必须逐一检查所选轴和标签是否已有结果或能够明确为空。

这种方式不要求把问题先映射为单一主题或单一关系。关系观察轴彼此独立，通过多轴组合覆盖问题涉及
的不同语义方面；“找全”则转化为关系分面表达式是否正确、所选轴和标签是否覆盖目标语义、对应关系
实例是否全部召回、证据是否充分的联合问题。

## 7 当前已形成的结论

目前可以确认以下结构原则：

1. 知识组织的单位是知识对象之间的关系实例，而不是单纯主题或概念节点。
2. 最终模型包含关系分面和知识对象域分类两组正交体系；前者相对领域无关，后者必然领域相关。
3. 关系分面的一级定义关系观察轴，不是父子本体中的大类。
4. 不同关系观察轴之间没有必然关系；知识库按关注范围选择启用哪些轴。
5. 关系分面的二级是某一关系观察轴下赋予关系实例的语义标签；同轴标签允许重叠，其并集必须覆盖该轴适用范围。
6. 关系实例与关系分面标签分离；同一关系实例可以具有多个关系观察轴标签，也可以在同一轴内具有多个二级标签。
7. 完整语义由自然语言命题和原文证据保留，不追求严格知识图谱式模板化。
8. 关系观察轴和二级关系标签不能从单个金标准反推，金标准用于轴线冻结后的检索覆盖验证。
9. 当前阶段不启用知识对象域分类和筛选，整个知识库固定视为 AI Agent 全域。

现有 12 个一级家族和 38 个具体关系不再直接视为已冻结分类。它们可以作为候选输入，但必须先判断
每个候选属于关系分面还是知识对象域分类，再按对应规则重新审计。当前至少已经发现：

- “分类与结构”可能同时包含部分—整体和类型—实例两个轴；
- “来源与证据”可能同时包含来源和判断依据两个轴；
- “主体与资源”更像多个主体关系主题的集合，而非单一观察轴；
- “状态与过程”是否已经穷尽生命周期类别仍需检查。

## 8 下一个待决问题：形成哪些关系观察轴

当前第一个需要讨论的问题不是“最终保留多少个二级关系”，而是：

> 为了支持 AI Agent 全域中的关系找全检索，应当形成哪些彼此独立、可划分且可稳定抽取的关系
> 观察轴？

建议按以下步骤确定：

1. 从当前 AI Agent 语料中提出候选关系观察轴，领域无关性和跨领域泛化暂不作为本阶段通过条件；
2. 检查每个候选是否只回答一个稳定问题，而不是多个主题的集合；
3. 为每个候选轴声明适用范围和不适用边界；
4. 检查同轴候选标签的并集是否覆盖适用实例，保留有独立检索价值的重叠标签，并合并完全重合项；
5. 检查原文是否足以稳定判断该轴及其二级标签；
6. 检查用户问题是否能够自然映射到该轴；
7. 冻结首版关系轴目录后，再分别设计各轴的二级标签、覆盖缺口和抽取验证。

在这项工作完成前，不应急于实现 38 个关系标签的全局抽取，也不应把现有 12 个一级直接迁移为数据
模型的固定枚举。

## 9 暂不决定的事项

以下问题留待观察轴目录稳定后处理：

- 每个知识库如何配置启用的观察轴；
- 知识对象域轴如何按知识组织目的形成组织树、如何选择各层切分视角，以及是否参考社区聚类候选；
- 知识对象域范围、查询锚点和关系分面如何组合成完整查询计划；
- 主 Agent 是否直接看到观察轴，还是只看到二级标签及允许的布尔表达式结构；
- 关系实例的身份、去重和增量更新方式；
- 同一关系在多轴上的分类是否使用独立模型调用；
- 关系检索与现有概念、主题、block 检索如何融合和排序；
- 观察轴目录的版本、迁移和兼容策略；
- 关系找全质量的固定样本、金标准和长期回归方式。
