- 日期：2026-11-17

- 当前范围：AI Agent 全域；暂不实现知识对象域分类和筛选

## 1 文档定位

### 1.1 本文要解决的问题

15 号设计已经确定知识库由“知识对象域轴”和“关系分面轴”两组正交体系组织，但尚未确定关系分面的一级观察轴，也没有说明哪些轴值得继续细化二级关系。本文专门解决以下问题：

1. 什么才算一个关系观察轴，什么不是；
2. 首版应当保留哪些关系观察轴；
3. 各轴分别考察关系中的哪一个语义维度，适用和不适用于什么；
4. 首批深化哪些轴，以及如何设计这些轴下的二级关系；
5. 如何验证轴、二级关系、抽取和找全检索确实有效。

本文不以“再定义一套 40 类关系”为目标。轴是关系检索的观察角度；二级关系是某个角度下可独立选择和验证、也可以在同一关系实例上重叠的语义标签。两者混在一起，会重新产生旧一级家族的边界问题。

### 1.2 本文的产出

- 首版关系观察轴候选目录；
- 轴的定义、适用全集和排除边界；
- 轴内二级关系的设计规则和首批深化计划；
- 轴线盲审、二级关系抽取和找全检索的验证协议；
- 最新验证结果、被否决方案和待确认决策。

### 1.3 文档状态与更新规则

本文当前是候选设计。轴线、二级关系和模型结论必须经过本文第 8 节定义的验证后才能分别标记为“候选”“已验证”或“已否决”。

文档只保留最新有效设计，不并列维护“初稿、修订稿、最终稿”。旧版本由 Git 历史保存；大体积模型输出、原始 trace 和一次性分析脚本仍保存在被忽略的运行目录或实验记录中，不直接复制进本文。

## 2 设计依据与推理

### 2.1 旧一级关系家族暴露的问题

前期按照 12 个一级家族和若干二级关系开展抽取，证明了关系入口能够帮助回答横切主题的问题，也暴露了结构问题：

1. 部分一级是观察角度，例如“因果关系是什么”；部分一级只是相关主题的集合，例如“主体与资源”。
2. 部分一级把不同问题压在一起。例如“分类与结构”同时包含整体—部分和实例—类型；“来源与证据”同时包含来源追踪和判断依据。
3. 一级之间缺少统一关系，容易把“目标动作的约束”“规范上的允许”“对象域的隔离”混成一条谓词推导链。
4. 二级关系是否必须互斥、在哪个全集内穷尽，没有统一约束。
5. 单次输入大量关系类型时，模型会把关系名称、原文动词和领域主题混在一起，出现多判和漏判。
6. 从单个问题或金标准反推关系类别，会把答案方面误写成通用分类结构。

因此，本次不能只在旧 12 类上改名，而要先重新确定“轴”的定义和判断标准，再从语料及已有语义框架产生候选。

### 2.2 新基础模型带来的变化

本设计采用以下已经形成的基础判断：

- 知识对象不限于普通实体，还包括事件、动作、状态、概念、命题和已经实体化的关系实例；
- 关系实例与分面标签分离，事实语义由自然语言命题和原文证据保留；
- 知识对象域轴必然领域相关，回答“去哪里找”；
- 关系分面轴尽量领域无关，回答“找什么样的关系”；
- 同一关系实例可以在多个关系轴上拥有标签，也可以在同一轴内拥有多个二级关系标签；
- 同一轴内的二级关系标签允许重叠，但所有标签的并集必须覆盖该轴声明适用范围内的全部关系实例。

### 2.3 关系观察轴的定义

关系观察轴是一个**在声明适用范围内保持同一含义、可由原文证据判断，并且只考察对象关系的一个语义维度的问题**。它不是一个领域主题，也不是对一个对象的综合评价。

例如：

- “某行动在规则下是允许、禁止还是要求？”只考察规范状态，可以作为关系观察轴；
- “两个对象或信息域之间是否被隔开、连通或可达？”只考察边界与连通性，可以作为关系观察轴；
- “某对象的安全性如何？”不是关系观察轴。它可能同时依赖因果影响、成立条件、边界控制、来源和证据，属于领域关注点或综合判断。

“稳定”不是指同一输入在多次运行中必须得到完全相同的结果，也不是指一个轴只能有一个答案，而是指该问题在跨领域、换用不同自然语言问法时仍保持同一语义维度；轴内可以存在多个答案，也可以在同一关系实例上并存多个二级关系标签。

一个轴在定义阶段需要说明四项：

- 轴标识和中文名称；
- 唯一语义维度，用一个规范问句表达；
- 最小关系形态，即至少涉及哪些知识对象和参与角色，才能构成该维度的关系；
- 判定边界，即什么原文证据算进入该轴、什么不算，以及如何与相邻维度区分。

完整参与角色集合、轴内二级关系标签及其覆盖与可区分边界、查询表达式和检索用法，属于后续深化与验证内容，
不在轴的定义阶段一次性确定。

以“边界与连通”为例：

```text
名称：边界与连通
唯一语义维度：两个对象、信息域或行动范围之间是隔开、连通还是可达？
最小关系形态：至少存在边界两侧的对象或范围，并表达它们之间是否穿越、连接、隔开、
              包含在域内或可达。
判定边界：原文必须明确表达边界或连通关系；仅出现“安全”“控制”等主题词不算，
          仅表达整体—部分也不进入本轴。
```

轴不是知识图谱中的大类，也不是父子本体中的中间节点。不同轴之间不建立固定继承、优先级或映射关系；某个知识库根据自身目的启用需要的轴。

### 2.4 关系观察轴的设计与验证

本节把候选来源、轴定义、验证优先级、双验证和冻结放在同一条生命周期中。候选轴的语义来源与具体
问题的验证优先级是两个不同问题，不能互相替代。

#### 2.4.1 候选来源与候选集边界

首版关系观察轴首先从“知识对象之间可能存在哪些通用关系语义维度”出发，形成一组尽量领域无关的
观察视角候选。候选轴不由当前文档中的高频谓词、单个知识库的问题或答案分布决定。

以下材料用于提出和审查候选，但任何单一来源都不能直接成为最终轴目录：

1. 当前 AI Agent 语料中的真实关系实例，用于检查候选维度是否存在可观察证据；
2. ConceptNet 等有限通用关系集合；
3. UCCA、FrameNet 等语义角色和场景结构；
4. PROV-O、ODRL、SKOS 等专门关系模型。

旧 12 个一级家族和旧二级关系不再作为候选轴的设计输入。它们只在候选轴形成后用于检查是否无意中
继承了旧结构问题，不参与决定新轴应当有哪些。

ConceptNet 的关系表说明有限关系集合可以服务实际应用，但它同时混合了组成、分类、因果、前置条件、
位置、用途、来源和符号关系，不能直接照搬。[ConceptNet Relations](https://github.com/commonsense/conceptnet5/wiki/Relations)

UCCA 把句子组织为场景、参与者、修饰关系及场景间连接，并允许场景作为其他场景的参与者；FrameNet
也把关系意义放在具体框架角色中。这些工作支持把动作、事件、状态和关系实例作为知识对象，也支持
把条件、时间、目的等作为关系或修饰语义保留，而不是全部压缩成实体谓词。[UCCA](https://aclanthology.org/P13-1023/)、[FrameNet](https://framenet.icsi.berkeley.edu/)

PROV-O 区分实体、活动和主体，并显式表达生成、派生、使用与归属；ODRL 将许可、禁止、义务与主体、
行动和资产分开；SKOS 将层级关系、关联关系和映射关系分开。这些模型分别说明来源、规范、类型和映射
不能被同一种“关联”关系吞并。[PROV-O](https://www.w3.org/TR/prov-o/)、[ODRL](https://www.w3.org/TR/odrl-model/)、[SKOS](https://www.w3.org/TR/skos-reference/)

开放关系类型发现研究支持从给定语料抽取实例、抽象类型名称并进行聚类，而不是假设一套预先完备的
跨领域关系本体可以覆盖一切。[TABS](https://aclanthology.org/2022.emnlp-main.461/)、[oreLLM](https://aclanthology.org/2024.acl-long.709/)

因此，已知体系用于发现候选轴和审查语义边界；当前语料用于盲审候选是否有原文证据，不能按词频或
聚类结果自动生成轴目录。最终目录仍须经过抽取、选择和找全检索验证。

#### 2.4.2 候选轴必须满足的定义要求

候选目录允许保留尚未完全细化的通用观察视角，但候选轴进入验证前必须按 2.3 补齐四项定义，并满足：

1. **关系性**：轴必须描述知识对象之间的关系，不能是领域主题、单个对象的属性或综合评价。
2. **单一语义维度**：轴只能考察关系中的一个语义维度，不能包含两个可以分别回答的问题。例如
   “是否允许”和“谁授予了权限”必须分属规范模态与权责和控制。
3. **边界可操作**：轴必须能够说明最小关系形态，以及什么关系进入、什么关系不进入。

除管理性的轴标识外，这三项与 2.3 的语义定义直接对应，不再使用额外的“可组合性”等抽象要求代替
具体定义。领域主题、知识对象域、参与角色、对象评价以及若干通用轴的组合都不能作为候选轴。

#### 2.4.3 具体问题选择优先验证轴

当前固定知识库的 `c13-003` 不负责定义轴，而负责从通用候选目录中选择优先验证对象：

> 在当前知识库中，除了沙箱、虚拟机和出口控制，AI Agent 还有哪些隔离或控制边界？请分别说明
> 各限制什么。

这里的“隔离或控制边界”是用户查询目标，不是单个关系观察轴。将问题分解后，得到的是它可以由候选
目录中的哪些通用语义维度组合回答，而不是要为这个问题新造轴。例如：

- “哪些对象、信息域或行动范围被隔开、连接或可达”指向边界与连通维度；
- “哪些行动被允许、禁止或要求”指向规范模态维度。

具体优先验证哪一到两个轴，由题目所需覆盖、候选轴之间的潜在混淆和验证成本共同决定。具体问题只
影响验证顺序，不改变候选轴的语义来源。

只有真实查询暴露出的语义确实构成一种通用的对象关系维度时，才考虑增加新的候选轴。新增候选必须
回到通用关系语义、参考体系和其他领域样例中重新审查，不能由当前问题直接定义。如果暴露出的只是
答案方面、领域主题、参与角色或若干通用轴的组合，就不能新增轴。

#### 2.4.4 抽取有效性与选择有效性

每批只将一到两个候选轴深化到可验证状态，并分别完成以下两个门槛：

**A. 抽取有效性**

给定一个轴的定义和原文，模型能否发现该轴下的关系实例、正确提取参与对象和角色、给出直接原文
证据，并排除相关但不属于该轴的内容。

这一验证回答的是：**这个轴能不能从原文中被可靠识别和抽取。**

**B. 选择有效性**

给定自然语言用户问题、当前待验证候选轴和累计已验证轴集合，模型能否准确选择一个或多个相关轴、
对最相关轴排序，并排除不相关轴。该验证同时检查待验证候选轴能否被选择，以及它是否与已验证轴
真正可区分。

这一验证回答的是：**这个轴能不能成为 LLM 可理解、可使用的关系检索入口。**

两个方面不能互相替代。一个轴可能容易从原文抽出，但用户问题无法稳定选择它；也可能轴名很容易
选择，但原文中的具体关系无法稳定抽取。抽取失败通常指向最小关系形态、判定边界或证据要求；
选择失败通常指向轴名称、规范问句或轴间重叠。

#### 2.4.5 候选目录、已验证集合与冻结流程

“候选轴目录”和“已验证轴集合”必须分开：

- 候选轴目录可以包含尚待审查或验证的通用候选；
- 已验证轴集合只收纳已经通过抽取有效性和选择有效性验证的轴；
- 具体问题只决定从候选目录进入验证的顺序，不改变候选目录的语义来源。

```text
从对象关系语义和参考体系形成通用轴候选
        ↓
按 2.3 补齐候选定义，排除领域主题、对象评价和参与角色
        ↓
形成候选轴目录
        ↓
用具体找全问题（首轮为 c13-003）映射所需通用关系维度
        ↓
从候选目录中选择 1～2 个优先验证轴
        ↓
抽取有效性验证 + 选择有效性验证
        ↓
根据失败修改轴定义，必要时拆分、合并或退回候选目录
        ↓
两者通过后，加入已验证轴集合
        ↓
在累计已验证轴集合上做同义问法和跨问题选择回归
        ↓
按问题价值选择下一批候选轴，但不为单个问题定制专用轴
        ↓
已验证轴集合达到首版稳定范围后冻结
        ↓
只对已验证轴设计二级关系
        ↓
抽取稳定性与找全检索验证
```

`c13-003` 的题面用于判断哪些通用轴应优先验证；它的金标准答案块只用于某一轮轴定义固定后测量
抽取和覆盖。二者都不能反向决定轴目录。轴线冻结前，也不根据单个金标准反复调整参数直到通过。

### 2.5 轴、二级关系与参与角色的区别

三者不能混为一谈：

```text
关系观察轴：从什么角度观察关系
二级关系：该角度下的哪一种关系
参与角色：该关系中有哪些位置及哪些知识对象占据这些位置
```

例如“A 向 B 发送消息”：

```text
轴：流转与输入输出
二级关系：发送
参与角色：发送者 A、接收者 B、消息内容
```

“主体、对象、来源、目标、接受者、机制、条件、受益者”等是参与角色，不单独构成关系轴。否则每一种
句法角色都会膨胀为一个分类，而不是形成有限、有区分度的观察角度。

## 3 核心概念与边界

### 3.1 知识对象

本文接受以下知识对象：

- 实体，例如 Agent、工具、凭证、策略；
- 事件、动作或状态，例如调用工具、批准请求、暂停任务；
- 概念或命题，例如“上下文隔离”；
- 已实体化的关系实例，例如“Agent A 访问了资源 B”这一事件关系本身。

被实体化的关系实例也是知识对象，可以作为另一条关系的端点。例如，条件关系可以把一个目标动作、
状态或关系实例作为目标端点：

```text
R1：Agent 访问外部网络
R2：R1 以人工批准为必要条件
```

### 3.2 关系实例

关系实例至少保留：

- 参与角色及其知识对象；
- 完整自然语言命题；
- 支撑该命题的原文证据；
- 关系观察轴及对应的二级关系标签。

关系实例不必被强制改写成严格三元组。否定、模态、条件、时间、程度、例外和评价由自然语言命题和证据承担，分类标签只负责形成可检索入口。

### 3.3 关系参与角色

参与角色说明某个知识对象在具体关系中充当什么位置。角色可以包括主体、对象、来源、目标、接受者、机制、条件、持有者等，但不是关系观察轴。

角色名称应来源于具体关系或框架，不能为了方便检索把所有对象统一写成“主体”和“客体”。当角色本身承载关键检索信息时，应由二级关系定义说明，而不是新增一个一级轴。

### 3.4 关系观察轴与二级关系标签

关系观察轴回答“从哪个角度观察”；二级关系标签回答“这个角度下具体呈现了哪些关系”。

轴内二级标签必须满足：

- **覆盖性**：任何符合该轴适用范围的关系实例，都至少能获得一个有原文证据的二级标签；
  标签集合的并集覆盖本轴全部适用情况，不使用“其他”或“无法归类”作为兜底；
- **原文可判**：每个标签都能由原文或明确命题语义直接判断；
- **检索可用性**：每个标签至少对应一种可独立表达的检索意图或可区分语义；
- **重叠合理**：同一关系实例可以同时获得多个同轴标签，不要求互斥；如果两个标签在所有适用
  样本上含义完全相同且不能提供独立检索价值，则应合并，而不是仅靠多标签保留；
- **边界明确**：标签定义必须说明进入条件，以及缺少何种原文证据时不能添加该标签。

这里的“覆盖”指二级标签集合对本轴适用范围的覆盖，不是从语料中抽全关系实例的召回率。允许
重叠只取消分类互斥，不取消标签定义的语义边界。

### 3.5 多轴与轴内多标签

同一关系实例可以在不同轴上得到标签，也可以在同一轴内得到多个二级关系标签。例如：

> 只有经过人工批准，Agent 才能访问外部网络。

可以同时得到：

```text
条件依赖：必要前置条件
规范模态：附条件许可
权责与控制：批准权属于某主体或机制
边界与连通：外部网络访问受到控制
```

多轴标签不是重复抽取多条关系。返回结果应保留一份关系实例和完整命题，同时列出多个分面标签。
同一轴内的多个标签同样附着在同一关系实例上，不复制关系实例或原文证据。

如果同一原文确实表达了多个可独立断言的关系，仍应分别形成关系实例；不能为了减少数据量把它们硬合并。

### 3.6 知识对象域轴

知识对象域轴必然领域相关，按知识组织目的划分知识对象和证据。例如 AI Agent 知识库可按生命周期划分为设计、开发、发布和运维，再在运维下划分安全、可观察性和故障恢复。

“安全”“记忆管理”“部署”“评测”“生命周期”不是关系观察轴。它们可能成为知识对象域、能力域或查询场景，但不能直接作为关系分面。

当前阶段固定整个活动知识库为 AI Agent 全域，不实现知识对象域筛选。同一关系类别内部的领域歧义暂时保留，不能通过知识对象域分类掩盖关系轴定义问题。

### 4.1 参考资料审查与候选轴推导

不作为推导输入；它们只是旧初稿，待本节完成后再与新候选逐项对照。

当前进度：仅完成 ConceptNet；UCCA、FrameNet、PROV-O、ODRL、SKOS、TABS 和 oreLLM 尚未进入候选集。

#### 4.1.1 ConceptNet 逐关系审查

[ConceptNet Relations](https://github.com/commonsense/conceptnet5/wiki/Relations) 当前列出 34 个正式关系。
它们可以证明有限关系集合能够服务实际知识表示，但关系粒度并不统一，既包含对象关系，也包含词汇、
属性、语境和外部链接关系。因此必须逐项检查，不能把 `/r/*` 同名复制成观察轴。

“候选集增量”中的编号 C01～C12 是本次推导的临时候选编号，与旧初稿的 R01～R15 无对应关系。
每行只执行一种主要推导动作：新增观察轴、为已有观察轴增加证据、合并到已有观察轴，或因它不属于
两个知识对象之间的可检索关系而排除。候选沿表格首次出现后即进入临时集合，后续关系通过编号继续
增加证据，不再按关系名另建同义候选。

“来源定义”是依据 ConceptNet 英文关系表所作的中文转述，不是原网页文字或官方中文定义；“本文性质
判断”和“候选集增量或排除理由”是本文依据观察轴定义所作的判断，不是 ConceptNet 自身的分类结论。

处理标记：`🟢 新` 表示首次建立候选；`🔵 补` 表示为已有候选增加证据；`🟠 拆`
表示一个来源关系同时支持两个候选；`🔴 排` 表示不进入候选集。关系名省去统一的 `/r/` 前缀。

表格按内容密度排列：第一列只放处理标记和关系名；来源列用换行区分定义与示例；判断列只放关系性质；较长
推导集中在最后一列，避免长句把中间列撑宽。

| 🔴 排 · DefinedAs | A 与 B 意义高度重叠，B 是 A 的解释性表达。<br>例：`peace → absence of war` | 概念定义／解释 | 排除为关系轴。属于概念定义和归一化，不建立一般对象关系。 |
| 🔵 补 · MannerOf | A 是做 B 的一种具体方式。ConceptNet 称其类似 IsA，但用于动词。<br>例：`auction → sale` | 本文判断为行动概念的类型包含 | 支持 C01 的“子类型归类”。ConceptNet 仍将 MannerOf 列为独立关系，本文依据其“类似 IsA，但用于动词”的说明推导：当参与者是行动概念时，它与子类型归类的差异在参与者类型，而不在类型包含判断本身。该归并属于本文判断，并非 ConceptNet 原文结论；若原文表达的是用一个机制实现另一个目标而非类型包含，则不能仅凭 MannerOf 归入本轴。 |

| 🔴 排 · HasContext | A 是 B 语境中使用的词，B 可以是主题、领域或方言。<br>例：`astern → ship`；`arvo → Australia` | 语境／领域归属 | 排除。属于知识对象域和词义语境，不是对象关系轴。 |
| 🔵 补 · SimilarTo | A 与 B 相似。<br>例：`mixer ↔ food processor` | 比较 | 支持 C11“相似、对立与区分”；首版仅保留为弱候选。ConceptNet 没有提供一般“替代”关系，候选名不引入替代语义。 |
| 🔴 排 · Etymologically<wbr>RelatedTo | A 与 B 有共同词源。<br>例：`folkmusiikki ↔ folk music` | 词源关系 | 排除。属于语言历史信息，不进入通用对象关系轴。 |
| 🔴 排 · Etymologically<wbr>DerivedFrom | A 从 B 词源派生。<br>例：`dejta → date` | 词源关系 | 排除，不进入 C09。词汇词源不能等同于内容或对象的来源关系。 |
| 🔵 补 · CausesDesire | A 使某人希望得到 B。<br>例：`having no food → go to a store` | 因果＋偏好 | 仅为 C06 提供弱证据；不新增欲望轴，是否保留取决于 Agent 语料是否真正需要。 |
| 🔵 补 · MadeOf | A 由材料 B 制成。<br>例：`bottle → plastic` | 材料组成 | 支持 C02。 |
| 🔵 补 · ReceivesAction | B 是对 A 可以执行的动作。<br>例：`button → push` | 被动可作用性 | 支持 C04；主动能力与被动可作用性由完整命题区分，不拆成两个轴。 |
| 🔴 排 · ExternalURL | A 指向 ConceptNet 外部的进一步数据，类似 RDF `seeAlso`。<br>例：来源表未给示例 | 外部链接 | 排除。属于元数据和引用入口，不是对象关系。 |

ConceptNet 还说明：`InstanceOf` 应并入 `IsA`；`Entails` 应按语义归入 `MannerOf` 或
`HasPrerequisite`；`Not*` 关系只是对应断言的否定，不产生新的语义维度。这些规则与上表一致，
因此不额外增加候选轴。

#### 4.1.2 ConceptNet 完成后得到的临时候选集

| 编号 | 临时候选观察轴 | 当前证据来源 | ConceptNet 支持程度 |
| --- | --- | --- | --- |
| C01 | 类型归类：对象或行动属于什么类型、类别或上位概念？初步二级关系为“实例归类”和“子类型归类” | IsA、MannerOf | 明确；IsA 同时提供两种端点层级，MannerOf 支持行动概念的子类型归类 |
| C02 | 组成与部分：整体由哪些部分、成员、材料或子事件构成？ | PartOf、HasA、HasSubevent、HasFirstSubevent、HasLastSubevent、MadeOf | 明确 |
| C03 | 用途与目的：对象、机制或行动被用于什么用途，服务于什么目标或结果？初步二级标签为“功能用途”和“目标动机”，允许重叠 | UsedFor、MotivatedByGoal | 明确；表达用途或目的，不等于当前具备相应能力 |
| C04 | 能力与可作用性：对象通常能够执行哪些行动，或能够承受哪些行动？初步二级标签为“主动能力”和“被动可作用性” | CapableOf、ReceivesAction | 明确；表达主动或被动能力，不等于具有相应用途 |
| C05 | 位置与空间关系：对象位于何处，与另一对象是否邻近或处于同一空间范围？ | AtLocation、LocatedNear | 明确，但边界与可达性尚未得到支持 |
| C06 | 作用与影响：A 对 B 的发生、可阻止性或愿望产生什么作用？ | Causes、ObstructedBy、CausesDesire | 明确；方向与正负极性留在命题中 |
| C07 | 时间与事件组织：事件或子事件以什么先后位置组织？ | HasFirstSubevent、HasLastSubevent | 有直接证据，但范围较窄 |
| C08 | 条件与依赖：目标成立前必须满足什么条件？ | HasPrerequisite | 明确，但只有一个强关系 |
| C09 | 来源与产生：对象或信息由哪个主体、过程或活动产生？ | CreatedBy | 有直接证据；尚不含一般派生和流转 |
| C10 | 符号表征：一个符号或表达如何象征性地表示另一对象或含义？ | SymbolOf | 有直接证据；尚不覆盖术语映射或模型对应 |
| C11 | 相似、对立与区分：对象之间在哪个相关方面相似、相反或彼此区分？ | SimilarTo、Antonym、DistinctFrom | 证据偏词汇关系，暂为弱候选；不支持“替代” |
| C12 | 拥有与归属：某对象或资源由谁持有或归谁所有？ | HasA | 弱证据，且与组成混在同一关系中，待后续来源决定 |

C03 与 C04 的相邻边界：C03 回答“A 被用来做什么或为什么目的服务”，用途可以在当前能力受损时
继续存在；C04 回答“A 通常能够做什么或承受什么”，能力可以存在而不构成 A 的用途。原文明确同时
表达用途和能力时，同一关系实例可以同时进入两个轴；抽取时不从其中一个自动推出另一个。C03 内的
“功能用途”和“目标动机”可以同时成立，因此它们是同轴多标签，而不是互斥分类。

ConceptNet 没有直接支持规范状态、权利责任、一般输入输出、状态生命周期或证据判断。它们不能因为
常识上“应该有”就提前写入候选集；等待后续来源逐项审查。

#### 4.1.3 ConceptNet 审查结论

- ConceptNet 是关系名来源，不是观察轴目录。它提供了 12 个临时候选方向，其中 C01～C10 有较直接的
  关系语义，C11、C12 证据较弱。
- ConceptNet 的词汇、属性、语境、词源和外部链接关系不进入轴候选；保留在概念归一化、对象属性、
  完整命题或元数据中。
- `HasSubevent` 等关系表明事件也可以作为知识对象，但事件关系不应自动拆成新轴。只要语义仍然是
  整体—部分，就增强 C02；只有明确表达时间位置时，才增强 C07。
- 下一步审查 UCCA，并逐项判断它是为现有候选增加证据，还是暴露新的通用关系维度。

### 4.2 各候选轴的定义

以下轴卡是第一轮候选。每张轴卡均按四项定义检查；当前“最小关系形态”用于验证该轴是否确实
构成对象关系，仍须经过第 8 节的盲审后才能冻结。

#### 4.2.1 R01 因果影响

**唯一问题**：A 对 B 的发生、可能性、强度或持续状态产生了什么作用？

**最小关系形态**：至少存在一个作用来源，以及一个被影响的发生、可能性、能力、程度或持续状态，并由原文明确建立作用关系。

**适用全集**：原文明确表达一个对象、活动、状态、条件或机制对另一个知识对象的出现、不发生、概率、程度、能力或持续状态产生作用的实例。

**暂定二级方向**：导致、使能、抑制、防止、增强、减弱、维持。方向、强度和条件由完整命题保留；候选方向允许重叠，但进入二级设计前仍需检查覆盖性和独立检索价值。

**不进入本轴**：只有时间先后而没有作用；只有命题层面的逻辑前置；只有规范允许或禁止；只有主题相关或共同出现。

#### 4.2.2 R02 条件依赖

**唯一问题**：B 的发生、成立、继续或被接受依赖哪些条件？

**最小关系形态**：至少存在一个目标动作、状态、判断或关系实例，以及一个被原文明确表达为前置、必要、充分、触发或阻止条件的知识对象。

**适用全集**：原文明确表达目标动作、状态、判断或关系实例与另一条件、对象、机制或步骤之间存在前置、必要、充分、触发或阻止关系的实例。

**暂定二级方向**：必要条件、充分条件、触发条件、前置依赖。现实中可能同时成立必要和充分关系；这些标签允许在同一关系实例上重叠，但必须共同覆盖本轴，并分别具备原文证据。

**不进入本轴**：一般因果作用；毫无逻辑依赖的共同出现；只表达时间顺序；只表达规范状态而没有条件依赖。

#### 4.2.3 R03 规范模态

**唯一问题**：某行动或状态在规则、权限或政策下处于什么规范状态？

**最小关系形态**：至少存在一个行动或状态，以及一个规则、权限体系、政策或权威来源；原文须明确给出允许、禁止、要求或建议等规范状态。

**适用全集**：原文明确由规则、制度、权限体系或权威主体对某行动、状态、访问或使用作出允许、禁止、要求、建议等规范判断的实例。

**暂定二级方向**：允许、禁止、要求、建议。授权、委托和职责归属暂放 R13，避免把“行动是否可以做”和“谁有权作出该决定”混为一类。

**不进入本轴**：单纯技术可行性；没有规范来源的事实性能力；只有条件但不含规范评价；只描述授权关系而没有规范状态。

#### 4.2.4 R04 组成结构

**唯一问题**：哪个整体由哪些部分、成员或内容构成？

**最小关系形态**：至少存在一个整体或集合，以及一个被原文明确归入该整体或集合的部分、成员或内容项。

**适用全集**：原文明确表达整体—部分、集合—成员、结构—构件或明确列举的内容构成关系的实例。

**暂定二级方向**：部分组成、集合成员、内容构成。是否进一步划分取决于语料中是否存在稳定的用户查询差异。

**不进入本轴**：类型归属；普通包含词语导致的内容相关；空间容纳；只是列举多个对象但没有把它们构成一个整体。

#### 4.2.5 R05 类型归类

**唯一问题**：某对象、实例或实践属于哪个类型、类别或子类？

**最小关系形态**：至少存在一个待分类对象，以及一个由原文明确给出的类型、类别或子类。

**适用全集**：原文明确表达实例—类型、子类—父类、类别划分或明确分类归属的实例。

**暂定二级方向**：实例归属、子类归属、类别划分。具体命名仍需避免与普通名词释义和主题分类混淆。

**不进入本轴**：整体—部分；空间集合成员；仅因功能相似而推断同类；文档自身的章节归类。

#### 4.2.6 R06 边界与连通

**唯一问题**：哪些对象、信息域或行动范围之间被隔开、连通或可达？

**最小关系形态**：至少存在边界两侧的对象或范围，并由原文明确表达它们之间是否穿越、连接、隔开、包含在域内或可达。

**适用全集**：原文明确表达逻辑或物理空间中的包含、排除、隔离、连接、可见、可达、不可达或访问边界的实例。首版以逻辑边界、信息边界和访问连通性为主，不以普通物理位置检索为主要目标。

**暂定二级方向**：域内包含、域外排除、隔离、连接、可达、不可达。二级标签必须避免把“通过某机制实现隔离”的另一层因果关系并入本轴。

**不进入本轴**：整体—部分结构；普通内容包含；没有边界或连通语义的“使用”“访问”；只有安全主题而没有实际边界关系。

#### 4.2.7 R07 时间顺序

**唯一问题**：事件或状态在何时、以什么先后、并发、持续或重复结构出现？

**最小关系形态**：至少存在两个事件或状态之间的相对时间结构，或一个事件、状态与明确的持续时间、重复周期或时间区间结构。

**适用全集**：原文明确表达先后、同时、区间重叠、持续时间、周期性或事件内部子事件顺序的实例。

**暂定二级方向**：先于、同时、持续、周期性、子事件顺序。

**不进入本轴**：状态自身发生变化；纯因果作用；普通日期元数据；以时间为必要条件但重点在于目标是否成立的条件关系。

#### 4.2.8 R08 状态与生命周期

**唯一问题**：对象、过程或能力经历了什么状态变化？

**最小关系形态**：至少存在一个对象、过程或能力，以及原文明确表达的前后状态、生命周期阶段或状态转变。

**适用全集**：原文明确表达创建、开始、继续、暂停、恢复、完成、失效、重置、删除等状态转变或生命周期阶段的实例。

**暂定二级方向**：创建、开始、继续、暂停、恢复、完成、重置、删除。阶段标签允许重叠；其并集必须结合对象类型声明覆盖本轴范围，并明确每个阶段标签的原文进入条件。

**不进入本轴**：只有时间先后；外部机制导致状态变化而原文重点在因果作用；普通属性赋值；单纯描述一直存在的静态属性。

#### 4.2.9 R09 来源与派生

**唯一问题**：对象、信息或断言由谁产生、从哪里来、由什么派生？

**最小关系形态**：至少存在一个被追踪的知识对象或断言，以及原文明确的来源、创建者、生成活动、派生来源或归属对象。

**适用全集**：原文明确表达来源、创建者、生成活动、派生、继承、归因或出处关系的实例。

**暂定二级方向**：来源对象、创建者、生成活动、派生自、归属于。PROV-O 的实体、活动和主体分离可作为边界参考。

**不进入本轴**：某信息向何处流动；某证据支持什么结论；仅仅出现 URL 或文件名但没有来源关系。

#### 4.2.10 R10 流转与输入输出

**唯一问题**：信息、资源、任务或信号如何从一处流向另一处？

**最小关系形态**：至少存在流出来源、流入目标，以及被传递的信息、资源、任务或信号；输入输出可以显式或由原文清楚表达方向。

**适用全集**：原文明确表达输入、输出、发送、接收、传递、引入、消费、产生或任务移交的实例。

**暂定二级方向**：输入、输出、发送、接收、传递、消费、产生。控制权、权利和职责的委托不放在本轴。

**不进入本轴**：静态来源；总体构成；一般因果影响；只有一个对象出现但没有源和去向。

#### 4.2.11 R11 依据与判断

**唯一问题**：什么证据、观测或结果支持、反驳或推出某个判断？

**最小关系形态**：至少存在证据、观测、验证或评估结果，以及被支持、反驳、指示或推出的判断、结论或状态。

**适用全集**：原文明确表达证据支持、反驳、证明、指示、验证、审计、测量、评估或据此推出某结论的实例。

**暂定二级方向**：支持、反驳、指示、验证、评估。观测和审计本身可能同时属于其他轴；本轴只记录它们与判断或结论之间的依据关系。

**不进入本轴**：对象来源；没有结论或判断目标的普通记录；以制度直接规定某结论的规范关系；纯主题相关。

#### 4.2.12 R12 目的与功能

**唯一问题**：对象、规则或机制被用来实现什么目标、承担什么功能？

**最小关系形态**：至少存在手段、对象、规则或机制，以及原文明确表达的用途、目的、功能或预期目标。

**适用全集**：原文明确表达用途、设计目的、预期目标、服务功能或为实现某结果而采用某手段的实例。

**暂定二级方向**：用途、目的、功能、预期效果。原文必须区分明确目的与仅从行为推得的效果。

**不进入本轴**：已实际产生的因果结果；纯规范要求；没有目的或功能语义的普通使用动作。

#### 4.2.13 R13 权责与控制

**唯一问题**：哪个主体对对象或行动拥有、获得、授予、委托或承担什么权利、责任与控制？

**最小关系形态**：至少存在主体，以及其拥有、获得、授予、承担或撤销的权利、责任、任务、资源或控制权；发生转移时还须有被授权或被委托对象。

**适用全集**：原文明确表达所有权、控制权、授权、委托、任务分配、职责承担、批准权、撤销权等主体—权利—对象或行动关系的实例。

**暂定二级方向**：拥有、授权、委托、分配、负责、撤销。需要验证“授权”与“允许”是否必须分解为不同轴，还是可以作为规范轴和控制轴上的不同分面。

**不进入本轴**：一般行动许可；信息或资源移动；实际执行动作；只在句法上出现主体但没有权利、责任或控制关系。

#### 4.2.14 R14 表征与映射

**唯一问题**：符号、数据、模型或术语如何表示、编码或对应另一个知识对象？

**最小关系形态**：至少存在表示载体（符号、术语、数据或模型）、被表示对象，以及原文明确表达的表示、编码、映射或对应关系。

**适用全集**：原文明确表达表示、指称、编码、代表、映射、等价对应或模型—对象对应关系的实例。

**暂定二级方向**：表示、指称、编码、映射、等价对应。

**不进入本轴**：普通类型归属；没有约定关系的命名；从相似性推测的对应；数据来源。

#### 4.2.15 R15 比较与替代

**唯一问题**：多个对象在某一维度上如何比较，能否相互替代？

**最小关系形态**：至少存在两个可比较对象，或一个对象与明确备选对象，并具有原文表达的差异、优劣、相似、替代或备选关系。

**适用全集**：原文明确表达相似、不同、优劣、高低、取舍、替代或备选关系的实例。

**暂定二级方向**：相似、不同、比较评价、替代、备选。

**不进入本轴**：没有共同比较维度的两个对象；类型归属；功能不同且没有比较或替代语义的并列介绍。

### 4.3 旧分类残留检查

本节不是设计目标，也不是候选轴来源。它只用于在候选轴形成后检查是否仍混入了旧分类的领域主题、
参与角色或多问题集合。如果本文候选轴本身已经能够说明其语义和边界，本节不影响轴目录。

| 旧一级家族 | 处理方式 | 原因 |
| --- | --- | --- |
| F01 因果与作用 | 基本进入 R01 | 单一作用视角仍成立，但需把纯条件、纯规范排除 |
| F02 条件与控制 | 拆分 | 条件依赖进入 R02；规范范围和规范状态进入 R03；边界控制进入 R06；控制权进入 R13 |
| F03 允许与禁止 | 收窄为 R03 | 保留规范模态；授权、委托、职责归属移入 R13 |
| F04 状态与过程 | 拆分 | 状态变化进入 R08；事件间相对时间进入 R07；外部作用保留在 R01 |
| F05 分类与结构 | 拆分 | 组成进入 R04，类型归属进入 R05 |
| F06 时间与顺序 | 进入 R07 | 同时检查与 R02 条件、R08 生命周期变化的边界 |
| F07 空间、边界与连通 | 收窄为 R06 | 首版主要保留逻辑边界、隔离、连通和可达性 |
| F08 目的与用途 | 进入 R12 | 常规目的／用途暂不拆分，等待查询差异证据 |
| F09 比较与替代 | 进入观察轴 R15 | 当前不作为首批深化轴 |
| F10 来源与证据 | 拆分 | 来源和派生进入 R09；证据和判断进入 R11 |
| F11 表征与映射 | 进入观察轴 R14 | 语义独立，是否进入首版由语料价值决定 |
| F12 主体与资源 | 解散 | 主体、资源、来源、目标等是参与角色；流转进入 R10，权责和控制进入 R13 |

旧二级关系不能自动迁移到新轴。每一条旧二级关系都必须回答：它属于哪个轴；它与其他同轴标签是否可区分且具有独立检索价值；它是否能由原文稳定判断；本轴所有标签的并集是否覆盖适用实例。不能回答者只能作为候选保留，不能进入实现目录。

### 4.4 不属于关系观察轴的候选

以下概念不应直接进入轴目录：

- **安全**：知识对象域、质量关注点或查询场景；
- **生命周期**：知识对象域的组织视角；
- **记忆管理、工具调用、评测、部署**：能力域、职能域或知识对象域；
- **隔离**：可能由 R03、R06、R09、R10 和 R13 共同回答的查询目标；
- **信任**：可能组合 R06、R09、R11 和 R13，不能仅凭“信任”一词定义一条领域无关关系；
- **控制边界**：可能组合条件、规范、边界、流转和权责，不对应单一轴；
- **主体、对象、来源、目标、机制**：关系参与角色，不是轴。

一个自然语言词可能同时触发多个轴。轴系统的目标不是让一个词只对应一个轴，而是让查询可以说明需要枚举哪些独立关系视角。

### 4.5 当前轴目录的完整性边界

15 个轴只是首版候选，尚不能宣称覆盖所有可能关系。完整性只按以下顺序逐步验证：

1. 当前知识库中明确表达的关系是否能够映射到至少一个轴；
2. 无法映射的实例是否反复形成新问题簇；
3. 新问题簇是否属于知识对象域或参与角色而非关系轴；
4. 用户可以自然提出、但现有轴无法表达的找全问题是否存在；
5. 新增轴是否提供当前轴无法提供的独立检索入口。

在没有验证证据前，不为了“看起来完整”而继续增加轴。

## 5 轴间关系与组合语义

### 5.1 多轴标注规则

- 轴间和轴内都允许重叠；
- 一条关系实例可拥有零个、一个或多个轴标签，也可在同一轴内拥有多个二级标签；
- 每个轴标签必须基于原文中该轴的明确语义，不能因为其他轴标签存在而顺带补写；
- 多轴并存时只保留一份关系实例和证据，分面标签作为附属分类；
- 如果原文实际表达两个可以独立成立的关系，应分别形成关系实例，不能只做多标签。

### 5.2 主要轴边界

| 相邻轴 | 区分方式 |
| --- | --- |
| R01 因果影响 / R02 条件依赖 | R01 问实际作用及影响程度；R02 问目标成立在逻辑上依赖什么条件。二者可同时成立 |
| R02 条件依赖 / R03 规范模态 | R02 描述条件关系；R03 描述行动的允许、禁止、要求等规范状态 |
| R03 规范模态 / R13 权责与控制 | R03 问行动本身是否允许；R13 问谁拥有批准、授权、委托、撤销或负责地位 |
| R04 组成结构 / R05 类型归类 | R04 是整体—部分／集合—成员；R05 是实例—类型／子类—父类 |
| R04 组成结构 / R06 边界与连通 | R04 说明构成；R06 说明域内域外、隔离、连接和可达性 |
| R09 来源与派生 / R10 流转与输入输出 | R09 问来源和派生；R10 问从来源到目标的传递路径及输入输出 |
| R09 来源与派生 / R11 依据与判断 | R09 问内容从哪里来；R11 问内容如何支持或影响判断 |
| R11 依据与判断 / R13 权责与控制 | R11 问证据和结论；R13 问权利、责任和控制归属 |
| R12 目的与功能 / R01 因果影响 | R12 是明确目的、用途或功能；R01 是实际产生或可能产生的作用 |
| R05 类型归类 / R14 表征与映射 | R05 问类别归属；R14 问符号、模型或数据对另一对象的表示与对应 |

轴边界不是靠优先级解决的。同轴标签反复同时成立不自动构成缺陷；只有它们在所有适用样本上完全重合、无法形成独立检索价值时才应合并。如果两个轴总是必须同时选择且回答同一个问题，应考虑合并或重新定义。

### 5.3 查询组合示例

问题：“AI Agent 中有哪些隔离与控制边界？”

不能用“隔离”直接命中一个轴，而应拆解为若干关系轴和检索子问题：

- R03：哪些行动被允许、禁止或要求；
- R06：哪些对象、信息域或行动范围被隔离、连接或可达；
- R09：被控制的输入来自哪里，属于何种来源；
- R10：信息、资源或控制信号如何跨越边界流转；
- R13：谁拥有授权、控制、委托或撤销的权力。

问题：“长期编码 Agent 如何管理有限上下文？”

可能组合：

- R04：上下文或记忆由哪些部分构成；
- R08：哪些内容被压缩、保留、淘汰或恢复；
- R10：信息如何进入、离开或传递至外部存储；
- R12：各机制服务于什么目标；
- R02：在什么条件下触发压缩、检索或恢复。

该示例只说明轴组合方式，不作为任何金标准或关系目录的设计来源。

## 6 首批二级关系设计

### 6.1 设计顺序

首批二级关系必须在线轴盲审之后确定。当前不直接冻结 15 个轴下的全部类别，原因如下：

- 部分轴可能合并、拆分或删除；
- 轴内二级标签需要依据真实关系实例形成；
- 同时在提示词中注入大量类型会产生明显语义干扰；
- 单轴类别设计、抽取和检索验证可以独立进行；
- 过早分类会把单领域答案方面固化成通用关系。

### 6.2 首批深化轴的候选顺序

根据当前找全问题和已有实验基础，首批优先审核以下轴：

1. R06 边界与连通；
2. R02 条件依赖；
3. R03 规范模态；
4. R09 来源与派生；
5. R11 依据与判断；
6. R13 权责与控制；
7. R01 因果影响。

这只是验证队列，不是轴的重要性排名，也不是最终首批清单。盲审中如果发现某个轴高频、定义稳定且查询映射清楚，可以提前；如果发现边界持续不清，应推迟深化。

### 6.3 二级关系的设计模板

每个二级关系至少记录：

| 字段 | 内容 |
| --- | --- |
| 关系 ID | 当前轴内稳定编号 |
| 中文名称 | 可被产品和设计人员理解的术语 |
| 稳定定义 | 一句领域无关的关系语义 |
| 所属轴 | 唯一的一级观察轴 |
| 轴覆盖贡献 | 与其他同轴标签共同覆盖该轴适用范围的方式 |
| 典型参与角色 | 该关系需要的角色，不用主体／客体含糊带过 |
| 原文判定依据 | 原文明确表达什么才可判断 |
| 同轴多标签与边界 | 可同时命中的标签、何时允许重叠、缺少何种证据时不得添加本标签 |
| 跨轴排除边界 | 什么情况虽然相关，但不属于本轴 |
| 查询用法 | 用户可能如何通过该关系检索 |
| 当前证据 | 语料实例、运行次数和验证结论 |
| 状态 | 候选／已验证／已否决 |

### 6.4 二级关系不得直接复用旧模板

旧 38／40 个关系表只能作为候选词汇来源。迁移时必须逐项检查：

1. 它是否真正属于某一个轴，而不是多个轴的主题集合；
2. 它与其他同轴标签是否可区分，并在允许重叠时是否仍有独立检索价值；
3. 它是否存在稳定的独立用户查询；
4. 它是否可以由原文可靠判断；
5. 它是否能通过单类别注入和组合注入测试。

未通过者不得因为“以前已经用过”而继续保留。

## 7 从用户问题到关系轴

### 7.1 查询分解

一个找全问题需要先识别：

- 资料范围；
- 知识对象域，当前固定为 AI Agent 全域；
- 查询锚点，例如某个对象、行动或状态；
- 需要枚举的关系观察轴；
- 每个轴内需要检索的二级关系标签，以及标签间的布尔关系与求值作用域；
- 覆盖完成的判定条件。

### 7.2 轴选择与排序

主 Agent 可以根据完整问题选择一个或多个轴，并对最相关轴排序。排序只影响检索调度和证据优先级，不改变关系分类。

轴名不应依赖大量领域关键词才能理解。验证时必须使用不同问法，检查模型选择是否稳定，不能用固定的几个提示词验证通过代替语义稳定性。

### 7.3 查询计划结构

当前阶段的计划可以表示为：

```text
查询
  资料范围：活动知识库快照
  知识对象域：AI Agent 全域（固定）
  查询锚点：对象、动作、状态或命题
  关系分面表达式
    AND(
      OR(A.A1, A.A2),
      B.B3
    )
  求值作用域：关系实例 / block / 文档
  覆盖检查
    布尔表达式是否按声明作用域求值
    轴内所选标签是否全部有结果或明确为空
    关系实例是否有原文证据
```

表达式叶节点表示“某轴下的某二级标签”。`OR` 表示任一标签满足即可，`AND` 表示同一求值作用域
必须同时满足所有子树。默认的“找全”候选召回可以在同一轴的备选标签间使用 `OR`，但用户明确要求
同时具备多个语义时使用 `AND`。每个 `AND` 必须声明在关系实例、block 还是文档级求交；不能只返回
一个不带作用域的标签列表。多标签命中最终按关系实例或声明作用域去重。

### 7.4 无法稳定映射时

遇到以下情况必须显式记录，不能静默缩减：

- 问题是知识对象域问题而不是关系问题；
- 同一问法在不同运行中映射到不同轴；
- 需要多个轴但当前只能选择其中一个；
- 现有轴无法表达查询意图；
- 轴虽然可选，但语料中没有足够关系实例。

这些情况进入轴线审计，用于调整轴定义或确认能力边界。

## 8 验证设计

### 8.1 验证目标

本设计不是验证“模型能否生成看似合理的标签”，而是验证：

1. 轴是否只考察一个关系语义维度；
2. 关系实例能否被稳定归入轴；
3. 轴内二级标签的并集是否覆盖适用范围，且每个标签都有可判定的原文边界；
4. 原文是否足以支持分类；
5. 主 Agent 是否能从自然问题映射到轴；
6. 基于关系分面的检索是否真实改善找全；
7. 成本和稳定性是否在可接受范围内。

### 8.2 固定实验配置

每次正式回放必须记录：

- collection 快照 ID；
- 文档和 block 范围；
- 模型及参数；
- 轴目录版本；
- 二级关系目录版本；
- 提示词版本；
- 单次或多次运行、并发和重试设置；
- 输出 token 上限及截断情况；
- 原始结果所在路径和哈希。

不同配置之间的结果不得直接合并统计。

### 8.3 第一阶段：用具体问题选择优先验证轴

首轮先按 2.4.1 的来源边界形成通用候选轴目录，再固定 `c13-003` 的题面，不查看目标
block 分布，并回答以下问题：

1. 题目要求回答的“找全”涉及哪些关系语义方面；
2. 这些方面分别映射到候选轴目录中的哪些通用轴；
3. 哪些方面属于知识对象域、主题、参与角色或若干通用轴的组合，不能新增为轴；
4. 哪些候选轴对本题覆盖最关键、彼此最容易混淆，因而应优先验证。

首轮从既有候选目录中选择一到两个轴进入 8.4 的双验证，不为 `c13-003` 单独设计轴。题目中的领域
词不能直接变成轴；例如“隔离”和“控制边界”必须被分解并映射到既有通用轴。

语料关系实例用于构造正例、反例和排除边界，不能按频次或聚类结果自动决定轴目录。`c13-003` 的目标
block 只有在候选轴定义固定后才用于测量抽取覆盖。

### 8.4 第二阶段：候选轴抽取与选择即时验证

每一到两个候选轴都必须完成以下两个验证门槛。

#### 8.4.1 抽取有效性

针对候选轴和主要相邻轴，建立纳入与排除样例：

- 单一轴关系；
- 多轴并存关系；
- 同一句包含多个独立关系；
- 条件、否定、例外、模态和隐含表达；
- 轴定义不清导致的错误归类；
- 领域关键词缺失但关系仍然明确的表达。

验证记录必须包含关系实例、参与对象、原文证据和排除理由。首次验证以块级输入为主，避免整篇输入的注意力漂移掩盖轴定义问题。

#### 8.4.2 选择有效性

使用“当前待验证候选轴 + 累计已验证轴集合”，对多种自然问法验证：

- 是否能稳定选中正确轴；
- 是否会把领域词误当成轴；
- 是否正确返回多个相关轴并排序；
- 是否正确排除不相关轴；
- 轴集合能否覆盖问题的关系方面。

首个批次只有两个待验证轴时，验证主要检查二者是否可区分；后续批次必须把新候选轴与累计已验证轴
集合一起验证，防止新轴与旧轴争夺同一查询意图。候选通过后的正式回归只使用已验证轴集合。

任何一批轴只要抽取或选择任一方面失败，就返回修改轴定义，不进入该批轴的二级关系设计。轴线冻结前，不使用单个找全问题调参，也不根据一个金标准反向修改轴。

### 8.5 第三阶段：单轴二级关系验证

每次只输入一个轴和一个候选二级关系，先验证：

- 发现率；
- 多次运行稳定性；
- 原文证据支持；
- 参与者是否正确；
- 与其他同轴类别的误归。

单类别验证通过后，再进行同轴多类别验证。不同轴不得因为实现方便而一次性全部注入。

### 8.6 第四阶段：轴级组合验证

将同一轴下已经过单类验证的二级关系组合，检查：

- 类别之间是否互相干扰；
- 是否出现类型竞争导致漏判；
- 多类别返回是否正确保留同轴多标签，并未造成关系实例或证据重复；
- 轴的完整查询是否比逐类别调用更稳定或更经济。

如果组合效果明显低于单类结果，应保留独立抽取，不能为降低成本掩盖召回退化。

### 8.7 第五阶段：抽取输入边界验证

至少在以下粒度中比较：

- 单句；
- 单 block；
- 相邻 block；
- 分批文档；
- 整篇文档。

验证目的不是寻找一个“最便宜”的调用方式，而是判断语义上下文、长上下文注意力、跨块关系和输出截断分别造成什么影响。任何整篇或分批方案都必须与块级结果对照。

### 8.8 第六阶段：累计已验证轴集合的选择与冲突回归

在每个小批验证之外，还要在全部已验证轴组成的集合上执行选择回归：

- 是否能稳定选中正确轴；
- 是否会把领域词误当成轴；
- 是否正确返回多个轴；
- 是否正确排除不相关轴；
- 轴集合能否覆盖问题的关系方面。

测试问题在验证前冻结，不能根据模型输出临时改写直到通过。

### 8.9 第七阶段：找全检索验证

轴线冻结后才进入找全验证：

1. 单文档找全；
2. 多文档找全；
3. 同一语义的多种问法；
4. 单轴查询；
5. 多轴组合查询；
6. 与仅使用主题、概念和文本相似度的结果对照；
7. 对漏召回进行逐条原文审查；
8. 对额外召回判断是合理扩展还是精度退化。

金标准用于验证，不用于设计轴和二级关系的语义。

### 8.10 指标

每个轴和二级关系应记录：

| 指标 | 说明 |
| --- | --- |
| 实例发现率 | 人工确认的目标关系中有多少被抽出 |
| 多次运行稳定性 | 固定输入下同一关系被稳定发现的比例 |
| 人工判定精度 | 抽出的关系中确实符合定义的比例 |
| 无法判定率 | 只看原文无法确定关系的比例 |
| 证据支持率 | 返回关系有直接原文支持的比例 |
| 轴选择一致性 | 同一意图的不同问法是否选择相同轴 |
| 二级标签覆盖率 | 人工确认有效的关系实例中，至少获得一个正确同轴二级标签的比例 |
| 同轴多标签一致性 | 多次运行得到的二级标签集合是否一致，可使用集合重合度衡量 |
| 无依据重叠率 | 同一关系实例上的额外二级标签缺少独立原文证据的比例 |
| 关系分面表达式正确率 | 标签、`AND`／`OR` 运算符和求值作用域均正确的查询计划比例 |
| 跨轴漏覆盖 | 问题需要但未选择的轴 |
| 找全边际贡献 | 新轴或类别额外找到、且主题检索未覆盖的目标证据 |
| 成本 | 输入／输出 token、调用次数、时延和失败重试 |

### 8.11 通过、可容忍失败和阻断失败

**通过要求**：

- 轴的核心问题能够由人工稳定解释；
- 一级轴没有持续混合两个独立问题；
- 二级关系标签能够覆盖本轴适用范围，并可按原文形成稳定的多标签集合；
- 典型问题能够稳定映射到正确轴；
- 主 Agent 能输出带作用域的布尔表达式，并正确计算结果；
- 关系检索能覆盖主题检索遗漏的证据方面。

**可容忍失败**：

- 低频关系暂时没有二级入口；
- 部分关系需要二次审查；
- 不同轴或同轴合法多标签造成返回排序、去重或聚合方式变化；
- 单个领域内暂时存在尚未拆分的歧义。

**阻断失败**：

- 大量实例无法归入任何轴；
- 一个轴持续混淆两个不可同时回答的问题；
- 轴选择依赖领域关键词；
- 同轴标签并集无法覆盖本轴适用范围，或查询表达式的运算符／作用域错误导致漏召回；
- 只有整篇输入才能找到，但块级和分批方案无法恢复；
- 交易式提高召回必然以大面积错误分类为代价；
- 关系检索相较主题检索没有可验证的找全贡献。

高风险漏召回不能用总体平均准确率覆盖。

## 10 风险、待决问题与下一步

### 10.1 设计风险

- 15 个轴仍然可能混合不同问题；
- 某些轴在理论上成立，但当前语料没有独立检索价值；
- 多轴标签增加标注和模型调用成本；
- 同轴多标签无法形成覆盖，或大量标签完全重合却没有独立检索价值；
- 主 Agent 能识别轴名，但自然问题不能稳定映射；
- 关系抽取改善发现率，却没有改善完整证据覆盖；
- 知识对象域筛选尚未实现，同一关系类别仍可能包含大量领域歧义。

### 10.2 设计被推翻的条件

出现以下证据时，应重新设计轴：

- 盲审中持续出现现有轴无法合理吸收的新关系语义维度；
- 某个轴长期需要大量例外和优先级才能判断；
- 某个轴与另一个轴始终回答同一个问题；
- 轴内二级标签无法覆盖适用范围，且不能通过收窄全集或合并冗余标签解决；
- 用户自然问题无法映射到轴，只能依赖固定关键词；
- 关系检索无法带来独立于主题检索的证据覆盖。
